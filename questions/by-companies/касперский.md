## Go

### Наследование или композиция?

Go не поддерживает наследование. Используется **композиция** — через встраивание (embedding) структур и интерфейсов. Встраивание позволяет «пробрасывать» методы, но не создаёт иерархии типов.

```go
type Animal struct{ Name string }
func (a Animal) Speak() string { return a.Name }

type Dog struct{ Animal } // Dog «наследует» Speak через embedding
```

### Все примитивы синхронизации в Go

- `sync.Mutex` / `sync.RWMutex` — взаимное исключение
- `sync.WaitGroup` — ожидание завершения горутин
- `sync.Once` — однократное выполнение
- `sync.Cond` — условные переменные
- `sync.Map` — потокобезопасная карта
- `sync/atomic` — атомарные операции над числами и указателями
- **Каналы** (`chan`) — примитив CSP, тоже средство синхронизации

> Всё из списка `каналы, Mutex, WaitGroup, sync.Cond` — средства синхронизации.

---

### Порядок обхода map

**Произвольный (случайный) в момент выполнения.** Начиная с Go 1.0 рантайм намеренно рандомизирует стартовый бакет при каждом `range`. Это сделано, чтобы программисты не полагались на конкретный порядок. В момент компиляции порядок не определяется.

### Аргументы defer — когда вычисляются?

**В момент определения (объявления) defer**, а не в момент вызова отложенной функции. Функция вызывается позже, но её аргументы захватываются сразу.

```go
x := 1
defer fmt.Println(x) // напечатает 1, даже если x изменится
x = 2
```

Исключение: если используется замыкание `defer func() { fmt.Println(x) }()` — тогда `x` читается в момент вызова.

---

### Когда вызывается defer?

При **выходе из функции**, в которой он объявлен — нормальном (`return`) или аварийном (`panic`). Несколько defer вызываются в порядке **LIFO** (последний объявленный — первый вызванный).

### Слайс vs массив

||Массив|Слайс|
|---|---|---|
|Размер|Фиксированный, часть типа: `[3]int ≠ [4]int`|Динамический|
|Передача|Копируется целиком|Передаётся заголовок (ptr + len + cap)|
|Тип|Значимый тип|Ссылочный тип (указывает на backing array)|
|Нулевое значение|`[0, 0, 0]`|`nil` (len=0, cap=0, ptr=nil)|

---

### Запись в закрытый канал

**Паника** (`panic: send on closed channel`). Читать из закрытого канала можно — вернётся нулевое значение типа и `ok=false`.

---

### Горутина в main + паника

```go
func main() {
    go func() { panic("boom") }()
    time.Sleep(time.Second)
}
```

**Паника в любой горутине роняет всю программу.** recover работает только внутри той же горутины, где произошла паника. Паника в main — тоже роняет программу; отличие только в стек-трейсе.

## Linux

### Что содержит /proc

Виртуальная файловая система, отражающая состояние ядра в реальном времени:

- `/proc/<PID>/` — информация о процессе: `cmdline`, `fd/`, `maps`, `status`, `environ`
- `/proc/cpuinfo` — информация о CPU
- `/proc/meminfo` — состояние памяти
- `/proc/net/` — сетевая статистика
- `/proc/sys/` — настраиваемые параметры ядра (sysctl)
- `/proc/version`, `/proc/uptime`, `/proc/loadavg`

Файлы не занимают место на диске — генерируются ядром на лету.

---

### Технологии изоляции в Linux

- **Namespaces** — изоляция ресурсов: `pid`, `net`, `mnt`, `uts`, `ipc`, `user`, `cgroup`
- **cgroups (Control Groups)** — ограничение и учёт ресурсов: CPU, memory, I/O, pids
- **seccomp** — фильтрация системных вызовов
- **capabilities** — гранулярное управление привилегиями (вместо root/non-root)
- **AppArmor / SELinux** — мандатное управление доступом (MAC)
- **chroot / pivot_root** — изоляция файловой системы
- **OverlayFS** — слоёная ФС (основа образов Docker)

## Контейнеризация и оркестрация

### Системы контейнеризации

- **Docker** — де-факто стандарт, использует containerd под капотом
- **containerd** — low-level container runtime (CRI-совместимый)
- **CRI-O** — легковесный runtime для Kubernetes
- **Podman** — daemonless, rootless-контейнеры, совместим с Docker CLI
- **LXC / LXD** — системные контейнеры (ближе к VM)
- **runc** — эталонная реализация OCI runtime spec
- **Kata Containers** — контейнеры в легковесных VM (изоляция уровня гипервизора)

### Системы оркестрации

- **Kubernetes (k8s)** — стандарт индустрии
- **Docker Swarm** — встроенный в Docker, проще k8s
- **Nomad (HashiCorp)** — оркестрация контейнеров и не-контейнерных воркло́дов
- **Apache Mesos / Marathon** — enterprise-масштаб, менее популярен сейчас
- **OpenShift** — enterprise k8s от Red Hat
- **k3s / k0s** — лёгкие дистрибутивы Kubernetes
