## Stack
- Быстрое выделение (сдвиг указателя)
- LIFO - последний вошёл, первый вышел
- Размер известен в compile time
- i32, bool, массивы фиксированного размера
```rust
let x = 5;                  // 4 байта на стеке
let flag = true;            // 1 байт на стеке
let arr = [1, 2, 3, 4, 5];  // 20 байт на стеке (5 * i32)
let point = (10.0, 20.0);   // кортеж на стеке
```

## Heap
- Медленнее (поиск свободного места, аллокация)
- Размер может быть неизвестен заранее
-  Heap нужен для динамических данных
- Доступ через указатель
- String, Vec, Box<T>

```rust
let s = String::from("hello");  // на стеке: ptr + len + capacity (24 байта)
                                 // в heap: сами байты "hello"

let v = vec![1, 2, 3];          // на стеке: ptr + len + capacity
                                 // в heap: данные [1, 2, 3]

let b = Box::new(100);          // на стеке: указатель (8 байт)
                                 // в heap: число 100
```

## Аллокация
Сам процесс запроса памяти у системы. Это системный вызов, поэтому дорого. Rust показывает где это происходит - если видишь String, Vec, Box, Rc, Arc - значит аллокация.
```rust
// Аллокация происходит
let s = String::from("hello");        // аллокация
let v = Vec::new(); v.push(1);        // аллокация при push
let b = Box::new(42);                 // аллокация

// Аллокации НЕТ - просто ссылки на существующие данные
let slice: &str = "hello";            // строковый литерал в бинарнике
let view: &[i32] = &arr[1..3];        // срез - указатель + длина
fn process(data: &str) {}             // принимает ссылку, не владеет
```

## Почему важно
- Stack: ~1 такт CPU
- Heap: ~100+ тактов + возможная фрагментация
- В hot path избегай аллокаций - переиспользуй буферы, используй `with_capacity`
- Rust даёт контроль: видишь тип - понимаешь где память
