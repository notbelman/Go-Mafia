### Главный вопрос: когда компилятор узнаёт конкретный тип?

**impl Trait** - компилятор знает тип при компиляции. Под капотом он подставляет конкретный тип и генерирует оптимизированный код. Это называется **статическая диспетчеризация**.

**dyn Trait** - компилятор НЕ знает тип при компиляции. Тип определяется в рантайме через специальную таблицу указателей (vtable). Это называется **динамическая диспетчеризация**.

### Практическое следствие

С `impl Trait` функция может вернуть только **один конкретный тип**. Даже если два типа реализуют один трейт - нельзя вернуть то один, то другой в зависимости от условия.

С `dyn Trait` можно вернуть **разные типы** в рантайме, хранить их в одной коллекции, передавать куда угодно - главное, чтобы они реализовывали нужный трейт.

### Trade-off

| | impl Trait | dyn Trait |
|-|------------|-----------|
| Знание типа | Compile-time | Runtime |
| Скорость | Быстрее (инлайн) | Медленнее (vtable lookup) |
| Гибкость | Один тип | Разные типы |
| Размер бинарника | Больше | Меньше |

### Когда что

- **impl** - дефолт, когда заранее известно что именно возвращаешь/принимаешь
- **dyn** - когда нужна гибкость: разные типы в коллекции, условный возврат разных типов, плагины
