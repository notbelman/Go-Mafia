# Вывод типов и ограничения - почему closure нельзя вернуть без `impl` или `Box`

Каждая closure имеет уникальный анонимный тип, который невозможно написать явно. Это создаёт ограничения при возврате closure из функций и хранении в структурах.

## Зачем

Понимание этих ограничений нужно чтобы:
- Правильно писать сигнатуры функций возвращающих closure
- Выбирать между `impl Trait`, generics и trait objects
- Понимать ошибки компилятора связанные с типами closure

## Под капотом

**Проблема: анонимный тип**
```rust
let x = 5;
let closure = |y| x + y;

// Какой тип у closure?
// Что-то вроде: __anonymous_closure_main_line2<'a>
// Этот тип существует, но его имя недоступно программисту
```

**Нельзя написать явно:**
```rust
// ОШИБКА: нет синтаксиса для типа closure
fn make_adder(x: i32) -> ??? {
    |y| x + y
}

// Не работает:
fn make_adder(x: i32) -> Fn(i32) -> i32  // Fn это трейт, не тип
fn make_adder(x: i32) -> |i32| -> i32    // такого синтаксиса нет
```

**Три способа решения:**

### 1. `impl Trait` (возврат конкретного анонимного типа)
```rust
fn make_adder(x: i32) -> impl Fn(i32) -> i32 {
    move |y| x + y
}

// Компилятор знает точный тип, просто скрывает его за impl Fn
// Вызывающий код не знает конкретный тип, но компилятор - знает
// Мономорфизация, инлайнинг, zero-cost
```

Как это работает внутри:
```rust
// Компилятор видит:
fn make_adder(x: i32) -> impl Fn(i32) -> i32 {
    move |y| x + y
}

// И генерирует (концептуально):
struct __make_adder_closure {
    x: i32,
}
impl Fn<(i32,)> for __make_adder_closure {
    fn call(&self, (y,): (i32,)) -> i32 {
        self.x + y
    }
}
fn make_adder(x: i32) -> __make_adder_closure {
    __make_adder_closure { x }
}
```

### 2. `Box<dyn Trait>` (trait object, динамическая диспетчеризация)
```rust
fn make_adder(x: i32) -> Box<dyn Fn(i32) -> i32> {
    Box::new(move |y| x + y)
}

// Аллокация в куче
// vtable для вызова
// Размер Box известен (указатель + указатель на vtable)
```

### 3. Generics (тип определяется вызывающим кодом)
```rust
// Не для возврата, но для приёма closure:
fn apply<F, R>(f: F) -> R
where
    F: FnOnce() -> R,
{
    f()
}

// Вызывающий код "передаёт" тип через generic
```

## Ключевые детали

**`impl Trait` ограничения:**
```rust
// ОШИБКА: нельзя вернуть разные типы
fn make_closure(flag: bool) -> impl Fn() {
    if flag {
        || println!("A")
    } else {
        || println!("B")  // другой анонимный тип!
    }
}

// Каждая closure - уникальный тип
// impl Trait требует ОДИН конкретный тип
```

Решение через Box:
```rust
fn make_closure(flag: bool) -> Box<dyn Fn()> {
    if flag {
        Box::new(|| println!("A"))
    } else {
        Box::new(|| println!("B"))
    }
}
// Box<dyn Fn()> может хранить любой тип реализующий Fn()
```

**Вывод типов аргументов closure:**
```rust
// Типы аргументов выводятся из использования
let closure = |x| x + 1;  // x: ??? пока не известно

let _: i32 = closure(5);  // теперь x: i32

// closure(5.0);  // ОШИБКА: уже выведен i32
```
```rust
// Без использования - ошибка
let closure = |x| x + 1;
// ОШИБКА: не могу вывести тип x
// Нужно либо использовать, либо аннотировать:
let closure = |x: i32| x + 1;
```

**Типы выводятся один раз:**
```rust
let identity = |x| x;

let s = identity(String::from("hello"));  // x: String
// let n = identity(42);  // ОШИБКА: уже выведен String
```

Для полиморфной функции нужна обычная функция или generic:
```rust
fn identity<T>(x: T) -> T { x }

let s = identity(String::from("hello"));  // T = String
let n = identity(42);  // T = i32, другая мономорфизация
```

**`impl Trait` в позиции аргумента vs возврата:**
```rust
// Аргумент: вызывающий выбирает конкретный тип
fn take_closure(f: impl Fn(i32) -> i32) {
    // f имеет конкретный тип, выбранный вызывающим
}

// Возврат: функция выбирает конкретный тип
fn return_closure() -> impl Fn(i32) -> i32 {
    // функция решает какой тип вернуть
    |x| x + 1
}
```

**RPIT (Return Position Impl Trait) и лайфтаймы:**
```rust
// impl Trait захватывает все generic лайфтаймы по умолчанию
fn make_closure<'a>(s: &'a str) -> impl Fn() + 'a {
    move || println!("{}", s)
}

// Без + 'a компилятор выведет 'static, и будет ошибка
```

## Ограничения / Когда не использовать

**`impl Trait`:**
- Нельзя для разных типов в разных ветках
- Нельзя в trait методах (до недавнего времени, сейчас можно через RPITIT)
- Скрывает тип от вызывающего кода - иногда это минус

**`Box<dyn Fn>`:**
- Аллокация в куче
- Динамическая диспетчеризация (vtable call)
- Нельзя использовать если closure не object-safe (generic методы)

**Function pointers (`fn`):**
- Только для closure без захвата
- Меньше гибкости
```rust
// fn pointer работает только без захвата
let fp: fn(i32) -> i32 = |x| x + 1;  // OK

let y = 5;
let fp: fn(i32) -> i32 = |x| x + y;  // ОШИБКА: захватывает y
```

## Примеры

**Выбор между impl и Box:**
```rust
// impl Trait - когда один конкретный тип, performance critical
fn make_multiplier(n: i32) -> impl Fn(i32) -> i32 {
    move |x| x * n
}

// Box<dyn> - когда нужна гибкость или хранение в коллекции
fn make_operation(op: &str) -> Box<dyn Fn(i32, i32) -> i32> {
    match op {
        "add" => Box::new(|a, b| a + b),
        "mul" => Box::new(|a, b| a * b),
        _ => Box::new(|a, b| a - b),
    }
}

// Коллекция разных closure
let operations: Vec<Box<dyn Fn(i32) -> i32>> = vec![
    Box::new(|x| x + 1),
    Box::new(|x| x * 2),
    Box::new(|x| x - 3),
];
```

**Хранение closure в структуре:**
```rust
// С generic - размер структуры зависит от closure
struct CallbackGeneric<F: Fn()> {
    callback: F,
}

// С Box - фиксированный размер структуры
struct CallbackBoxed {
    callback: Box<dyn Fn()>,
}

// С impl в поле - НЕЛЬЗЯ
// struct CallbackImpl {
//     callback: impl Fn(),  // ОШИБКА: impl Trait не в этой позиции
// }
```

**Практика - обработчики событий:**
```rust
type EventHandler = Box<dyn FnMut(Event) + Send>;

struct EventLoop {
    handlers: Vec<EventHandler>,
}

impl EventLoop {
    fn on_event(&mut self, handler: impl FnMut(Event) + Send + 'static) {
        self.handlers.push(Box::new(handler));
    }
}
```
