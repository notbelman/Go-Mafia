- Kubernetes = **ОС для кластера**. Абстрагирует инфраструктуру, предоставляет единую площадку для деплоя приложений
- **Декларативная модель:** ты описываешь ЖЕЛАЕМОЕ состояние (YAML), Kubernetes приводит систему к этому состоянию и поддерживает его
- Автоматизирует: service discovery, scaling, load balancing, self-healing, leader election, rolling updates
- Произошёл из **Borg/Omega** (внутренние системы Google, 2 млрд контейнеров в неделю). Open source с 2014
- Managed K8s (GKE, EKS, AKS) — **использовать** K8s в 10 раз проще чем **управлять** им

---

## Что такое Kubernetes

Kubernetes — система автоматизации деплоя и управления контейнеризированными приложениями

> **Аналогия:**
> ОС для компьютера — управляет процессами на одной машине
> Kubernetes для кластера — управляет контейнерами на множестве машин
>
> Ты (капитан) — решаешь **КУДА** плыть
> K8s (рулевой) — ведёт корабль по курсу, докладывает обстановку

## Декларативная модель

#### Императивно (без K8s)
"Запусти 3 инстанса на сервере A, 2 на сервере B, настрой балансировщик..." — ты управляешь **КАК**

#### Декларативно (K8s)
"Хочу 5 инстансов моего приложения, порт 8080, 256MB RAM" — ты описываешь **ЧТО**, K8s решает **КАК**

Изменил описание → K8s приводит систему к новому состоянию:
- Добавил реплику → K8s запустит ещё один pod
- Убрал компонент → K8s остановит его
- Приложение упало → K8s перезапустит

## Что K8s даёт "из коробки"

| Фича | Что делает |
|---|---|
| **Service discovery** | Приложения находят друг друга по имени |
| **Horizontal scaling** | Автоматическое масштабирование по нагрузке |
| **Load balancing** | Распределение трафика между репликами |
| **Self-healing** | Перезапуск упавших, перенос с упавших нод |
| **Leader election** | Встроенный механизм выбора лидера |
| **Rolling updates** | Обновление без downtime |

## Зачем Kubernetes

|  | Монолит | Микросервисы |
|---|---|---|
| Приложения | 1 | 100+ |
| Деплои | 1 | 100+ |
| Ручное управление | ок | невозможно |

Kubernetes автоматизирует управление микросервисами:
- Какой сервис на какой ноде (Scheduler)
- Перезапуск при падении (self-healing)
- Обнаружение сервисов (Service discovery)
- Конфигурация (ConfigMaps, Secrets)
- Масштабирование (HPA, ReplicaSets)

## Стандартизация облака

#### Без K8s
AWS API ≠ GCP API ≠ Azure API → vendor lock-in, миграция = переписать деплой

#### С K8s
`kubectl apply -f app.yaml` — работает одинаково на AWS, GCP, Azure, on-prem. K8s API = единый стандарт деплоя

## Когда НЕ нужен Kubernetes

- ❌ Монолитное приложение (один процесс, один сервер)
- ❌ Менее 5 микросервисов (overhead > польза)
- ❌ Нет ресурсов на обучение команды
- ❌ Нет готовности к начальным затратам (K8s потребляет ресурсы сам по себе)

- ✅ Нужен когда: 20+ микросервисов, авто-масштабирование, multi-cloud, zero-downtime deploys, self-healing

## Варианты развёртывания

#### Managed (рекомендуется)
- GKE (Google), EKS (Amazon), AKS (Azure)
- Провайдер управляет control plane — ты только деплоишь приложения

#### Self-managed
- kubeadm, Rancher, OpenShift
- Ты управляешь всем сам — сложно, нужна экспертиза

#### Hybrid
- On-prem + cloud spillover при пиках нагрузки
