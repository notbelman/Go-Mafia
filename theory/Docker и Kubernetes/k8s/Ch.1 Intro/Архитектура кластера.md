- Кластер = **Control Plane** (мозг) + **Worker Nodes** (рабочие лошадки). Control plane управляет, workers выполняют
- Control Plane: **API Server** (единая точка входа), **etcd** (хранилище состояния), **Scheduler** (куда разместить), **Controllers** (поддерживают desired state)
- Worker Node: **Kubelet** (агент, управляет подами на ноде), **Container Runtime** (Docker/containerd), **kube-proxy** (сетевой балансировщик)
- Все компоненты общаются **только через API Server**. Никто не ходит напрямую в etcd или между собой
- Production: минимум 3 master ноды (HA). Worker нод — сколько нужно под нагрузку

### Компоненты подробнее

#### API Server
- Единственная точка входа в кластер
- RESTful API (kubectl, controllers, kubelet — все через него)
- Stateless — ничего не хранит сам, всё в etcd
- Валидирует объекты, уведомляет подписчиков об изменениях

#### etcd
- Distributed key-value store (Raft consensus)
- Хранит ВСЁ состояние кластера (объекты, конфиги, секреты)
- Только API Server общается с etcd напрямую
- Потеря etcd = потеря кластера → бэкапы критичны

#### Scheduler
- Watch: новые pod'ы без назначенной ноды
- Выбирает лучшую ноду (по ресурсам, affinity, taints)
- Записывает решение через API Server (поле nodeName)
- НЕ запускает pod — только назначает ноду

#### Controllers
- Reconciliation loop: desired state → current state
- Каждый контроллер отвечает за свой тип объекта
- Примеры: ReplicaSet controller, Deployment controller, Node controller, Job controller
- Создают другие объекты через API Server

### Компоненты подробнее

#### Kubelet
- Агент на каждой worker ноде
- Watch: pod'ы назначенные на его ноду
- Инструктирует Container Runtime запустить/остановить контейнеры
- Следит за здоровьем pod'ов (probes), репортит статус в API Server
- НЕ управляет контейнерами запущенными вне K8s

#### Container Runtime
- containerd (default с K8s 1.24+), CRI-O, Docker
- Запускает контейнеры по инструкции Kubelet
- Общается с Kubelet через CRI (Container Runtime Interface)

#### kube-proxy
- Сетевой компонент на каждой ноде
- Реализует Service abstraction (ClusterIP, NodePort...)
- Настраивает iptables/IPVS правила для load balancing
- НЕ проксирует трафик сам (настраивает правила в ядре)

## Как K8s запускает приложение

`kubectl apply -f app.yaml`

1. **kubectl → API Server** — манифест разбивается на объекты, каждый сохраняется в etcd
2. **Controller** замечает новый Deployment → создаёт ReplicaSet → ReplicaSet создаёт Pod объекты
3. **Scheduler** замечает Pod'ы без ноды → выбирает лучшую ноду → записывает nodeName в Pod
4. **Kubelet** на ноде замечает назначенный Pod → инструктирует Container Runtime запустить контейнер
5. **kube-proxy** замечает готовый Pod → настраивает сетевые правила для Service (load balancer)
6. **Kubelet + Controllers** постоянно мониторят → pod упал — перезапуск, нода упала — pod перемещён на здоровую ноду

## Сколько нод нужно

#### Control Plane (master)
- **Dev/test:** 1 нода (single point of failure — ок для dev)
- **Production:** 3+ ноды (etcd требует Raft quorum: 2N+1)

#### Worker Nodes
- Зависит от нагрузки
- Можно добавлять/убирать без downtime
- В облаке: cluster autoscaler добавляет ноды автоматически
