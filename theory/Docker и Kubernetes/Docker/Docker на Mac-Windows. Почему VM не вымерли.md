## Контейнер использует ядро хоста

Контейнер — не VM, у него нет своего ядра. Он использует Linux-ядро хост-машины через namespaces и cgroups.
```
Linux-хост:
  Приложение → контейнер → Linux kernel хоста (напрямую)

Mac/Windows:
  Приложение → контейнер → Linux kernel → LinuxKit VM → хост ОС
```

На Mac и Windows нет Linux-ядра, поэтому Docker Desktop запускает легковесную Linux VM (LinuxKit) и контейнеры работают внутри неё.

## Windows-контейнеры

Существуют, но только на Windows-хосте. Linux-контейнер на Windows — через VM. Windows-контейнер на Linux — невозможно.

## Почему VM не вымерли

| Нужно                               | Контейнер | VM  |
| :---------------------------------- | :-------- | :-- |
| Разные ОС на одном хосте           | ❌        | ✅  |
| Полная изоляция ядра (безопасность) | ❌        | ✅  |
| Мультитенантность (чужой код)       | Рискованно| ✅  |
| Legacy-приложения (Windows Server)  | ❌        | ✅  |
| Микросервисы, CI/CD, dev-окружение  | ✅        | Избыточно |

Контейнеры разделяют ядро → если эксплойт в ядре, все контейнеры уязвимы. VM — полная изоляция на уровне гипервизора.
