
| Стратегия          | Как работает                                                     | Плюсы                                               | Минусы                                                              | Когда использовать                                      |
| ------------------ | ---------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------- |
| Hash               | hash(key) % N шардов                                             | Равномерное распределение                           | Resharding при добавлении шарда - перемещается большая часть данных | Нет естественного диапазона, нужна равномерность        |
| Range              | key в диапазоне [A, B) - конкретный шард                         | Запросы по диапазону идут на один/несколько шардов  | Hotspots (все пишут в последний диапазон)                           | Time-series, данные с естественным порядком             |
| Directory          | Lookup-таблица key - shard_id                                    | Полный контроль, можно двигать отдельные ключи      | Lookup на каждый запрос, справочник = SPOF                          | VIP-клиенты на отдельных шардах, неравномерные данные   |
| Consistent Hashing | Ключи и шарды на кольце, ключ идёт к ближайшему шарду по часовой | При добавлении шарда перемещается только 1/N данных | Сложнее реализовать, возможна неравномерность без virtual nodes     | Динамическое количество шардов, кэши (Memcached, Redis) |
