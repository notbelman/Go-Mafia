- **Hash** — хеш-таблица `hash(value) → TID`. Только `=`, **никаких** range/сортировки/UNIQUE
- Экономия **~20%** vs B-tree на длинных строках (URL, токены)
- В **99% случаев B-tree лучше** (универсальнее, тоже быстр на `=`). Hash — почти никогда

---

**Использовать:**
- Длинные строковые ключи (URL, токены) — экономия места
- Только точные совпадения, никогда range/сортировка

**Не использовать:**
- Нужны `>`, `<`, `BETWEEN`, `ORDER BY`, `LIKE`
- Нужен UNIQUE constraint (Hash не поддерживает)
- В 99% случаев B-tree лучше

```sql
CREATE INDEX idx_url ON pages USING HASH(url);
```
