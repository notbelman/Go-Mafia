- **pg_stat_user_indexes** — сколько раз индекс сканировался (`idx_scan`). `idx_scan = 0` за месяц → индекс **не нужен**, удаляй
- **pg_stat_user_tables** — HOT update ratio, dead tuples, последний VACUUM/ANALYZE
- Лишние индексы = замедление записи + место на диске + работа для VACUUM. **Регулярно чисти**

---

## Неиспользуемые индексы

```sql
SELECT
  schemaname, relname AS table,
  indexrelname AS index,
  idx_scan,                          -- сколько раз сканировался
  pg_size_pretty(pg_relation_size(indexrelid)) AS size
FROM pg_stat_user_indexes
WHERE idx_scan = 0
ORDER BY pg_relation_size(indexrelid) DESC;
```

`idx_scan = 0` + индекс создан давно → безопасно удалять. Но проверь: может это UNIQUE constraint или индекс для FK.

## Эффективность индексов

```sql
SELECT
  relname AS table,
  indexrelname AS index,
  idx_scan,                          -- сколько раз использован
  idx_tup_read,                      -- строк прочитано из индекса
  idx_tup_fetch                      -- строк получено из heap
FROM pg_stat_user_indexes
WHERE relname = 'orders'
ORDER BY idx_scan DESC;
```

`idx_tup_read >> idx_tup_fetch` → индекс читает много, но мало подходящих строк → низкая селективность.

## HOT update ratio

```sql
SELECT
  relname,
  n_tup_upd,
  n_tup_hot_upd,
  ROUND(100.0 * n_tup_hot_upd / NULLIF(n_tup_upd, 0), 1) AS hot_pct,
  n_dead_tup,
  last_vacuum,
  last_analyze
FROM pg_stat_user_tables
WHERE relname = 'users';
```

`hot_pct < 50%` → пересмотри fillfactor или лишние индексы на UPDATE-heavy колонках.

## Размеры индексов vs таблица

```sql
SELECT
  t.relname AS table,
  pg_size_pretty(pg_relation_size(t.oid)) AS table_size,
  i.indexrelname AS index,
  pg_size_pretty(pg_relation_size(i.indexrelid)) AS index_size,
  ROUND(100.0 * pg_relation_size(i.indexrelid) / NULLIF(pg_relation_size(t.oid), 0)) AS pct
FROM pg_stat_user_tables t
JOIN pg_stat_user_indexes i ON t.relname = i.relname
ORDER BY pg_relation_size(i.indexrelid) DESC;
```

Индекс > 50% от таблицы → возможно bloat → `REINDEX CONCURRENTLY`.

## Невалидные индексы

```sql
SELECT indexrelid::regclass, indisvalid
FROM pg_index WHERE NOT indisvalid;
```

INVALID индексы — результат упавшего `CREATE INDEX CONCURRENTLY`. Не используются, но занимают место. Удалить и пересоздать.

## Дублирующиеся индексы

```sql
SELECT
  array_agg(indexrelid::regclass) AS indexes,
  indrelid::regclass AS table,
  indkey
FROM pg_index
GROUP BY indrelid, indkey
HAVING COUNT(*) > 1;
```

Два индекса с одинаковыми колонками → один лишний.
