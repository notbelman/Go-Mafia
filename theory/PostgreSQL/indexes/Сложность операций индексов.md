
| Индекс     | Point lookup    | Range scan     | Insert       | Delete       | Место           |
| :--------- | :-------------- | :------------- | :----------- | :----------- | :-------------- |
| **B-tree** | O(log_f n)      | O(log_f n + k) | O(log_f n)   | O(log_f n)   | O(n)            |
| **Hash**   | **O(1)** avg    | ❌ не поддерж.  | **O(1)** avg | **O(1)** avg | O(n)            |
| **GIN**    | O(log n + k)    | ❌ не поддерж.  | O(m · log n) | O(m · log n) | O(n · m)        |
| **GiST**   | O(log n) ~ O(n) | O(log n + k)   | O(log n)     | O(log n)     | O(n)            |
| **BRIN**   | O(r) + heap     | O(r) + heap    | **O(1)**     | **O(1)**     | **O(r) ≈ 0.1%** |
**f** = fanout (100-300 для B-tree),
**k** = количество результатов, 
**m** = ключей на строку (GIN: массив из m элементов), 
**r** = количество block ranges в BRIN
## Пояснения

**B-tree**: `log_f n` при f=200 и n=100M → **~4 чтения страниц**. На практике верхние уровни в кэше → 1-2 disk I/O. Range scan идёт по linked list листьев.

**Hash**: O(1) — амортизированная. Worst case O(n) при коллизиях / rehash. Но на практике почти всегда O(1).

**GIN**: insert **дорогой** — одна строка с массивом из m элементов = m вставок в B-tree ключей. `fastupdate` буферизует → амортизирует до O(1) per row, но периодический flush = spike. Поиск: O(log n) найти ключ в B-tree + O(k) пройти posting list.

**GiST**: поиск деградирует от O(log n) до O(n) при сильном перекрытии bounding box'ов (геоданные с высокой плотностью). На практике обычно O(log n).

**BRIN**: поиск = пройти r block ranges (O(r) — линейно, но r **очень мало**: таблица 10GB / 1MB per range = 10K ranges). Потом bitmap heap scan подходящих блоков. Insert = просто обновить min/max одного range → O(1).

## Worst case

|Индекс|Worst case lookup|Когда|
|:--|:--|:--|
|B-tree|O(log_f n)|Всегда (сбалансировано)|
|Hash|**O(n)**|Все ключи в одном bucket (коллизии)|
|GIN|O(log n + n)|Один ключ → posting list = вся таблица|
|GiST|**O(n)**|Все bounding box'ы перекрываются|
|BRIN|**O(n)**|Данные не отсортированы → все ranges подходят|
