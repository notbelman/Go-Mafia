- Миграция без даунтайма = **никогда не блокировать** таблицу надолго. `ALTER TABLE ADD COLUMN` (без DEFAULT) — **мгновенно** в PG 11+. `CREATE INDEX CONCURRENTLY` — без блокировки записи
- **Опасные** операции: `ALTER TABLE ADD COLUMN ... DEFAULT ... NOT NULL` (PG < 11), `DROP COLUMN` если код ещё читает, `ALTER TYPE`, `CREATE INDEX` (без CONCURRENTLY) — берут **ACCESS EXCLUSIVE** lock
- Стратегия: **expand → migrate → contract**. Сначала расширяй схему (безопасно), потом мигрируй данные, потом убирай старое
- **Backfill** больших таблиц — батчами: `UPDATE ... WHERE id BETWEEN X AND Y`, не `UPDATE ... SET col = val` на 100M строк (одна транзакция → lock → OOM)

---

## Безопасные операции (мгновенные)

| Операция | Почему безопасно |
|:--|:--|
| `ADD COLUMN` (nullable, без DEFAULT) | Метаданные, не трогает строки |
| `ADD COLUMN ... DEFAULT val` (PG 11+) | PG хранит DEFAULT в каталоге, не перезаписывает строки |
| `DROP COLUMN` | Помечает невидимой (физически не удаляет) |
| `RENAME COLUMN` | Метаданные |
| `ADD CONSTRAINT ... NOT VALID` | Не проверяет существующие строки |
| `CREATE INDEX CONCURRENTLY` | Два прохода, без блокировки записи |

## Опасные операции (блокируют)

| Операция | Что происходит | Решение |
|:--|:--|:--|
| `ADD COLUMN DEFAULT NOT NULL` (PG < 11) | Перезаписывает **все** строки | Добавить nullable → backfill → SET NOT NULL |
| `ALTER COLUMN TYPE` | Перезаписывает все строки | Новая колонка → backfill → переключить |
| `CREATE INDEX` (без CONCURRENTLY) | ACCESS SHARE lock на всё время | Всегда `CONCURRENTLY` |
| `VALIDATE CONSTRAINT` | Сканирует всю таблицу | `NOT VALID` → deploy → `VALIDATE` отдельно |
| `SET NOT NULL` | Сканирует всю таблицу (PG < 12) | CHECK constraint вместо NOT NULL (PG < 12) |

## Стратегия: Expand → Migrate → Contract

### Пример: переименовать колонку

```
-- ❌ ПЛОХО: ALTER TABLE RENAME COLUMN old_name TO new_name
-- Код читающий old_name сломается мгновенно

-- ✅ ХОРОШО (3 деплоя):

-- Deploy 1 (expand): добавить новую колонку
ALTER TABLE users ADD COLUMN new_name TEXT;
-- + триггер для синхронизации
CREATE TRIGGER sync_names BEFORE INSERT OR UPDATE ON users
FOR EACH ROW EXECUTE FUNCTION sync_old_to_new();

-- Deploy 2 (migrate): backfill + переключить код на new_name
UPDATE users SET new_name = old_name WHERE new_name IS NULL;  -- батчами!
-- Код начинает писать/читать new_name

-- Deploy 3 (contract): убрать старое
DROP TRIGGER sync_names ON users;
ALTER TABLE users DROP COLUMN old_name;
```

### Пример: добавить NOT NULL колонку

```sql
-- Deploy 1: добавить nullable
ALTER TABLE orders ADD COLUMN priority INT;

-- Deploy 2: backfill батчами
DO $$
DECLARE
  batch_size INT := 10000;
  max_id BIGINT;
BEGIN
  SELECT MAX(id) INTO max_id FROM orders;
  FOR i IN 0..max_id/batch_size LOOP
    UPDATE orders
    SET priority = 0
    WHERE id BETWEEN i * batch_size AND (i + 1) * batch_size - 1
      AND priority IS NULL;
    COMMIT;  -- не держим одну огромную транзакцию
  END LOOP;
END $$;

-- Deploy 3: добавить constraint
ALTER TABLE orders ADD CONSTRAINT orders_priority_not_null
  CHECK (priority IS NOT NULL) NOT VALID;  -- не проверяет существующие
-- ... следующий деплой:
ALTER TABLE orders VALIDATE CONSTRAINT orders_priority_not_null;  -- проверяет, но не блокирует запись
```

## Backfill батчами

```sql
-- ❌ ПЛОХО: одна транзакция на 100M строк
UPDATE huge_table SET new_col = compute(old_col);
-- → одна транзакция, огромный WAL, блокировки, OOM

-- ✅ ХОРОШО: батчами по 10K
UPDATE huge_table SET new_col = compute(old_col)
WHERE id BETWEEN 0 AND 9999 AND new_col IS NULL;

UPDATE huge_table SET new_col = compute(old_col)
WHERE id BETWEEN 10000 AND 19999 AND new_col IS NULL;
-- ...
```

В Go:
```go
batchSize := 10000
for offset := 0; ; offset += batchSize {
    res, err := db.Exec(`
        UPDATE huge_table SET new_col = compute(old_col)
        WHERE id >= $1 AND id < $2 AND new_col IS NULL
    `, offset, offset+batchSize)
    if res.RowsAffected() == 0 { break }
    time.Sleep(100 * time.Millisecond)  // дать дышать репликам
}
```

## Lock timeout

Миграции должны **быстро сдаваться** если не могут получить лок:

```sql
SET lock_timeout = '5s';  -- не ждать лок дольше 5 секунд
ALTER TABLE users ADD COLUMN ...;
-- если за 5s не получил лок → ERROR → retry позже, не блокируй прод
```
