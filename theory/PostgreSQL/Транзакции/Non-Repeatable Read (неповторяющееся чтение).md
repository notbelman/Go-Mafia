- **Non-Repeatable Read** — два одинаковых SELECT в одной транзакции возвращают **разные значения**. Между ними другая транзакция закоммитила UPDATE
- Защита: **REPEATABLE READ+**. На этом уровне PG фиксирует snapshot на **первом запросе** — последующие SELECT видят тот же срез
- Отличие от Dirty Read: тут читаем **закоммиченные** данные (легальные), но они **изменились** между двумя SELECT'ами
- Отличие от Phantom Read: тут **значения** меняются (UPDATE), там **количество строк** (INSERT/DELETE)

---

| Суть                  | Два одинаковых SELECT в одной транзакции возвращают разные значения    |
| --------------------- | ---------------------------------------------------------------------- |
| Проблема              | Данные "меняются" прямо под ногами во время работы транзакции          |
| Отличие от Dirty Read | Там читаем НЕзакоммиченные, тут - закоммиченные, но изменившиеся       |
| Защита                | REPEATABLE READ+                                                       |
| PostgreSQL            | На REPEATABLE READ транзакция видит "снимок" на момент первого запроса |

## Пример
```
T1: BEGIN
T1: SELECT balance WHERE id=1 → 1000
                                    T2: BEGIN
                                    T2: UPDATE SET balance = 5000 WHERE id=1
                                    T2: COMMIT
T1: SELECT balance WHERE id=1 → 5000 (значение изменилось!)
T1: COMMIT
```

- [[Phantom Read (фантомное чтение)]] — там количество строк, тут значения
