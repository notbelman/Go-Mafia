## CDC (Change Data Capture)

Захват изменений из одной БД и автоматическая отправка в другие системы.

**Типичный сценарий:** данные пишутся в PostgreSQL → CDC слушает журнал изменений → отправляет в Kafka → оттуда в Elasticsearch (для поиска) и ClickHouse (для аналитики).

**Как работает:** коннекторы подключаются к replication log БД и перенаправляют изменения. В Kafka есть готовые коннекторы для разных БД.

**Нюанс:** коннекторы бывают медленные, ресурсоёмкие. Часто пишут свои для конкретной логики.

## libslave (приложение-реплика)

Приложение прикидывается репликой БД и слушает replication log. Данные хранятся в оперативке приложения — не нужно ходить в сеть за каждым запросом.

**Пример из Тинькофф:** рекламный движок на C++ должен отвечать за 100мс. Нужно матчить пользователей с рекламой по множеству параметров. Ходить в БД — слишком медленно. Решение: libslave подключается к MySQL, приложение хранит все нужные данные в RAM и отвечает мгновенно.

**Ограничение:** данные должны помещаться в оперативку. Если БД 256ГБ, а RAM 64ГБ — концепция не ложится.

**Инициализация:** при старте приложения делается начальная наливка (SELECT нужных данных), дальше обновления приходят через replication stream.

**Связь:**
- [[Поисковые движки (Search Engines)]] — CDC часто используется для синхронизации основной БД с Elasticsearch
- [[Колоночные базы данных|колоночные БД]] — CDC для потоковой загрузки данных в ClickHouse
