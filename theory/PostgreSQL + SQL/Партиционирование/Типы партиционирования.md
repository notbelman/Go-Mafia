
| Тип       | Как делит данные                                | Когда использовать                                                         | Когда НЕ использовать                                      | Pruning работает                                     | Нюансы                                                          |
| --------- | ----------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------- |
| Range     | По диапазону значений [FROM, TO)                | Time-series, логи, события с датой; нужен retention (DROP PARTITION)       | Данные распределены неравномерно - одна партиция разбухает | WHERE date >= '2024-01-01' AND date < '2024-02-01'   | Границы [FROM, TO) - нижняя включительно, верхняя исключительно |
| List      | По конкретным значениям из списка               | Фиксированные категории (регион, статус, тип); изоляция по юрисдикциям     | Категорий много (сотни) или часто добавляются новые        | WHERE region = 'EU' или WHERE region IN ('EU', 'US') | Нет DEFAULT + значение не попало никуда = ошибка INSERT         |
| Hash      | По остатку от деления hash(key) % N             | Нет естественного ключа; равномерное распределение; параллельная обработка | Запросы по диапазонам; нужен retention                     | Только WHERE key = value (точное равенство)          | Modulus нельзя изменить - пересоздавать партиции                |
| Composite | Многоуровневое: партиция разбита на субпартиции | Огромные таблицы; фильтры по двум измерениям (дата + user_id)              | Усложняет DDL; субпартиций слишком много                   | На каждом уровне последовательно                     | Pruning полный только если WHERE содержит ключи обоих уровней   |
