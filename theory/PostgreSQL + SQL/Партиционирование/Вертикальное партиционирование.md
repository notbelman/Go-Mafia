Разбиение таблицы по столбцам — выносим часть колонок в отдельную таблицу, связываем по ключу.

## Зачем

- разделить hot и cold данные (часто читаемые vs редко нужные)
- уменьшить ширину строки — больше строк влезает в страницу, быстрее seq scan
- изолировать тяжёлые поля (blob, jsonb, text) от лёгких

## Когда использовать

- есть явное разделение hot/cold по частоте доступа
- тяжёлые поля (blob, большой json) тянут вниз производительность
- TOAST не справляется или хочется явный контроль

## Когда не использовать

- большинство запросов всё равно нужны все столбцы — JOIN overhead
- таблица небольшая — усложнение без профита
- нет явного паттерна доступа hot/cold
## Пример

```sql
-- было
users (id, name, email, avatar_blob, settings_json, bio_text)

-- стало
users_main (id, name, email)              -- 100 байт на строку, читаем постоянно
users_heavy (id, avatar_blob, settings_json, bio_text)  -- 10 КБ на строку, читаем редко

-- запрос списка пользователей
SELECT id, name, email FROM users_main;  -- быстро, компактно

-- запрос профиля с аватаром
SELECT m.*, h.avatar_blob 
FROM users_main m 
JOIN users_heavy h ON m.id = h.id 
WHERE m.id = 123;
```
