- **Оконные функции** — вычисления по группе строк **без схлопывания** (в отличие от GROUP BY). Каждая строка остаётся в результате + получает агрегат по "окну"
- Синтаксис: `func() OVER (PARTITION BY ... ORDER BY ... ROWS/RANGE ...)`. PARTITION BY = "группировка без GROUP BY", ORDER BY = порядок внутри окна
- Топ-5 на собесе: **ROW_NUMBER** (уникальный номер), **RANK/DENSE_RANK** (ранг с пропусками / без), **LAG/LEAD** (предыдущая/следующая строка), **SUM/COUNT OVER** (нарастающий итог)
- **Порядок выполнения**: оконные функции срабатывают **после** WHERE, GROUP BY, HAVING — но **до** ORDER BY и LIMIT

---

## Базовый синтаксис

```sql
SELECT
  name, department, salary,
  ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn,
  SUM(salary) OVER (PARTITION BY department) AS dept_total,
  AVG(salary) OVER () AS company_avg  -- пустое OVER = всё как одно окно
FROM employees;
```

## ROW_NUMBER / RANK / DENSE_RANK

```sql
-- Данные: salary = [100, 100, 90, 80]

ROW_NUMBER():  1, 2, 3, 4     -- уникальный номер (100 и 100 получат разные)
RANK():        1, 1, 3, 4     -- одинаковые = одинаковый ранг, потом пропуск
DENSE_RANK():  1, 1, 2, 3     -- одинаковый ранг, БЕЗ пропуска
```

### TOP-N per group (классика собеса)

```sql
-- Топ-3 зарплаты в каждом отделе
SELECT * FROM (
  SELECT *,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn
  FROM employees
) sub
WHERE rn <= 3;
```

## LAG / LEAD

```sql
-- Предыдущая и следующая строка
SELECT
  date, revenue,
  LAG(revenue, 1) OVER (ORDER BY date) AS prev_day,       -- вчера
  LEAD(revenue, 1) OVER (ORDER BY date) AS next_day,      -- завтра
  revenue - LAG(revenue) OVER (ORDER BY date) AS diff      -- разница с вчера
FROM daily_stats;
```

`LAG(col, N, default)` — N строк назад, default если нет (дефолт NULL).

## Нарастающий итог (running total)

```sql
SELECT
  date, amount,
  SUM(amount) OVER (ORDER BY date) AS running_total,
  SUM(amount) OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS week_sum
FROM transactions;
```

## Frame (ROWS / RANGE)

```sql
-- Последние 3 строки включая текущую
SUM(x) OVER (ORDER BY date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)

-- От начала до текущей (дефолт при ORDER BY)
SUM(x) OVER (ORDER BY date RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)

-- Всё окно
SUM(x) OVER (ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)
```

**ROWS** — физические строки. **RANGE** — логический диапазон (одинаковые значения = одна группа).

## FIRST_VALUE / LAST_VALUE / NTH_VALUE

```sql
SELECT
  name, salary,
  FIRST_VALUE(name) OVER (ORDER BY salary DESC) AS top_earner,
  LAST_VALUE(name) OVER (
    ORDER BY salary DESC
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING  -- важно!
  ) AS lowest_earner
FROM employees;
```

`LAST_VALUE` без явного frame даёт **текущую строку** (дефолтный frame = до CURRENT ROW). Частая ловушка.

## NTILE

```sql
-- Разбить на 4 квартиля
SELECT salary,
  NTILE(4) OVER (ORDER BY salary) AS quartile
FROM employees;
```

## Порядок выполнения SQL

```
FROM → WHERE → GROUP BY → HAVING → SELECT (оконные функции тут!) → ORDER BY → LIMIT
```

Оконные функции **нельзя** использовать в WHERE/HAVING — они ещё не вычислены. Оборачивай в подзапрос.

## Производительность

- `PARTITION BY` + `ORDER BY` по индексу → PG может избежать сортировки
- Без индекса → Sort на каждое окно
- Несколько оконных функций с одинаковым OVER → PG **переиспользует** сортировку

```sql
-- Именованное окно (DRY)
SELECT
  ROW_NUMBER() OVER w,
  SUM(salary) OVER w
FROM employees
WINDOW w AS (PARTITION BY department ORDER BY salary DESC);
```
