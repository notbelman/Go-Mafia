- **Generational hypothesis:** большинство объектов умирают молодыми. Разбить heap на поколения: **young** (частые сборки, маленький объём) и **old** (редкие). Пережил GC → переходит в старшее поколение → сканируется реже
- **В Go нет поколений:** escape analysis кладёт короткоживущие объекты на **стек** ≈ «молодое поколение». Стек GC не трогает — объекты умирают при выходе из функции. В Java почти всё в heap (`new` → heap) → поколения критически важны
- **Go 1.26: [[Green Tea GC (new)]] ≠ generational.** Green Tea оптимизирует Mark фазу через page-based scanning и cache locality. Нет деления heap на поколения, нет write barrier для межпоколенческих ссылок. Go по-прежнему non-generational

---

## Идея

Разбить кучу на поколения по возрасту объектов. Большинство объектов удаляются молодыми (как в естественном отборе). Те, кто пережил сборку мусора, вероятно переживут и следующую. ^gen-idea

```
Поколение 0 (young):  частые сборки, маленький объём
Поколение 1 (old):    редкие сборки, большой объём
Поколение 2 (oldest): очень редко, только при нехватке памяти
```

## Как работает

```
Создали X1..X8 → все в поколении 0
GC поколения 0 → X1, X3, X4, X8 живые → переносим в поколение 1
Создали Y1..Y8 → в поколении 0
GC поколения 0 → Y3, Y8 живые → переносим в поколение 1
...
Когда памяти не хватает → GC поколения 1 (заглянуть к «старикам»)
```

Идея: если не критическое потребление памяти, проходим GC только по молодым. Если 10 раз прошли молодых и толком не очистили — заглядываем к старшим. ^gen-how-works

## Почему в Go нет поколений

Go через escape analysis старается класть максимум на стек. Короткоживущие объекты (обработка запроса → больше не нужны) с большой вероятностью окажутся на стеке, а не в хипе. ^go-no-gen

**Стек ≈ «молодое поколение»:** объекты создаются и умирают при выходе из функции, GC их не трогает. ^stack-as-young-gen

В Java почти всё в хипе (`new` → heap), поэтому поколения критически важны. В Go хип уже «отфильтрован» escape analysis. ^java-vs-go

> [!info] Green Tea GC (Go 1.26) — не generational
> Green Tea оптимизирует **Mark фазу** через page-based scanning и лучшую cache locality.
> Это **не** generational GC — нет деления heap на young/old поколения, нет write barrier для межпоколенческих ссылок.
> Go по-прежнему non-generational. Оптимизация идёт в другом направлении: эффективность обхода графа.
