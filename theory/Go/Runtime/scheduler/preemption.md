- Go — **гибридный**: кооперативная (компилятор вставляет точки) + асинхронно-вытесняющая (Go 1.14+, sysmon)
- кооперативные точки: пролог функции, channel ops, mutex, syscall, `runtime.Gosched()`
- вытеснение: sysmon видит G > 10ms → SIGURG → signal handler останавливает в safe point

---

|                | Кооперативный                            | Вытесняющий                   |
| :------------- | :--------------------------------------- | :---------------------------- |
| Кто отдаёт CPU | Задача сама                              | Планировщик принудительно     |
| Риск           | Одна задача может захватить CPU навсегда | Нет, гарантирует fairness     |
| Overhead       | Меньше (нет прерываний)                  | Больше (сигналы, safe points) |
| Пример         | Go < 1.14, Node.js event loop            | Linux kernel, Go ≥ 1.14       |

## Кооперативная часть

Компилятор вставляет точки переключения в код, горутина сама ставит эти точки, а не как в вытесняющем режиме, когда нужно найти горутину, послать сигнал,поймать, проверить safe point ^coop-compiler-inserts

```
Горутина отдаёт управление при:
- вызове функции (проверка стека в прологе)
- channel send/receive
- mutex Lock/Unlock
- syscall
- runtime.Gosched()
- выделение памяти (может вызвать GC)
``` 
^coop-yield-points

## Асинхронно-вытесняющая часть (Go 1.14+)

```
1. sysmon видит: G работает > 10ms
2. ставит g.preempt = true
3. шлёт SIGURG потоку
4. signal handler останавливает G в safe point
5. G возвращается в очередь P
```

^fa7cbc

Sysmon детектирует горутину, работающую дольше **10ms**, и вытесняет её через **SIGURG** в GRQ. ^async-preempt-mechanism

**Почему «асинхронно»:** вытеснение может произойти не сразу. Если с точки зрения GC горутина в unsafe point (несогласованные указатели) — вытеснение откладывается до выхода в safe point. ^async-preempt-delay

**Safe points** — места, где можно безопасно остановить горутину. Нельзя останавливать: в середине записи в память, при работе с runtime-структурами, в CGO вызове. Компилятор вставляет safe points в код. ^safe-points

## Зачем добавили вытеснение

```go
// До Go 1.14: tight loop без вызовов функций → горутина
// захватывала P навсегда, другие горутины голодали
go func() {
    for { x++ }  // нет вызовов → нет кооперативных точек
}()

// С Go 1.14: sysmon вытеснит через ~10ms
```

До Go 1.14 tight loop без вызовов функций мог захватить P навсегда — не было кооперативных точек для переключения. ^preempt-before-1-14

С Go 1.14 sysmon вытеснит такую горутину через ~10ms. ^preempt-after-1-14

## runtime.Gosched()

```go
for {
    doWork()
    runtime.Gosched()  // добровольно: «планировщик, переключись»
}
```

`runtime.Gosched()` — явная кооперативная точка: горутина добровольно отдаёт управление планировщику и возвращается в очередь. ^gosched
