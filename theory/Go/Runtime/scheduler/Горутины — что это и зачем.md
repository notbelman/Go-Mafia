- горутина = пользовательский контекст (стек + регистры CPU), переключаемый runtime Go в userspace, не ядром ОС
- контекст-свитчинг потоков ОС дорогой: два перехода (в ядро и обратно), вымывание кэшей
- переключение G1→G2: сохранить регистры CPU (SP, PC, BP...) в gobuf G1 → загрузить регистры из gobuf G2. SP (вершина стека) и BP (начало фрейма функции) теперь указывают на стек G2 — процессор "смотрит" на него. Стек не копируется
- программист не знает про потоки ОС — только горутины. Вся сложность абстрагирована runtime
- стек горутины: начальный **2KB** (vs 2-8MB у потока ОС), растёт динамически до 1GB

## Зачем легковесные потоки

**Контекст-свитчинг потоков ОС:** поток вытесняется → переход в ядро → шедулер ядра выбирает следующий поток → переход обратно. Два переключения контекста, кэши вымываются. ^g-os-thread-switch-cost

**Идея Go:** зачем переключаться через ядро? Runtime Go сам переключает горутины внутри потока ОС (M). Всё происходит в userspace (обычный код приложения, без syscall в ядро). ^g-userspace-idea

#### Переключение G1 → G2
1. Сохранить регистры CPU (SP, PC, BP...) в gobuf G1
2. Загрузить регистры из gobuf G2 в процессор

Всё. Два шага. SP/BP — часть регистров в gobuf, не отдельный шаг. После загрузки gobuf G2 процессор "смотрит" на стек G2 и продолжает с того места, где G2 остановилась.
P
#### Что такое SP и BP
Это регистры процессора.
- **SP (Stack Pointer)** — указывает на вершину стека (где мы сейчас)
- **BP (Base Pointer)** — указывает на начало текущего фрейма функции

#### Что такое gobuf:
поле `sched` в структуре `runtime.g`. Хранит сохранённые регистры горутины — её "закладку", где она остановилась.

## Что такое горутина

Структура в runtime Go (~несколько сотен байт) + стек. ^g-struct-size

Стек начинается с **2KB** (vs 2-8MB у потока ОС), динамически растёт до 1GB (64-bit) / 256MB (32-bit). ^g-stack-size

## API
```go
go func() { /* ... */ }()     // анонимная функция
go myFunction(arg1, arg2)     // явная функция
go obj.Method()               // метод
```
^g-api

**Тысячи и десятки тысяч горутин — норма.** Runtime переваривает такой объём. ^g-scale

## Три признака легковесности

1. Переключение в userspace (runtime Go), не через ядро ОС
2. Минимальный стек — 2KB, растёт динамически
3. Маленькая структура (~сотни байт) 
^g-lightweight-3
