- неправильно: `if len(ch) > 0 { <-ch }` — между строчками может вклиниться другая горутина
- правильно: `select` + `default` — атомарная проверка «могу ли я сейчас?»
- буфер=1 в first-response-wins: страховка от недетерминизма планировщика

---

## Неправильный подход

```go
// НЕ ДЕЛАТЬ — race condition
if len(ch) > 0 {
    v := <-ch  // между len и чтением кто-то мог забрать!
}

if len(ch) < cap(ch) {
    ch <- v    // между len и записью буфер мог заполниться!
}
```

Между **любыми** двумя строчками кода может пройти 1000 лет и встроиться 1000 горутин. len проверил — ок, но к моменту чтения/записи состояние уже изменилось. ^nb-len-race

## Правильный подход — select + default

`select` + `default` даёт **атомарную** проверку: «могу ли я прямо сейчас выполнить операцию?» Если нет — немедленно идёт в `default`, не блокируясь. ^nb-select-default-atomic

```go
// Неблокирующее чтение
select {
case v := <-ch:
    fmt.Println(v)
default:
    // нечего читать — не блокируемся
}

// Неблокирующая запись
select {
case ch <- v:
    // записали
default:
    // некуда писать — не блокируемся
}

// Комбинированное — в одном select можно и читать, и писать
select {
case v := <-ch1:
    process(v)
case ch2 <- result:
    // отправили
default:
    // ничего не готово
}
```

## Пример: first-response-wins без утечки

```go
ch := make(chan int, 1)  // буфер = 1!
for i := 0; i < 5; i++ {
    go func() {
        select {
        case ch <- doWork():
            // записали
        default:
            // кто-то уже записал — уходим, не блокируемся
        }
    }()
}
return <-ch
```

**Почему буфер=1:** планировщик Go недетерминированный. Может ли произойти, что все 5 горутин завершатся до `return <-ch`? Крайне маловероятно, но может. Если все уйдут в default — в канале пусто. ^nb-frw-buf1-reason

Буфер=1 гарантирует: хотя бы одна горутина запишет в буфер, даже если читатель ещё не готов. ^nb-frw-buf1-guarantee
