- на стеке до **10 МБ**, больше → heap
- escape analysis: даже маленький массив уедет в heap если **вернуть адрес** из функции
- передача в функцию → **полная копия** всех данных (10 МБ массив = 10 МБ копирования)
- избежать копии: передать **указатель** `*[N]int` или взять **срез** `arr[:]`
- массив на стеке может **переехать** при росте стека горутины (в отличие от C/C++)

## Аллокация: стек до 10 МБ

Массив размером до 10 МБ аллоцируется на стеке. Всё что больше — на heap. ^array-stack-limit

```go
var a [1_000_000]byte    // 1 МБ → стек ✅
var b [10_000_001]byte   // 10 МБ + 1 байт → heap
```

Проверить: `go build -gcflags="-m"` → покажет `moved to heap`. ^array-escape-flag

Даже маленький массив уедет в heap если escape analysis решит: ^array-escape-small

```go
func makeArray() *[10]int {
    a := [10]int{}
    return &a  // возвращаем адрес → escape → heap
}
```

^493ba2

Escape analysis отрабатывает на этапе компиляции. Сразу принимается решение, что массив будет жить в heap. ^array-escape-compile-time

## Копирование при передаче

Передача массива в функцию — полная копия всех данных. ^array-pass-by-value

```go
func process(arr [10_000_000]int) { // копируется 80 МБ!
    arr[0] = 999  // изменяем копию, оригинал не тронут
}
```

Два способа избежать копирования: ^array-avoid-copy

```go
func byPointer(arr *[1000]int) { arr[0] = 999 }  // указатель
func bySlice(s []int) { s[0] = 999 }              // срез
```

^0b00ff

## Переезд при росте стека горутины

```go
a := [3]int{1, 2, 3}
fmt.Println(&a)         // 0xc000012018
_ = make([]byte, 1<<20) // большая аллокация → стек растёт
fmt.Println(&a)         // 0xc000102018 — адрес изменился!
```

В Go массив на стеке может переехать, когда стек горутины растёт — все данные копируются на новое место. В C/C++ адрес стековой переменной стабилен. ^array-stack-relocation
