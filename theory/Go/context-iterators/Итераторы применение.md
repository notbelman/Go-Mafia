## Зачем итераторы

До Go 1.23 range работал только по встроенным типам: slice, map, string, channel, int. ^apply-before-123

Для обхода дерева или графа — ручной цикл с потенциальной off-by-one error. ^apply-manual-loop-risk

```go
// БЫЛО: обход с конца — легко ошибиться на ±1
for i := len(s) - 1; i >= 0; i-- {
    fmt.Println(s[i])
}

// СТАЛО: slices.Backward
for _, v := range slices.Backward(s) {
    fmt.Println(v)
}
```

Итераторы устраняют off-by-one ошибки при обходе пользовательских структур — логика обхода скрыта внутри итератора. ^apply-off-by-one-fix

## Итераторы в stdlib

```go
// slices
slices.All(s)        // iter.Seq2[int, T] — индекс + значение
slices.Values(s)     // iter.Seq[T] — только значения
slices.Backward(s)   // iter.Seq2[int, T] — с конца

// maps
maps.All(m)          // iter.Seq2[K, V] — ключ + значение
maps.Keys(m)         // iter.Seq[K] — только ключи
maps.Values(m)       // iter.Seq[V] — только значения
```

`slices.All` и `slices.Backward` возвращают `iter.Seq2[int, T]` (индекс + значение). `slices.Values` возвращает `iter.Seq[T]` (только значения). ^apply-slices-types

`maps.All` возвращает `iter.Seq2[K, V]`, `maps.Keys` — `iter.Seq[K]`, `maps.Values` — `iter.Seq[V]`. ^apply-maps-types

Зачем `maps.Values` возвращает итератор, а не срез? Ленивые вычисления: итератор не создаёт новый срез, не аллоцирует память — просто обходит значения. ^apply-lazy-eval

## Pipeline: цепочки итераторов

```go
func Multiply(seq iter.Seq[int], factor int) iter.Seq[int] {
    return func(yield func(int) bool) {
        for v := range seq {
            if !yield(v * factor) { return }
        }
    }
}

func Filter(seq iter.Seq[int], pred func(int) bool) iter.Seq[int] {
    return func(yield func(int) bool) {
        for v := range seq {
            if pred(v) {
                if !yield(v) { return }
            }
        }
    }
}

// Декларативный пайплайн:
source := RangeN(1000)
doubled := Multiply(source, 2)
evens := Filter(doubled, func(n int) bool { return n%2 == 0 })

for v := range evens {
    fmt.Println(v)
}
```

Pipeline строится через вложенные итераторы: каждый принимает `iter.Seq` и возвращает `iter.Seq`. Внутри можно идти range по входному итератору. ^apply-pipeline-pattern

Итераторы компонуются как функциональные трансформеры — декларативный стиль с range без создания промежуточных срезов. ^apply-pipeline-no-alloc

## Производительность

Бенчмарк: обычный range vs итератор до 10 элементов — разница несущественная. ^apply-bench-small

Итераторы не вносят значительный overhead. Если нужен пользовательский тип данных — нет причины не написать итератор. ^apply-perf-conclusion
