- `unsafe.Sizeof(x)` — размер объекта; `unsafe.Alignof(x)` — выравнивание; `unsafe.Offsetof(s.Field)` — смещение поля ^unsafe-funcs
- все три **известны на этапе компиляции** → можно делать compile-time проверки ^unsafe-compile-time
- compile-time assert: трюк с массивом `[0]uintptr` и переполнением беззнакового типа ^compile-assert-trick
- утилита **fieldalignment** — находит структуры с неоптимальным порядком полей ^fieldalignment-tool
- **не оптимизировать раньше срока** — читаемость почти всегда важнее ^premature-opt

## unsafe функции

```go
type Data struct {
    A bool    // offset 0
    B int32   // offset 4
    C bool    // offset 8
}

d := Data{}
fmt.Println(unsafe.Sizeof(d))          // 12
fmt.Println(unsafe.Alignof(d))         // 4
fmt.Println(unsafe.Offsetof(d.A))      // 0
fmt.Println(unsafe.Offsetof(d.B))      // 4
fmt.Println(unsafe.Offsetof(d.C))      // 8
```

^unsafe-funcs-example

## Compile-time проверка размера

```go
type CacheLine struct {
    A int64
    B int64
    C int64
    D int64
    // ... должно быть ровно 64 байта
}

// Если размер ≠ 64 → ошибка компиляции!
var _ [unsafe.Sizeof(CacheLine{}) - 64]byte  // ✅ если 64 байт
// Если 63 → 63-64 = underflow (uintptr беззнаковый) → не скомпилируется
// Если 65 → массив [1]byte — скомпилируется (нужна проверка в обе стороны)

// Полная проверка — в обе стороны:
var _ [64 - unsafe.Sizeof(CacheLine{})]byte
var _ [unsafe.Sizeof(CacheLine{}) - 64]byte
```

Работает потому что `unsafe.Sizeof` возвращает **константу** (uintptr, беззнаковый). Переполнение беззнакового → ошибка компиляции. ^compile-assert-explanation

Для полной проверки нужно **два** выражения в обе стороны: одно ловит случай «меньше», другое — «больше». ^compile-assert-two-sides

## Проверка выравнивания и смещения

```go
// Проверить, что выравнивание структуры = 8
var _ [unsafe.Alignof(Data{}) - 8]byte
var _ [8 - unsafe.Alignof(Data{})]byte

// Проверить, что поле B на смещении 4
var _ [unsafe.Offsetof(Data{}.B) - 4]byte
```

Полезно для бинарных протоколов, где layout структуры критичен. ^compile-assert-align-offset

## Когда оптимизировать

**Не спешить.** Читаемость > оптимизация в 99% случаев.

Оптимизировать когда: структуры в кэшлинии (gamedev), миллиарды объектов, бинарные протоколы. ^when-to-optimize

Иначе — описывать поля в порядке, удобном для чтения. ^readability-first
