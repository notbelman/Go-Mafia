- сравнение структур идёт **поле за полем, слева направо**
- первое различающееся поле → **ранний выход** (остальные не сравниваются)
- если часто сравниваете большие структуры → ставьте различающееся поле **первым**
- три причины думать о порядке полей: **читаемость**, **выравнивание**, **скорость сравнения**

---

## Бенчмарк: порядок полей меняет всё

```go
// Различающееся поле ПЕРВЫМ
type Fast struct {
    Size  int              // отличается!
    Data1 [10_000_000]byte // 10 MB
    Data2 [10_000_000]byte // 10 MB
}

// Различающееся поле ПОСЛЕДНИМ
type Slow struct {
    Data1 [10_000_000]byte // 10 MB
    Data2 [10_000_000]byte // 10 MB
    Size  int              // отличается!
}
```

**Fast:** сравнил Size → не равны → готово (наносекунды). ^struct-cmp-fast

**Slow:** сравнил 10 MB Data1 → равны → сравнил 10 MB Data2 → равны → сравнил Size → не равны (миллисекунды). ^struct-cmp-slow

Разница — **на порядки**. ^struct-cmp-magnitude

## Как работает сравнение

```go
a := MyStruct{F1: ..., F2: ..., F3: ...}
b := MyStruct{F1: ..., F2: ..., F3: ...}

// a == b под капотом:
// 1. Сравнить F1: если ≠ → return false
// 2. Сравнить F2: если ≠ → return false
// 3. Сравнить F3: если ≠ → return false
// 4. return true
```

Сравнение идёт в порядке объявления полей в структуре. Первое различающееся поле → ранний выход. ^struct-cmp-mechanics

## Три причины думать о порядке

1. **Читаемость** — логическая группировка полей (по умолчанию, самое важное) ^struct-order-readability

2. **Выравнивание** — минимизация padding (когда структуры в кэшлинии, миллиарды объектов) ^struct-order-alignment

3. **Скорость сравнения** — различающееся поле первым (когда много сравнений больших структур) ^struct-order-cmp

В большинстве случаев — приоритет читаемости. Остальные два — при явной необходимости + комментарий в коде, чтобы никто не сломал порядок. ^struct-order-priority
