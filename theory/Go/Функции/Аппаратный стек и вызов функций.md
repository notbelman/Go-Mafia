- **SP** (stack pointer) — вершина стека, двигается автоматически при push/pop
- **BP** (base pointer) — начало фрейма текущей функции, **статичен** внутри функции
- **IP** (instruction pointer) — адрес следующей инструкции, двигается автоматически
- CALL = push return address + jump; RET = pop return address + jump back
- фрейм: `call → push old BP → mov SP→BP → push locals`; возврат: `mov BP→SP → pop BP → ret`

---

## Три ключевых регистра

| Регистр | Что хранит | Кто двигает |
| :------ | :--------- | :---------- |
| **SP**  | адрес вершины стека (последний push) | автоматически при push/pop |
| **BP**  | адрес начала фрейма функции | программа (явно при входе/выходе) |
| **IP**  | адрес следующей инструкции | процессор (автоматически) |

SP двигается автоматически при push/pop. BP статичен внутри функции — программа явно устанавливает его при входе и выходе. IP двигает процессор автоматически. ^registers-three

## Почему JMP недостаточно

JMP просто прыгает по адресу. Но:
1. Нужно **запомнить куда вернуться** → CALL сохраняет return address
2. Нужно **передать аргументы** → push в стек или регистры
3. Нужно **сохранить фрейм** вызывающей функции → push old BP ^why-not-jmp

## Вызов функции (полный цикл)

```
Вызывающая сторона:
  push arg2          ; аргументы в обратном порядке (stdcall)
  push arg1
  call func          ; push IP+1 (return addr) → jump func

Вызываемая функция:
  push BP             ; сохранить старый base pointer
  mov BP, SP          ; установить новый base pointer = текущий SP
  push local1         ; локальные переменные
  push local2
  ...                 ; тело функции

Возврат:
  mov SP, BP          ; забыть локальные (не зануляя!)
  pop BP              ; восстановить старый base pointer
  ret                 ; pop return addr → jump back
```

CALL = push return address (IP+1) + jump. RET = pop return address + jump back. ^call-ret-mechanics

## Адресация через BP (статичен!)

```
BP + 6  → arg2          (второй аргумент)
BP + 4  → arg1          (первый аргумент)
BP + 2  → return addr   (адрес возврата)
BP      → old BP        (сохранённый base pointer)
BP - 2  → local1        (первая локальная переменная)
BP - 4  → local2        (вторая локальная переменная)
         ↑ SP (двигается)
```

SP двигается при каждом push/pop, BP — нет. Поэтому адресация идёт от BP. ^bp-addressing

## Стек не зануляется

При выходе `mov SP, BP` просто «забывает» локальные переменные. Данные остаются в памяти до перезаписи следующим вызовом. ^stack-no-zero

В C++ неинициализированная переменная → мусор. В Go zero value гарантирован самим языком. ^go-zero-value-guarantee

## Stack overflow

Бесконечная рекурсия → бесконечные фреймы → стек переполняется. Даже без параметров и локальных переменных: каждый CALL добавляет return address + old BP. ^stackoverflow-cause

В Go: max ~1 ГБ (64-бит), **нельзя** перехватить через recover. ^stackoverflow-go-limit
