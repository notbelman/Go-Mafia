- delete/clear **не освобождают бакеты** (включая overflow). Зануляют ключи/значения, но бакеты живут ^mem-delete-no-free
- пример: 1M записей `[128]byte` → удалили всё → **~293MB висит** (бакеты не почищены) ^mem-example-numbers
- `m = nil` / пересоздать map — **единственный** способ освободить бакеты ^mem-only-way
- если ключ или значение **>128 байт** → Go хранит указатель вместо inline (indirectkey/indirectvalue) ^mem-128-threshold
- совет: указатели в значениях уменьшают потребление бакетной памяти ^mem-pointer-tip

[[map Flashcards - memory]]
## Проблема

```go
m := make(map[int][128]byte)
for i := 0; i < 1_000_000; i++ {
    m[i] = [128]byte{}
}
// Alloc ≈ 461 MB

for k := range m {
    delete(m, k)
}
runtime.GC()
// Alloc ≈ 293 MB  ← бакеты живы, 293 MB не освобождены!
```
^mem-problem-code

Удалили все элементы, но бакеты (включая overflow) остаются в памяти. GC чистит только значения если они содержат указатели, но сами бакеты — никогда. ^mem-gc-behavior

## Почему 461 → 293, а не 461 → 461?

При заполнении происходили resize → старые oldbuckets освобождались GC. Если сделать `make(map, 1_000_000)` заранее (без resize), после delete будет ≈461 MB. ^mem-why-293

## Решения

```go
// 1. Забыть и пересоздать
m = make(map[int][128]byte)  // старые бакеты → GC

// 2. Указатели в значениях
m := make(map[int]*[128]byte)
// бакеты хранят 8-байтный указатель вместо 128-байтного значения
// после delete: указатели зануляются, [128]byte уходит в GC
```
^mem-solutions

## Порог 128 байт

Если ключ или значение >128 байт → Go хранит указатель, не само значение: ^mem-128-detail

```go
map[int][128]byte  // значение inline в бакете (128 байт на слот)
map[int][129]byte  // значение через указатель (8 байт на слот)
```
^mem-128-example

`[129]byte` как value потребляет бакетной памяти как `*[128]byte`. Трюк: увеличить массив на 1 байт → автоматически указатель. ^mem-129-trick
