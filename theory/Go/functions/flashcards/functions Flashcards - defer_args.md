Что выведет этот код?
```go
func process() {
    status := ""
    defer notify(status)
    status = "error"
}
func notify(s string) { fmt.Println(s) }
```
?
`""` (пустая строка) — аргумент `status` скопирован в момент defer, когда status ещё "". Изменение status после defer не влияет на уже скопированное значение.

Что выведет этот код?
```go
func process() {
    defer notify(get())
    fmt.Println("2")
}
func get() string  { fmt.Println("1"); return "arg" }
func notify(s string) { fmt.Println("3") }
```
?
`1`, затем `2`, затем `3` — `get()` вызывается немедленно при откладывании defer, печатает "1". Потом выполняется тело функции — "2". При выходе `notify` выполняется — "3".

Что произойдёт при выходе из функции, если был отложен nil через `defer f()`?
?
![[Defer аргументы и ловушки#^da-nil-panic]]
<!--SR:!2026-02-25,1,230-->

Что выведет этот код?
```go
var f func()
defer f()
f = func() { fmt.Println("executed") }
```
?
`panic: runtime error: invalid memory address or nil pointer dereference` — в момент `defer f()` значение f (nil) скопировано. Последующее переприсвоение f не влияет на отложенный вызов.
