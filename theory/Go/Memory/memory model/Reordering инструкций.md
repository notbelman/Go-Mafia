- **Компилятор**: видит независимые инструкции → переставляет для лучшего register allocation, instruction scheduling. Не знает про другие потоки.
- **Процессор**: pipeline + out-of-order execution. Если инструкция A ждёт данные из RAM (сотни тактов), процессор выполняет инструкцию B пока ждёт. Также store buffer: запись может "застрять" в буфере и стать видимой другому ядру позже.
- В рамках одного потока результат не меняется (иллюзия последовательности). Для другого потока — ломает логику ^reorder-single-thread
- Data race = симптом: компилятор/процессор не знает что кто-то читает из другого потока → реордерит свободно ^reorder-data-race-signal

## Проблема

```go
var msg string
var flag bool

go func() {           // горутина 1
    msg = "hello"     // (A)
    flag = true       // (B)
}()

for !flag {           // горутина 2
    runtime.Gosched()
}
fmt.Println(msg)      // (C) — всегда ли "hello"?
```

В рамках горутины 1: порядок A→B или B→A не важен — результат одинаковый (msg и flag независимы). Компилятор/процессор **может** переставить B перед A. ^reorder-example-goroutine1

Для горутины 2: если B выполнилось раньше A → flag=true, но msg ещё пустой → печатает "". ^reorder-example-goroutine2

## Кто реордерит и зачем

**Компилятор**: видит независимые инструкции → переставляет для лучшего register allocation, instruction scheduling. Не знает про другие потоки. ^reorder-compiler

**Процессор**: pipeline + out-of-order execution. Если инструкция A ждёт данные из RAM (сотни тактов), процессор выполняет инструкцию B пока ждёт. ^reorder-cpu-ooo

Также store buffer: запись может "застрять" в буфере и стать видимой другому ядру позже. ^reorder-store-buffer

## Правило

Reordering **никогда** не нарушает результат в рамках одного потока. Но **может** нарушить логику другого потока, читающего те же данные. ^reorder-rule

**Data race = сигнал**: компилятор/процессор не знает о другом потоке → свободно реордерит. Примитивы синхронизации (atomic, mutex) говорят: "сюда лезут из другого потока, не реордери". ^reorder-sync-primitives

## "Термоядерные баги"

Могут не проявляться годами:

- Зависят от архитектуры (x86 строже, ARM слабее) ^reorder-arch-diff
- Зависят от версии компилятора (новые оптимизации) ^reorder-compiler-version
- Зависят от нагрузки (timing) ^reorder-timing
- Воспроизводятся 1 раз из 10.000 ^reorder-repro-rate
