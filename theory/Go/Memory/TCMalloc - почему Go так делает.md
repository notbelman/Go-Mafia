- **TCMalloc** = Thread-Cache Malloc — аллокатор от Google ^tcm-def

- решает две проблемы обычного malloc: **contention** и **фрагментация** ^tcm-two-problems

- Go взял обе идеи и улучшил: кэш на P вместо потока ^tcm-go-improvement

---

[[memory Flashcards - tcmalloc]]

**Проблема 1: Contention**

malloc: все потоки конкурируют за один глобальный лок. ^tcm-malloc-contention

→ TCMalloc: у каждого потока свой кэш. Большинство аллокаций без лока. ^tcm-thread-cache

→ Go: кэш на P (не на поток), чтобы не тратить память на заблокированных потоках. ^tcm-go-p-cache

**Проблема 2: Фрагментация**

malloc: выделяет блоки произвольного размера → дыры разного размера → фрагментация. ^tcm-malloc-frag

→ TCMalloc: блоки фиксированных размеров (классы). Одинаковые рядом → нет фрагментации. ^tcm-size-classes-frag

**Почему Go не вызывает malloc напрямую:**

Каждый вызов malloc = syscall = дорого. Go запрашивает у ОС сразу 64MB (арена) и раздаёт сам. ^tcm-no-malloc-direct
