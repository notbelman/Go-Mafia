- стек горутины: 2KB → растёт x2 при нехватке, **сужается** x2 при использовании <25%
- contiguous stacks (Go 1.4+): копирование в новый блок + обновление указателей (stack maps), нет hot split
- uintptr **не обновляется** при переносе (семантически не указатель)
- макс: ~1GB (64-bit), ~250MB (32-bit). Стек аллоцируется в хипе → может расти

[[memory Flashcards - stack_growth]]

Стек горутины начинается с 2KB и растет автоматически при нехватке места. ^sg-initial-size

**Как работает:** ^09767d
```
1. Компилятор вставляет проверку в начало каждой функции (prologue)

func foo() {
    // [скрытый код] if SP < stackguard { runtime.morestack() }
    ...
}

2. Если места мало -- runtime.morestack():
   - аллоцирует новый стек (2x размер)
   - копирует данные со старого стека
   - обновляет все указатели на стек
	 - очищает старый стек
   - продолжает выполнение
```

^ea3b77

Компилятор вставляет проверку в prologue каждой функции: `if SP < stackguard { runtime.morestack() }`. ^sg-prologue-check

При вызове `runtime.morestack()`: аллоцируется новый стек размером 2x, копируются данные, обновляются все указатели, выполнение продолжается. ^sg-morestack-steps

```
До роста:              После роста:
+--------+ 2KB         +--------+ 4KB
| frame1 |             | frame1 |
| frame2 |             | frame2 |
| frame3 |             | frame3 |
+--------+ <- мало     |  free  |
                       |  free  |
                       +--------+ <- есть место
```

**Почему копирование, а не сегменты:**

Go 1.3 и раньше использовал segmented stacks (связный список сегментов). ^sg-segmented-old

Проблема segmented stacks — «hot split»: функция на границе стека постоянно аллоцирует/освобождает сегмент. ^sg-hot-split

Go 1.4+: contiguous stacks (копирование) — дороже разово, но нет hot split. ^sg-contiguous

**Лимиты:**

- начальный размер: 2KB
- максимум: ~1GB (64-bit), ~250MB (32-bit)
- рост: x2 каждый раз ^sg-limits

**Указатели фиксятся автоматически:**
```go
func foo() {
    x := 42
    bar(&x)  // если стек вырастет во время bar(), адрес &x обновится
}
```

^28a75e

Runtime знает где на стеке лежат указатели (stack maps от компилятора) и корректирует их при копировании. ^sg-stack-maps

`uintptr` не обновляется при переносе стека — это число, а не указатель. ^sg-uintptr

**Сужение стека:**

Если горутина использует менее 25% стека, runtime сужает его в 2 раза. ^sg-shrink-threshold

Например: стек 8KB, используется <2KB → сузится до 4KB. ^sg-shrink-example
