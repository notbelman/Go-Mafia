- ОС **не знает** где указатели в стеке → не может скопировать/обновить → выделяет много сразу ^os-stack-no-maps
- Go runtime **знает** (stack maps от компилятора) → может копировать и обновлять указатели ^go-stack-maps
- поток ОС: 1-8 MB сразу. Горутина: 2KB → растёт по необходимости ^stack-sizes-compare

[[memory Flashcards - os_thread_stack]]

ОС не может динамически растить стек потока:

- Не знает где в стеке лежат указатели → не может скопировать стек в новое место ^os-no-ptr-knowledge
- Не контролирует пользовательский код → не может обновить указатели ^os-no-control
- Единственный вариант — выделить много сразу с запасом ^os-must-reserve

Go runtime может:

- Компилятор генерирует stack maps — runtime знает где каждый указатель ^go-stack-maps-detail
- Контролирует весь код — вставляет проверку переполнения в пролог каждой функции ^go-prologue-check
- При нехватке — аллоцирует новый стек ×2, копирует, обновляет указатели ^go-grow-mechanism

Поэтому горутина стартует с 2 KB и растёт по необходимости. Поток ОС вынужден сразу резервировать 1-8 MB. ^stack-size-conclusion
