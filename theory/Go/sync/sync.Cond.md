Условная переменная -- горутины ждут наступления условия и получают уведомления об изменениях. ^cond-definition

| Метод               | Что делает                                                                                | Правило                                               |
| :------------------ | :---------------------------------------------------------------------------------------- | :---------------------------------------------------- |
| `NewCond(l Locker)` | Создает Cond с указанным локером                                                          | --                                                    |
| `Wait()`            | Встает в очередь `notifyList`, отпускает лок, засыпает, после пробуждения захватывает лок | Вызывать с захваченным локом, в цикле `for` (не `if`) |
| `Signal()`          | `runtime_notifyListNotifyOne` -- будит одну горутину                                      | --                                                    |
| `Broadcast()`       | `runtime_notifyListNotifyAll` -- будит все горутины                                       | Можно вызывать много раз (в отличие от `close(ch)`)   |
^cond-api-table

```go
cond := sync.NewCond(&sync.Mutex{})

// Ожидающая горутина
cond.L.Lock()
for !condition() {
    cond.Wait()
}
// ... используем ресурс ...
cond.L.Unlock()

// Уведомляющая горутина
cond.L.Lock()
// ... меняем состояние ...
cond.L.Unlock()
cond.Signal() // или Broadcast()
```
^cond-usage-pattern

### Почему Wait() нужно вызывать в цикле `for`, а не `if`

После пробуждения горутина обязана **перепроверить условие**: другая горутина могла уже забрать ресурс, или пробуждение было spurious (ложным). Использование `if` вместо `for` — классический баг. ^cond-wait-for-loop

### Signal vs Broadcast

`Signal()` будит ровно одну горутину из очереди. `Broadcast()` будит все. В отличие от `close(ch)`, `Broadcast()` можно вызывать многократно без паники. ^cond-signal-vs-broadcast
