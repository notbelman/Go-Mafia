Все ключи с одинаковым хешем попадают в один bucket → цепочка растёт → O(1) деградирует до O(n). ^hashdos-mechanism

**Как:** злоумышленник отправляет запрос с тысячами параметров, подобранных чтобы хеши коллидировали. ^hashdos-attack

**Защита Go:** рандомизированный seed хеш-функции при создании каждой мапы. Один и тот же ключ даёт разный хеш в разных мапах → заранее подобрать коллизии нельзя. ^hashdos-defense

**Практическое следствие:** HTTP-серверы на Go не нужно дополнительно защищать от HashDoS через смену хеш-библиотеки — runtime делает это автоматически при каждом `make(map)`. ^hashdos-practical
