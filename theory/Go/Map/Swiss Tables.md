## Проблемы старой реализации

| Проблема | Причина |
|:---------|:--------|
| Медленный поиск | цепочки переполнения = связанный список = прыжки по памяти = промахи кэша |
| Раздувание памяти | overflow-бакеты живут в памяти даже после удаления элементов |
| Дорогая переиндексация | удвоение размера + пересчёт хэшей всех элементов |

^st-old-problems

## Структура Swiss Table

```
Группа 0                Группа 1                Группа 2
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ ctrl word (64 б) │   │ ctrl word (64 б) │   │ ctrl word (64 б) │
├──┬──┬──┬──┬──┬──┤    ├──┬──┬──┬──┬──┬── ┤   ├──┬──┬──┬──┬──┬──-┤
│s0│s1│s2│s3│s4│s5│... │s0│s1│s2│s3│s4│s5 │...│s0│s1│s2│s3│s4│s5 │...
│s6│s7│           │    │s6│s7│            │   │s6│s7│            │
└──┴──┘           │    └──┴──┘            │   └──┴──┘            │
     8 слотов          8 слотов              8 слотов
```

Один массив, разделённый на группы по 8 слотов. Кэш-дружелюбно — нет прыжков по связанным спискам. ^st-structure-cache

## Контрольное слово (64 бита = 8 байт)

Каждый байт соответствует одному слоту: ^st-ctrl-layout

| Значение | Смысл |
|:---------|:------|
| 0x00 | слот пустой |
| 0x7F | слот удалён (deleted, нужен для пробирования) |
| 0x01-0x7E | H2 — младшие 7 бит хэша ключа |

^st-ctrl-values

Зачем deleted? Открытая адресация: поиск идёт до пустого слота. Если удалить элемент и пометить пустым — заколлиженные элементы за ним станут недоступны. ^st-ctrl-deleted-reason

## H1 и H2: разделение хэша

```
64-битный хэш:
┌─────────────────────────────────┬───────┐
│           H1 (57 бит)           │H2(7б) │
└─────────────────────────────────┴───────┘
         ↓                            ↓
    выбор группы              контрольное слово
```

H1 определяет в какую группу попадает ключ. ^st-h1-role

H2 записывается в контрольное слово и используется для быстрой фильтрации: прежде чем сравнивать полные ключи (которые могут быть 128 байт), сравниваем 7 бит. Та же идея что tophash в старой реализации. ^st-h2-role

## SIMD: 8 сравнений за одну инструкцию

Контрольное слово = 64 бита. Загружаем в векторный регистр, сравниваем с H2 за одну CPU-инструкцию (AVX/SSE). Результат — маска: какие слоты являются кандидатами для полного сравнения ключа. Фактически 8 шагов линейного поиска выполняются параллельно. ^st-simd-mechanism

## Вставка и поиск

1. Вычислить хэш → разделить на H1 и H2 ^st-lookup-step1
2. H1 → найти группу ^st-lookup-step2
3. Проверить контрольное слово группы (SIMD): есть ли слот с таким H2? ^st-lookup-step3
4. Кандидаты → сравнить полные ключи ^st-lookup-step4
5. Если группа заполнена → пробирование к следующей группе (открытая адресация на уровне групп) ^st-lookup-step5

## Go: несколько Swiss Tables вместо одной

```
Хэш-таблица (map)
    ├── Swiss Table 0 (≤1024 записей)
    ├── Swiss Table 1 (≤1024 записей)
    ├── Swiss Table 2 (≤1024 записей)
    └── ...
```

Переменное количество верхних бит H1 выбирает конкретную Swiss Table (расширяемое хэширование: 8 таблиц → 3 бита, 16 таблиц → 4 бита). ^st-multi-routing

Выгода: при переиндексации расширяется одна маленькая таблица (≤1024 элементов), а не гигабайтная. Остальные таблицы не затрагиваются. ^st-multi-benefit
