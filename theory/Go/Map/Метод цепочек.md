- бакет = указатель на **связный список** (или массив, дерево — не ограничен) ^ch-bucket-def
- вставка: хэш → бакет → добавить в список. Поиск: пройти список, **сравнивая ключи** ^ch-insert-search
- ключ хранится в бакете обязательно — для разрешения коллизий (хэш одинаковый, ключ разный) ^ch-why-store-key
- оптимизация итерации: **двусвязный список** между всеми элементами (пропуск пустых бакетов) ^ch-doubly-linked
- оптимизация поиска: **кэшировать хэш** рядом с ключом (не пересчитывать при проходе) ^ch-cache-hash
- **Go использует метод цепочек** (до Go 1.24, потом Swiss Table) ^ch-go-version

[[map Flashcards - chaining]]
## Как работает

```
hashtable[4]    (4 бакета)

bucket 0: → nil
bucket 1: → [key=5, val=200] → [key=9, val=900] → nil   ← коллизия 5%4=1, 9%4=1
bucket 2: → nil
bucket 3: → [key=3, val=300] → nil
```
^ch-example

**Вставка:** `hash(key) % cap` → бакет → добавить в начало или конец списка. ^ch-insert-detail

**Поиск:** `hash(key) % cap` → бакет → пройти список, сравнить ключи. Не нашли → нет элемента. ^ch-search-detail

**Удаление:** найти → удалить из списка. ^ch-delete

## Зачем хранить ключ?

При коллизии в одном бакете несколько элементов с разными ключами. Без ключа невозможно отличить `key=5` от `key=9`. ^ch-why-key-long

## Оптимизация: двусвязный список

Проблема: при итерации приходится заглядывать в пустые бакеты. Решение: связать все элементы двусвязным списком между бакетами → итерация пропускает пустые. ^ch-doubly-linked-detail

При поиске: иду по списку, сравниваю хэши. Как только хэш отличается от искомого → перешёл в другой бакет → стоп. ^ch-hash-compare-stop

## Оптимизация: кэширование хэша

Хранить хэш рядом с ключом → не пересчитывать при проходе по списку. Платим памятью, выигрываем время. ^ch-cache-hash-detail
