- Мьютекс Петерсона — классический алгоритм взаимного исключения для **двух** потоков без аппаратных атомиков
- Два флага "хочу войти" + переменная "чья очередь уступить" — вместе гарантируют mutex
- Исторически важен, но на практике не используется: нужны memory barriers, работает только для 2 потоков

---

## Идея — вежливость

Два потока (0 и 1). Каждый говорит "я хочу войти" и "уступаю другому". Если оба хотят — входит тот, кому не уступают.

```go
var (
    flag [2]bool  // flag[i] = "поток i хочет войти"
    turn int      // чья очередь уступить
)

// Поток id (0 или 1) хочет войти
func Lock(id int) {
    other := 1 - id
    flag[id] = true   // "я хочу войти"
    turn = id         // "но уступаю другому"
    for flag[other] && turn == id {
        // другой тоже хочет, и я уступил — жду
    }
}

func Unlock(id int) {
    flag[id] = false  // "я вышел"
}
```

## Почему работает

Три свойства:
1. **Mutual exclusion**: если оба хотят (flag[0]=flag[1]=true), то turn может быть только 0 или 1 — один из них пройдёт цикл, другой застрянет ^peterson-mutual-exclusion
2. **Progress**: если один не хочет (flag=false), другой сразу проходит ^peterson-progress
3. **No starvation**: уступающий (turn=id) дождётся — другой выставит turn на себя при следующем Lock ^peterson-no-starvation

## Проблемы на современном железе

**Memory reordering**: CPU и компилятор могут переставить `flag[id] = true` и `turn = id`. Если `turn = id` выполнится раньше `flag[id] = true` — алгоритм сломается. Нужны **memory barriers** / **atomic operations**. ^peterson-reordering

```go
// Правильная версия:
atomic.StoreInt32(&flag[id], 1)     // store-release
atomic.StoreInt32(&turn, id)        // store-release
for atomic.LoadInt32(&flag[other]) == 1 && atomic.LoadInt32(&turn) == id {
    runtime.Gosched()
}
```
