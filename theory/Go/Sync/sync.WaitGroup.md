Счетчик для ожидания завершения группы горутин. ^wg-definition

| Метод    | Что делает                                                                    | Правило                                |
| :------- | :---------------------------------------------------------------------------- | :------------------------------------- |
| `Add(n)` | Атомарно меняет counter, если стал 0 -- будит всех через `runtime_Semrelease` | Вызывать ДО запуска горутины           |
| `Done()` | `Add(-1)`                                                                     | Счетчик не должен уйти в минус (panic) |
| `Wait()` | Увеличивает waiters, блокируется на семафоре через `runtime_Semacquire`       | --                                     |
^wg-api-table

```go
var wg sync.WaitGroup

for i := 0; i < N; i++ {
    wg.Add(1)
    go func() {
        defer wg.Done()
        // работа
    }()
}

wg.Wait()
```
^wg-usage-pattern

### Почему Add(1) вызывать ДО запуска горутины

Если вызвать `Add(1)` внутри горутины — `Wait()` может завершиться до того, как горутина успеет инкрементировать счётчик. Это гонка данных. ^wg-add-before-goroutine

### Что произойдёт если Done() уведёт счётчик в минус

`WaitGroup` вызовет panic. Это защита от программных ошибок — отрицательный счётчик означает, что `Done()` вызван больше раз, чем `Add()`. ^wg-negative-panic

## Внутреннее устройство
```go
type WaitGroup struct {
    noCopy noCopy        // защита от копирования
    state  atomic.Uint64 // counter (биты 0-31) + waiters (биты 33-63)
    sema   uint32        // семафор
}
```
^wg-struct

### Как state упаковывает counter и waiters

`state` — одно `atomic.Uint64`, в котором упакованы два значения: **counter** в старших 32 битах и **waiters** в младших 32 битах. Атомарное обновление сразу обоих значений без дополнительных локов. ^wg-state-packing
