- `panic(nil)` — с Go 1.21+ создаёт `runtime.PanicNilError` (не просто nil) ^panic-nil-121
- проброс паники: recover → что-то сделать → panic(r) снова ^panic-rethrow-def
- подмена: паника в defer **заменяет** текущую (одна паника на функцию в любой момент) ^panic-replace-def
- антипаттерн **panic jump**: выпрыгнуть из вложенных циклов/функций через panic+recover ^panic-jump-def
- после recover выполнение продолжается **из defer**, не с места паники; остальные defer'ы тоже вызываются (LIFO) ^panic-after-recover

## panic(nil)

```go
func main() {
    defer func() {
        r := recover()
        fmt.Printf("%T: %v\n", r, r)
    }()
    panic(nil)
}
// Go 1.21+: *runtime.PanicNilError: panic called with nil argument
// До 1.21: <nil>: <nil> (было невозможно отличить от «нет паники»)
```

До Go 1.21 `panic(nil)` создавал проблему: в defer `recover()` возвращал `nil`, и было невозможно отличить «паники не было» от `panic(nil)`. С 1.21 `panic(nil)` оборачивается в `*runtime.PanicNilError`. ^panic-nil-problem

## Проброс паники

```go
func process() {
    defer func() {
        r := recover()
        log.Println("panic:", r)  // залогировали
        panic(r)                   // пробросили дальше
    }()
    panic("critical error")
}

func main() {
    defer func() {
        r := recover()
        fmt.Println("main caught:", r)  // перехватили
    }()
    process()
}
// panic: critical error (в логе)
// main caught: critical error
```

Редкий случай: нужно залогировать панику, но не обрабатывать — пусть летит дальше. ^panic-rethrow-usecase

## Подмена паники

```go
func main() {
    defer func() { fmt.Println("recovered:", recover()) }()

    defer func() { panic(3) }()  // заменит panic(2)
    defer func() { panic(2) }()  // заменит panic(1)
    defer func() { panic(1) }()  // заменит panic(0)
    panic(0)
}
// recovered: 3
```

Функция в любой момент ассоциирована **не более чем с одной** паникой. Новая паника в defer → заменяет предыдущую. Последняя паника (3) — та, что будет поймана recover. ^panic-replace-mechanics

## Антипаттерн: panic jump

```go
func deepSearch(data [][]int, target int) (result int, found bool) {
    defer func() {
        if r := recover(); r != nil {
            result = r.(int)
            found = true
        }
    }()

    for _, row := range data {
        for _, val := range val {
            if val == target {
                panic(val)  // ❌ «прыжок» через panic — антипаттерн!
            }
        }
    }
    return 0, false
}
```

Выпрыгнуть из вложенных циклов через panic — работает, но это злоупотребление механизмом паники. Используйте обычный return, флаги или вынесите в отдельную функцию. ^panic-jump-alternatives

## После recover — продолжение из defer

```go
func example() {
    defer fmt.Println("3: last defer")           // вызовется
    defer func() {
        recover()
        fmt.Println("2: recovered")
    }()
    defer fmt.Println("1: first after panic")     // вызовется

    panic("boom")
    fmt.Println("unreachable")
}
// 1: first after panic
// 2: recovered
// 3: last defer
```

Recover не возвращает к месту паники. Все defer'ы функции выполняются (LIFO), затем выход из функции. ^panic-recover-flow
