- `[]byte(s)` и `string(b)` — **всегда аллокация + копирование** (иммутабельность) ^conv-always-alloc
- каждая конверсия = +N байт в памяти. Две конверсии подряд = **тройной расход** ^conv-triple-cost
- `[]rune(string(b))` — **2 аллокации**, прямого каста `[]byte → []rune` нет ^conv-rune-two-allocs
- компилятор убирает копирование в 4 случаях: range, map lookup, сравнение, конкатенация с литералом ^conv-compiler-opts
- для горячих путей — unsafe конверсия (×15 быстрее) ^conv-unsafe-perf

---

**Проблема:** string иммутабельна, []byte мутабелен. Они не могут шарить память — иначе []byte сломает string. ^conv-immutability-reason

```go
s := "hello"
b := []byte(s)  // копируем 5 байт в новый []byte
b[0] = 'H'      // меняем b
fmt.Println(s)  // "hello" — s не изменилась, потому что это копия
```
^conv-immutability-example

**Каждая конверсия = аллокация + копирование:**
```go
s := "hello"       // 5 байт в памяти
b := []byte(s)     // +5 байт (копия)
s2 := string(b)    // +5 байт (ещё копия)
// итого: 15 байт вместо 5
```
^conv-triple-example

## Нет прямого каста []byte ↔ []rune

```go
[]rune([]byte("hello"))  // ❌ не компилируется

// Нужно через строку — 2 аллокации:
[]rune(string(b))  // []byte → string (аллокация) → []rune (аллокация)
```
^conv-no-direct-rune

Эффективный способ — ручная конвертация: считаешь длину рун, создаёшь slice, копируешь побайтово. Одна аллокация. ^conv-manual-rune

## Оптимизации компилятора (без аллокации)

```go
// 1. range — временный []byte, никуда не сохраняется
for i, b := range []byte(s) { ... }  // ✅ нет копии

// 2. map lookup — string нужна только для хэширования
m := map[string]int{"key": 1}
_ = m[string(b)]  // ✅ нет копии

// 3. сравнение — string живёт мгновение
if string(b) == "key" { ... }  // ✅ нет копии

// 4. конкатенация с литералом в сравнении
if string(b1) + "suffix" == string(b2) + "suffix" { ... }  // ✅ одна аллокация вместо трёх
```
^conv-compiler-opts-examples

Компилятор видит, что string живёт мгновение и никуда не сохраняется. ^conv-compiler-reasoning
