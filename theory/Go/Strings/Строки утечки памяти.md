- подстрока от гигабайтной строки: **20 байт держат 1 ГБ** (тот же underlying массив) ^leak-problem
- подстрока = новый header с тем же ptr → GC не может собрать оригинал ^leak-gc-reason
- решение: **принудительное копирование** через `string([]byte(s[i:j]))` (2 аллокации) ^leak-fix
- `strings.Clone(s)` (Go 1.20+) — чище, но внутри то же самое ^leak-clone
- аналогично subslice утечкам в slice ^leak-analogy

## Проблема

```go
func findSequence(data string) string {  // data = 1 ГБ
    idx := findStart(data)
    return data[idx : idx+20]  // 20 байт, но держит 1 ГБ!
}
```

Подстрока — новый header `{ptr, len=20}`, но ptr указывает внутрь гигабайтного массива. GC видит ссылку → не освобождает.

```
data  ──► ptr ──► [......1 ГБ данных......]
                       ↑
sub   ──► ptr ─────────┘  len=20
// Весь 1 ГБ жив из-за 20-байтной подстроки
```

## Решение: копирование

```go
func findSequence(data string) string {
    idx := findStart(data)
    sub := data[idx : idx+20]
    return string([]byte(sub))  // копия! GC заберёт оригинал
}
```

`string([]byte(...))` — аллокация + копирование 20 байт. Оригинальный 1 ГБ массив больше никем не держится → GC заберёт. ^leak-fix-mechanism

## strings.Clone (Go 1.20+)

```go
return strings.Clone(data[idx : idx+20])  // то же, но читабельнее
```

`strings.Clone` добавлен в Go 1.20. Внутри делает то же `string([]byte(s))`, но явно выражает намерение. ^leak-clone-detail

## Почему простое присваивание не помогает

```go
s2 := s[i:j]    // ❌ просто новый header, тот же ptr
s2 = s[i:j]     // ❌ то же самое
var s2 string = s[i:j]  // ❌ то же самое
```

При копировании строки копируется только header (16 байт). Данные всегда шарятся. Единственный способ разорвать связь — пройти через `[]byte` (принудительное копирование данных). ^leak-why-assign-fails
