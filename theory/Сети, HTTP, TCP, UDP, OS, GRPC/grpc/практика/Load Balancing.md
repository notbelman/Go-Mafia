## Проблема
HTTP/2 = одно долгоживущее TCP-соединение, все запросы мультиплексируются.
L4 балансировщик (Kubernetes Service, NLB) балансирует **соединения**, не запросы.
Результат: все запросы от клиента идут на один pod, остальные простаивают.

## Решения

**L7 proxy** (балансирует на уровне запросов):
- Envoy, Istio, Linkerd, nginx (с `grpc_pass`)
- Разбирает HTTP/2, каждый RPC маршрутизирует отдельно
- Envoy — стандарт де-факто для gRPC

**Client-side** (клиент сам выбирает backend):
- Headless Service в K8s → DNS возвращает IP всех подов
- `round_robin` policy в grpc-go
- Минус: нужен DNS re-resolve при изменении подов

**Service mesh** (Istio и т.д.):
- Envoy sidecar в каждом поде, L7 балансировка прозрачно
- Плюс: трейсинг, circuit breaker, mTLS "бесплатно"
- Минус: сложность, ~20% overhead

## MaxConnectionAge и деплой

После деплоя новых подов старые клиенты держат соединения к старым подам.
`MaxConnectionAge` на сервере принудительно закрывает соединение →
клиент переподключается → DNS re-resolve → попадает на новые поды.

Без этого: новый деплой, а трафик всё ещё на старых подах.

## Что выбрать
Мало сервисов, простой случай → client-side + headless service.
Продакшн с десятками сервисов → L7 proxy или service mesh.
