## Зачем
HTTP/2 соединение может "умереть" незаметно (пакеты дропаются,
L4 балансировщик убивает idle-соединения). TCP таймаут обнаружит это
через ~30 минут. gRPC keepalive — через секунды.

## Как работает
Периодические HTTP/2 PING-фреймы. Нет ответа в течение Timeout → соединение мёртвое, переподключение.

## Клиент
- **Time** — интервал пингов при отсутствии активности (мин 10s)
- **Timeout** — сколько ждать PING ACK (default 20s)
- **PermitWithoutStream** — пинговать даже без активных стримов

## Сервер
- **MaxConnectionIdle** — закрыть idle-соединение (GOAWAY)
- **MaxConnectionAge** — принудительно закрыть после N времени (±10% jitter).
  Зачем: заставить клиента переподключиться → DNS re-resolve → новые поды
- **MaxConnectionAgeGrace** — сколько ждать завершения текущих RPC после GOAWAY
- **Time / Timeout** — серверные пинги

## EnforcementPolicy (защита сервера)
- **MinTime** — минимальный интервал между пингами клиента (default 5 мин)
- **PermitWithoutStream** — разрешить пинги без стримов

Клиент пингует чаще MinTime → сервер закрывает соединение (`too_many_pings`).

## Главная ловушка
Клиент и сервер с несогласованными настройками → случайные connection reset.
Деплоить осторожно: **сначала** сервер с новым MinTime, **потом** клиент с новым Time.
