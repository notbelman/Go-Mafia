## protoc vs buf

**protoc** — официальный компилятор от Google.
Требует ручной установки плагинов (`protoc-gen-go`, `protoc-gen-go-grpc`),
длинных CLI-флагов, bash-скриптов для сборки. Хрупко, плохо воспроизводимо.

**buf** — современная замена. Декларативная конфигурация вместо флагов:
```yaml
# buf.gen.yaml
version: v2
plugins:
  - remote: buf.build/protocolbuffers/go
    out: gen/go
  - remote: buf.build/grpc/go
    out: gen/go
```
Плюсы buf: встроенный линтер (`buf lint`), детектор ломающих изменений
(`buf breaking`), remote-плагины (не нужно ставить локально), 2x быстрее protoc.

## Хранение протофайлов

**Отдельный репозиторий** (рекомендуется для нескольких команд/языков):
```
proto-repo/
├── order/v1/order.proto
├── user/v1/user.proto
└── buf.yaml
```
Один владелец контракта → генерация артефактов для Go, Python и т.д.

**В репозитории сервиса** — ок для маленьких проектов, но рискует
рассинхроном если клиентов > 1.

## CI pipeline (senior-уровень)
```
push .proto → buf lint → buf breaking (vs main) → buf generate → commit gen/
```

`buf lint` — стиль, именование, package.
`buf breaking` — ловит: удалённые поля, изменённые типы, переименованные сервисы.
Без этого шага один PR может сломать все клиенты.

## Что генерируется в Go

`.pb.go` — структуры сообщений, Marshal/Unmarshal (от `protoc-gen-go`).
`_grpc.pb.go` — клиент, серверный интерфейс, Register-функция (от `protoc-gen-go-grpc`).
Сгенерированный код **не редактируем**, коммитим в репо или генерим в CI.
