- **Сокет** — файловый дескриптор для сетевого I/O. Интерфейс ОС для отправки/приёма данных. Всё как с файлами: open → read/write → close
- **Типы**: `SOCK_STREAM` (TCP — byte stream), `SOCK_DGRAM` (UDP — датаграммы), `SOCK_RAW` (IP уровень — ping, traceroute)
- **Блокирующий** (дефолт): read/write блокируют поток до завершения. **Неблокирующий** (`O_NONBLOCK`): возвращают `EAGAIN` если нет данных → нужен мультиплексор
- **Мультиплексирование**: `select` (лимит 1024 fd) → `poll` (без лимита) → **`epoll`** (Linux, O(1) на событие). Go runtime использует **epoll/kqueue** через netpoll
- Go делает все сокеты **неблокирующими** автоматически. Горутина "блокируется" на `conn.Read()`, но M свободен (gopark → epoll → goready)

## Жизненный цикл (TCP сервер)

```
Сервер:                              Клиент:
socket()   → fd                      socket()   → fd
bind()     → привязать к адресу
listen()   → начать принимать
accept()   → ждать клиента  ←─────── connect()  → соединиться
read()     ← данные ────────────────  write()
write()    → данные ────────────────→ read()
close()                              close()
```

```go
// Go прячет это за net.Listen / net.Dial:
ln, _ := net.Listen("tcp", ":8080")    // socket + bind + listen
conn, _ := ln.Accept()                  // accept
buf := make([]byte, 1024)
n, _ := conn.Read(buf)                  // read
conn.Write([]byte("hello"))             // write
conn.Close()                            // close
```

## Блокирующий vs Неблокирующий

**Блокирующий** (дефолт):
```c
read(fd, buf, size);  // поток СПИТ пока не придут данные
                       // один поток = одно соединение
```

**Неблокирующий** (`O_NONBLOCK`):
```c
read(fd, buf, size);  // нет данных → errno = EAGAIN, возвращается сразу
                       // нужен цикл или мультиплексор
```

## Мультиплексирование: select → poll → epoll

| | select | poll | epoll |
|:--|:--|:--|:--|
| Лимит fd | **1024** (FD_SETSIZE) | нет | нет |
| Сложность | O(n) на каждый вызов | O(n) | **O(1)** на событие |
| Механизм | копирует все fd в ядро каждый раз | копирует все fd | ядро хранит список, уведомляет |
| Год | 1983 | 1986 | Linux 2002 |

**epoll** — ядро **само** следит за fd и уведомляет о готовности. Не нужно копировать список fd каждый раз.

```c
// Псевдокод epoll
int epfd = epoll_create(1);
epoll_ctl(epfd, EPOLL_CTL_ADD, client_fd, &event);  // добавить fd
epoll_wait(epfd, events, max_events, timeout);       // ждать готовности
// вернулись только ГОТОВЫЕ fd (не все)
```

**kqueue** — аналог epoll на macOS/BSD.

## Go: netpoll

Go runtime делает **все** сетевые сокеты неблокирующими + регистрирует в epoll/kqueue.

```
conn.Read(buf):
  1. Попробовать неблокирующий read → есть данные? вернуть
  2. Нет данных → gopark (горутина засыпает, M свободен)
  3. epoll_wait сообщил "fd готов" → goready (горутина просыпается)
  4. Прочитать данные → вернуть
```

**Результат**: горутина "блокируется" на Read/Write, но **M не блокируется**. Тысячи горутин ждут сеть — занимая всего несколько M.

## Адрес сокета

```go
addr := conn.RemoteAddr()  // IP:port удалённой стороны
addr := conn.LocalAddr()   // IP:port локальной стороны
```

Сокет привязан к **tuple** `(protocol, src_ip, src_port, dst_ip, dst_port)`.
