## Механизм:
Consumer сам вытягивает (pull) данные из партиций, запрашивая партии messages с определённого offset.

## Преимущества (Throughput):
Такая модель позволяет эффективно использовать **batching** - передачу данных большими блоками, что обеспечивает **гораздо более высокую пропускную способность**. Consumer сам управляет темпом чтения, запрашивая данные только тогда, когда готов их обработать.

## Оптимизация:
Чтобы не тратить ресурсы на пустые запросы, когда новых messages нет, Kafka поддерживает механизм **long-polling** (ожидание появления данных перед ответом на запрос).

## Ограничение:
Дополнительная latency - между появлением message и его чтением проходит время polling интервала.
Consumer должен сам управлять offset и обрабатывать rebalancing.
