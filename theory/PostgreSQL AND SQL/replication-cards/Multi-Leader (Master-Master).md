Пишем в несколько мастеров. Нет даунтайма на запись при падении одного.

**Когда:** два датацентра с асинхронной репликацией внутри каждого, между ними master-master — быстрая запись + защита от падения целого DC.

**Главная проблема — конфликты:**
```
EU мастер: UPDATE users SET balance = 100 WHERE id = 1
US мастер: UPDATE users SET balance = 200 WHERE id = 1
```

**Разрешение конфликтов:**
- **LWW (Last Write Wins)** — по времени. Не всегда корректно: ретраи могут нарушить порядок
- **Ранг реплик** — выигрывает мастер с большим рангом
- **Решение на клиенте** — как мёрж в git, клиент сам определяет
- **CRDT (Conflict-free Replicated Data Types)** — типы данных без конфликтов. Простейший: дельта (+500 вместо SET 500). Дельту можно накладывать в любом порядке
