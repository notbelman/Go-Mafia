Описание архитектуры кодом (PlantUML), а не картинками в Miro. Версионируется в Git, ревьюится через PR.

## C4 — четыре уровня масштаба

Аналогия с картой: материки → страны → города → улицы.

**C1 — System Context:** системы целиком. "Есть система аналитики, система сообщений, система постов". Показывает, какие системы есть и как они связаны.

**C2 — Container:** внутри системы — сервисы, базы данных, очереди. "В системе постов есть Post Service, Feed Service, Kafka, PostgreSQL". Это основной уровень для system design.

**C3 — Component:** внутри сервиса — компоненты и их взаимодействие.

**C4 — Code:** архитектура классов. На практике редко рисуют.

На system design интервью и в проектах обычно достаточно C1 + C2.

## Зачем кодом, а не в Miro

**Версионирование:** архитектура лежит в Git. Видно, кто, когда и что изменил. История изменений.

**Ревью:** хочешь добавить микросервис — создай PR. Архитектор смотрит: "Нужно ли это здесь?" Code review для архитектуры.

**Актуализация:** Miro-доски забрасывают через неделю. Код в репозитории — часть проекта, обновляется вместе с ним.

## PlantUML — синтаксис

Три основных элемента: Person (пользователь), Container (сервис/БД), Rel (связь между ними). Всё остальное — вариации.

```
Person(user, "Пользователь")
Container(post_svc, "Post Service", "Go")
ContainerDb(postgres, "PostgreSQL", "Posts DB")
Rel(user, post_svc, "создаёт пост")
Rel(post_svc, postgres, "пишет/читает")
```

Рисуется в онлайн-редакторе (PlantUML Online Editor), ничего ставить не нужно.
