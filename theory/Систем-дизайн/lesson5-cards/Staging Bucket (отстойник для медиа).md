Промежуточное хранилище для загруженных файлов, которые ещё не привязаны к сущности.

## Проблема

Пользователь загрузил картинку котика в пост, начал писать текст... и передумал. Закрыл вкладку. Картинка уже в S3, а поста нет. Со временем накапливаются осиротевшие файлы — мусор, за который платим деньги.

Если загружать картинку вместе с постом (в одном запросе) — проблемы нет, но UX хуже: пользователь не видит превью, пока не отправит пост.

## Решение: двухэтапная загрузка

**Этап 1:** Пользователь грузит картинку → Media Service кладёт её в **staging bucket** (отстойник). Возвращает URL.

**Этап 2:** Пользователь создаёт пост → Post Service получает URL картинки → воркер перекладывает файл из staging bucket в **основной bucket**.

**Очистка:** воркер периодически проходит по staging bucket и удаляет всё, что старше N часов. Не нужно сканировать и искать осиротевшие файлы — просто дропаем пачкой (можно сегментировать по часам).

## Почему не TTL на S3

Не все реализации S3-совместимых хранилищ поддерживают TTL на объекты. Отстойник — универсальное решение: работает с любым storage.

## Альтернативы (упоминались, но не выбраны)

Удалять через Kafka-ивент ("пост создан → переложи картинку"), отслеживать через клиент ("пользователь закрыл форму → удали"). Отстойник проще и надёжнее.

## Где ещё встречается

Любая система с загрузкой медиа до привязки к сущности: мессенджеры (загрузил фото, не отправил), маркетплейсы (фото товара при создании), CMS.
