Две стратегии построения ленты (feed). Когда формировать ленту — при записи поста или при чтении?

## Fan-out on Write (push-модель)

Пользователь написал пост → **сразу** обновляем ленты всех его друзей/подписчиков. При чтении лента уже готова — просто достаём из кэша.

**Как работает:** Post Service → Kafka (transaction outbox) → Feed Service → идёт в Relation Service ("с кем дружит автор?") → обновляет home feed каждого друга в in-memory хранилище (Tarantool/Redis).

**Структура кэша:** дека (deque). Новый пост — добавляем в начало, старый — выкидываем с конца. Инвалидация простая.

**Плюс:** чтение мгновенное — лента готова заранее. Идеально для read-intensive систем.

**Минус:** одна запись порождает N операций записи (по числу друзей). Для обычных пользователей — ок. Для звёзд с миллионом подписчиков — катастрофа.

## Fan-out on Read (pull-модель)

Пользователь открывает ленту → **в момент чтения** собираем посты от всех друзей, сортируем, отдаём.

**Плюс:** запись дешёвая — просто сохранили пост и всё.

**Минус:** чтение медленное — нужно обойти посты всех друзей, отсортировать. Для read-intensive системы — плохо.

## На практике — гибрид

Обычные пользователи → fan-out on write (пушим в ленты друзей).
Звёзды → fan-out on read (подмёрживаем при чтении).
