## Round Robin

**Суть:** Запросы распределяются по кругу. Первый → инстанс 1, второй → инстанс 2, третий → инстанс 3, четвёртый → снова инстанс 1.

**Аналогия:** Менеджер раздаёт задачи трём программистам по очереди: Васе, Пете, Коле, снова Васе... Не знает, насколько задачи сложные — просто раздаёт по кругу.

**Покрывает 80–90% задач балансировки.**

## Weighted Round Robin

**Суть:** То же самое, но инстансам назначается вес. Более мощный сервер получает больше запросов.

**Аналогия:** Вася — сеньор, ему даём 3 задачи за круг. Пете и Коле — по одной.

**Когда нужен:** серверы разных технических характеристик (разные CPU, RAM). На практике редко — обычно берут однотипные узлы.

**Пример в Nginx:**
```
upstream backend {
    server 192.168.1.1 weight=5;
    server 192.168.1.2 weight=1;
    server 192.168.1.3 weight=1;
}
```

**Связь:**
- самый популярный алгоритм балансировки
- не учитывает реальную нагрузку на инстансы (в отличие от least connections)
