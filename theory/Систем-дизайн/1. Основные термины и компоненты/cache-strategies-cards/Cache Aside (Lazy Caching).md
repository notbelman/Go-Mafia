**Суть:** Приложение само координирует кэш и БД. Кэш ничего не знает про БД, БД ничего не знает про кэш. Вся логика — в коде приложения.

## Чтение

1. Приложение идёт в кэш
2. Hit → возвращает данные
3. Miss → идёт в БД → получает данные → кладёт в кэш → возвращает

## Запись

1. Приложение пишет в БД
2. БД подтверждает
3. Приложение кладёт новое значение в кэш (или не кладёт — зависит от требований к консистентности)

**Почему "lazy":** данные попадают в кэш только когда их кто-то запросил. Никто не запрашивал → в кэше нет.

**Плюсы:**
- простая реализация — логика в коде приложения
- кэш упал → сервис работает, просто медленнее (ходит в БД напрямую)
- самая распространённая стратегия

**Минусы:**
- первый запрос всегда miss (cold start)
- приложение усложняется логикой "проверь кэш → сходи в БД → положи в кэш"

**Связь:**
- самая популярная стратегия — подходит для большинства задач
- кэш не является критической зависимостью (в отличие от cache through)
- прогрев кэша → при старте всё пусто, первые запросы медленные
- [[Read,Write ratio (соотношение чтения и записи)]] - read heavy
