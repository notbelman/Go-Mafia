- **Версионирование** — смена версии ключа (`v1:product:123` → `v2:product:123`). Старые записи вытесняются сами по TTL. Массовая инвалидация за одну операцию (смена конфига)
- **Тегированный кэш** — группам записей назначаются теги. `invalidate_tag("weather")` → все записи с тегом удаляются. Точечная инвалидация по группам
- Версионирование — **массовая** инвалидация (весь кэш). Теги — **точечная** (конкретные группы)
- Минус версионирования: после смены версии — **cold start**, все запросы в БД. Нужно быть готовым к всплеску
- Теги решают проблему **согласованности**: новость "курс доллара рухнул" → инвалидируем теги `weather` + `currency` → обе группы обновляются

## Сравнение

| | Версионирование | Теги |
|---|---|---|
| Масштаб | Весь кэш разом | Конкретные группы |
| Операция | Смена конфига (версии) | `invalidate_tag()` |
| Cold start | Да, весь кэш пуст | Только затронутые группы |
| Кейс | Глобальное обновление | Согласованность связанных данных |

## Версионирование кэша

Инвалидация через смену версии ключа. Старые записи вытесняются сами.

### Проблема
Браузер закэшировал иконку (`icon.png`). На бэкенде появилась новая. Как заставить браузер забрать свежую?

### Решение — смена имени
`icon.png` → `icon-v2.png` или `icon-a8f3c2.png` (хэш содержимого). Браузер видит — такой картинки в кэше нет → идёт за новой.

Именно поэтому на сайтах в URL картинок и скриптов часто видно хэши или версии.

### Применение к серверному кэшу
Товары в Redis с префиксом `v1:product:123`. Нужно инвалидировать все товары? Переключаем версию на `v2`:

1. Сервис идёт за `v2:product:123` — такого нет → идёт в БД
2. Кладёт в кэш с новым префиксом
3. Старые `v1:*` записи вытесняются по TTL или [[Алгоритмы вытеснения — основные|eviction policy]]

### Плюсы
- массовая инвалидация за одну операцию (смена конфига)
- не нужно перебирать и удалять записи

### Минусы
- после смены версии — **cold start**, все запросы мимо кэша в БД
- нужно быть готовым к всплеску нагрузки

## Тегированный кэш

Привязка тегов к группам записей. Инвалидация по тегу — все связанные записи обновляются разом.

### Проблема
Mail.ru: на главной — новости, погода, курс валют. Всё закэшировано в разных спейсах. Приходит новость "курс доллара рухнул до 30₽", а в виджете справа доллар = 75₽. Пользователь видит противоречие.

### Решение
Каждой группе данных назначается тег: новости → `news`, погода → `weather`, валюта → `currency`.

Новость "в Москве из-за глобального потепления рухнул курс доллара" → два тега: `weather` + `currency` → инвалидируем обе группы одновременно.

### Как работает
1. При записи указываем теги: `set("weather:moscow", data, tags=["weather"])`
2. При инвалидации: `invalidate_tag("weather")` → все записи с тегом удаляются
3. Следующий запрос → cache miss → поход в БД → свежие данные

### Когда использовать
- несколько групп данных на одной странице, которые должны быть согласованы
- событие затрагивает несколько категорий одновременно
- нужна точечная инвалидация: не весь кэш, а конкретные группы
