## 1. Транзакции
Нужны транзакции → реляционка. Деньги = всегда транзакции.

## 2. Формат данных
Временные события → time series. Отношения/графы → графовая. Сырые файлы → blob storage. Документы без связей → документная.

## 3. Навык работы с технологией
Нет опыта с графовой БД, а время поджимает → реляционка закроет задачу. Можно выбрать менее идеальное решение, но знакомое.

## 4. Характер обращения к данным
Много маленьких запросов (найти, обновить) → реляционка. Поднять миллионы строк по паре колонок → колоночная. Ключ-значение → key-value.

## 5. Сообщество и зрелость
Непонятная БД от Васи → риск. Популярное решение с экспертизой → быстрее решишь проблемы.

## 6. Частота изменяемости формата данных
Бизнес постоянно меняет структуру → документная (нет миграций). Стабильный формат → реляционка.

## Не обязательно одна БД
Посты → реляционка. Аналитика → ClickHouse. Полнотекстовый поиск → Elasticsearch. Кэш популярных постов → Redis/Tarantool. Данные дублируются, но нагрузка размазывается по тем БД, которые лучше подходят.

**Но:** не городить звездолёт для маленького проекта. Две таблицы — хватит одной реляционки.
