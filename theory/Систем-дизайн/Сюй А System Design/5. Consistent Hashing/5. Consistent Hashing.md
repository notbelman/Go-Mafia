- **Проблема:** `hash(key) % N` — при добавлении/удалении сервера **почти все ключи** перераспределяются. Лавина кэш-промахов
- **Согласованное хеширование** — при изменении числа серверов перераспределяется только **K/n ключей** (K = всего ключей, n = слотов). Кольцо от 0 до 2^160
- **Кольцо:** серверы и ключи хешируются на кольцо. Ключ принадлежит **ближайшему серверу по часовой стрелке**. Добавление сервера → переезжает только часть ключей между ним и предыдущим
- **Две проблемы базового подхода:** неравномерные отрезки (один сервер получает гораздо больше) + неравномерное распределение ключей
- **Virtual Nodes** — один сервер = 100–200 точек на кольце (s0_0, s0_1, s0_2...). Чем больше virtual nodes → равномернее распределение (отклонение 5% при 200 узлах)
- **Компромисс:** больше virtual nodes = равномернее, но больше памяти для хранения маппинга
- Используется: **Amazon Dynamo**, **Cassandra**, **Discord**, **Akamai CDN**, **Google Maglev** (сетевой LB)
- Преимущества: минимум перераспределения, горизонтальное масштабирование, борьба с hot keys

## Две проблемы базового подхода

### Проблема 1: неравномерные отрезки

![[5.10.png]]
При удалении сервера один из соседей получает **вдвое больший отрезок** → неравномерная нагрузка.

### Проблема 2: неравномерное распределение ключей

![[5.11.png]]
Серверы оказались рядом → один сервер обслуживает почти все ключи, остальные пустуют.

## Virtual Nodes — решение

![[5.12.png]]
Каждый сервер представлен на кольце **несколькими виртуальными узлами**:
- Сервер 0 → s0_0, s0_1, s0_2
- Сервер 1 → s1_0, s1_1, s1_2

Каждый сервер отвечает за **несколько отрезков** → нагрузка распределяется равномернее.

### Поиск с виртуальными узлами

![[5.13.png]]

От позиции ключа по часовой → ближайший **виртуальный** узел → он ссылается на реальный сервер.

### Сколько виртуальных узлов

| Virtual Nodes | Стандартное отклонение |
|---|---|
| 100 | ~10% |
| 200 | ~5% |

**Больше узлов** → равномернее, но **больше памяти** для хранения маппинга. Подбирается под требования системы.

## Поиск затронутых ключей

### При добавлении

![[5.14.png]]
От нового сервера **против часовой** до ближайшего сервера → ключи в этом диапазоне переносятся на новый.

### При удалении

![[5.15.png]]
От удалённого сервера **против часовой** до ближайшего → ключи переносятся на **следующий** сервер по часовой.

## Итоги — преимущества

| Преимущество | Описание |
|---|---|
| **Минимум перераспределения** | При добавлении/удалении → переезжает только K/n ключей |
| **Горизонтальное масштабирование** | Данные равномерно распределены |
| **Борьба с hot keys** | Равномерное распределение → нет перегрузки одного сервера |
