- **Web Crawler (поисковый робот)** — собирает веб-страницы для индексации (Googlebot), архивации, извлечения данных, мониторинга. Начинает с seed URL, проходит по ссылкам рекурсивно
- **1 млрд страниц/месяц**, QPS ~400, пиковый ~800. Средняя страница 500 КБ → **500 ТБ/мес**, **30 ПБ за 5 лет** хранения
- **BFS**, не DFS (граф может быть бесконечно глубоким). Но обычный BFS: невежливый (DDoS одного домена) + не учитывает приоритет
- **Граница сканирования** (URL Frontier): лицевые очереди (приоритеты по PageRank/частоте обновления) + тыльные очереди (вежливость — один домен = одна очередь = один поток)
- **Вежливость:** один рабочий поток = один домен. Задержка между запросами. robots.txt — кэшируем, соблюдаем правила
- **Дедупликация:** контента (хеши страниц, 29% интернета — дубли) + URL (фильтр Блума / хеш-таблица, чтобы не ходить повторно)
- **Устойчивость:** consistent hashing для распределения, сохранение состояния на диск, обработка исключений, таймауты
- **Расширяемость:** подключаемые модули (загрузчик PNG, веб-мониторинг). Ловушки: бесконечные URL → max длина URL + чёрные списки

## Функциональные требования

1. Начинать с набора **seed URL** (исходных адресов)
2. Загружать HTML-страницы по URL
3. Извлекать ссылки из HTML, добавлять в очередь
4. Повторять рекурсивно

## Нефункциональные требования

- **Масштабируемость** — миллиарды страниц, параллельные вычисления
- **Устойчивость** — некорректный HTML, неотзывчивые серверы, вредоносные ссылки
- **Вежливость** — не DDoS-ить сайты, соблюдать robots.txt
- **Расширяемость** — новые типы контента без переработки всей системы

## Расчёт нагрузки

```
1 млрд страниц / месяц
QPS: 1 000 000 000 / 30 / 24 / 3600 ≈ 400 стр/сек
Пиковый QPS: 400 × 2 = 800

Средняя страница: 500 КБ
Хранилище/мес: 1 млрд × 500 КБ = 500 ТБ
За 5 лет: 500 ТБ × 12 × 5 = 30 ПБ
```

## Архитектура — компоненты
![[9.2.png]]

### 1. Исходные URL (Seed URLs)
Отправная точка обхода. Стратегии: по **географии** (популярные сайты в каждой стране), по **тематике** (покупки, спорт, медицина).

### 2. Граница сканирования (URL Frontier)
Очередь URL для загрузки. **Ключевой компонент** — обеспечивает вежливость и приоритеты. Подробнее ниже.

### 3. Загрузчик HTML
Загружает страницы по HTTP. IP-адрес получает через DNS. Оптимизации:
- Распределённый поиск (серверы по регионам)
- Кэширующий DNS (DNS-запросы = узкое место, 10–200 мс)
- Локальность (серверы ближе к целевым сайтам)
- Таймауты (не ждать медленные серверы)

### 4. Распознаватель DNS
Переводит URL → IP-адрес. **Узкое место** — DNS синхронный и медленный. Решение: **DNS-кэш** (доменное имя → IP), обновляется по cron.

### 5. Анализатор контента
Проверяет корректность HTML. Отдельный компонент (не на сервере робота — замедлит).

### 6. Дедупликация контента ("Существующий контент?")
29% интернета — дубли. Сравниваем **хеши** страниц, не сами страницы. Дубль → отклоняем.

### 7. Хранилище контента
Диск для основного объёма + память для востребованного контента (hot/cold).

### 8. Средство извлечения ссылок
Парсит HTML → извлекает ссылки. Относительные пути → абсолютные URL.

### 9. Фильтр URL
Отклоняет: определённые расширения файлов, страницы с ошибками, чёрный список.

### 10. Дедупликация URL ("Существующий URL?")
Проверяет, был ли URL уже посещён или в очереди. **Фильтр Блума** или хеш-таблица. Уже был → не добавляем в очередь.

### 11. Хранилище URL
Хранит все посещённые URL.

## Флоу работы (11 шагов)

![[9.4.png]]

1. Добавляем seed URL в границу сканирования
2. Загрузчик HTML берёт URL из границы
3. Загрузчик получает IP от DNS → загружает страницу
4. Анализатор контента проверяет HTML
5. Контент передаётся на проверку дублей
6. **Дубль?** Да → отклоняем. Нет → передаём средству извлечения ссылок
7. Из HTML извлекаются ссылки
8. Ссылки → фильтр URL
9. Отфильтрованные → проверка "Существующий URL?"
10. **Уже был?** Да → ничего не делаем
11. **Новый URL** → добавляем в границу сканирования → цикл повторяется

## Граница сканирования — подробно

Два модуля: **лицевые очереди** (приоритеты) + **тыльные очереди** (вежливость).
![[9.8.png]]

### Лицевые очереди — приоритеты

![[9.7.png]]

- **Средство расстановки приоритетов** — вычисляет приоритет URL (PageRank, популярность, частота обновления)
- **Очереди f1–fn** — каждой назначен приоритет. Выше приоритет → чаще выбирается
- **Селектор очередей** — выбирает очередь, отдавая предпочтение приоритетным

### Тыльные очереди — вежливость

![[9.6.png]]

- **Маршрутизатор очередей** — распределяет URL по очередям так, чтобы **один домен = одна очередь**
- **Таблица связывания** — маппинг домен → очередь (wikipedia.com → b1, apple.com → b2)
- **Очереди b1–bn** — каждая содержит URL **только одного домена**
- **Селектор очередей** — привязывает каждый рабочий поток к одной очереди
- **Рабочие потоки 1–N** — каждый загружает **последовательно** из одного домена. Между загрузками — **задержка**

### Хранилище границы сканирования
Сотни миллионов URL. В памяти — нельзя (не хватит). На диске — медленно. **Гибрид:** основное на диске + буфер в памяти для добавления/удаления. Буфер периодически сбрасывается на диск.

### Актуальность
Страницы обновляются → нужно перепроходить. Стратегии:
- Учитывать **историю обновлений** (часто обновляется → чаще посещаем)
- Назначать **приоритеты** (важные страницы — в первую очередь)

## Загрузчик HTML — robots.txt

```
# Пример robots.txt с amazon.com
User-agent: Googlebot
Disallow: /creatorhub/*
Disallow: /rss/people/*/reviews
Disallow: /gp/cdp/member-reviews/
```

- Перед обходом сайта — **проверить robots.txt**
- **Кэшируем** robots.txt (не загружать каждый раз)
- Периодически обновляем кэш

## Оптимизация производительности

| Оптимизация | Описание |
|---|---|
| **Распределённый поиск** | Несколько серверов, каждый за своё подмножество URL |
| **DNS-кэш** | Кэширование домен→IP, обновление по cron. DNS = узкое место (10–200 мс) |
| **Локальность** | Серверы ближе к целевым сайтам → ниже латентность |
| **Таймауты** | Не ждать медленные серверы, перейти к следующей странице |

## Устойчивость

- **Consistent hashing** — распределение нагрузки между загрузчиками, добавление/удаление серверов
- **Сохранение состояния** — на диск, чтобы после сбоя перезапустить с того же места
- **Обработка исключений** — ошибки неизбежны, робот не должен падать
- **Проверка корректности данных** — предотвращение системных ошибок
