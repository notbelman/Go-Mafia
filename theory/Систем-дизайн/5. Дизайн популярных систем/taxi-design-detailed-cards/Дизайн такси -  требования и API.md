- Real-time система (ASR) -- не read/write-intensive, а постоянный поток обновлений координат
- DAU: 100M пассажиров + 5M водителей, availability 99.95%, eventual consistency
- Два API Gateway (passenger / driver) за общим Load Balancer -- разные приложения, разные права
- WebSocket для событий ("водитель найден", "подъехал", "в пути", "новый заказ")
- updatePosition каждые 5 сек, response time на заказ: 1 минута

---

Первый этап — зафиксировать требования. Система с двумя типами пользователей.

## Функциональные требования

- Заказ такси пользователем
- Начало и конец работы водителя (смена)
- Подбор ближайшего водителя для поездки
- Подтверждение / отклонение заказа водителем
- Наблюдение за поездкой (где машина)
- История поездок

## Нефункциональные требования

- DAU 100 млн (пассажиры), 5 млн (водители)
- Availability 99.95%
- Eventual consistency — не нужно в каждый момент видеть точную позицию, задержка ок
- Один заказ в день на пользователя
- Продолжительность поездки 30 минут
- Каждый водитель обрабатывает 20 заказов в день
- Response time на заказ такси: **1 минута**
- Геораспределённости нет, сезонности нет

## ASR (ключевое требование)

Это **не** read-intensive и не write-intensive. Это **real-time система**. 5 млн водителей обновляют координаты каждые 5 секунд — постоянный поток данных. Вся архитектура строится вокруг этого потока. Балун: "Я сразу выделил, что мне нужно очень много обновлять координат. Вот это очень важно."

## Два типа клиентов

Пассажир и водитель — разные приложения, разные права, разный API. Поэтому **два API Gateway**. Общий Load Balancer роутит трафик в нужный gateway.

```
Passenger → LB → API Gateway (passenger)
Driver    → LB → API Gateway (driver)
```

## API пассажира

```
createOrder(from, to)    — заказать такси
getOrdersList(user)      — история заказов
+ WebSocket канал        — события: "водитель найден", "подъехал", "в пути"
```

## API водителя

```
activateJob()            — начать смену
deactivateJob()          — закончить смену
applyOrder()             — подтвердить заказ
cancelOrder()            — отклонить заказ
updatePosition(position) — обновить координаты (each 5 seconds)
+ WebSocket канал        — события: "новый заказ", предложение поездки
```
