- DAU 50M, 1 пост в 5 дней → 115 RPS write
- Чтение 10 раз в день → 5787 RPS read
- Трафик ~1.2 МБ/с write
- Storage ~37 ТБ/год
- 2 ТБ in-memory для кэша лент

---

Прикидываем RPS и трафик до того, как проектировать компоненты. Нужно понимать масштаб.
## RPS на запись (посты)

```
RPS (write) = 50.000.000 / 5 / 86400 = 115
```

50M DAU, один пост в 5 дней, 86400 секунд в дне. **115 RPS — копейки.** Один инстанс PostgreSQL справится без проблем.

## RPS на чтение (ленты)

```
RPS (read) = 50.000.000 × 10 / 86400 = 5787
```

50M DAU, 10 просмотров ленты в день. **5787 RPS — уже значительно.** Один инстанс рискованно, нужно думать про кэширование / репликацию.

## Трафик

Максимум 2000 символов × 2 байта (UTF-8 кириллица) = 4000 байт. Плюс URL картинки (~200 байт), плюс id/created/user_id. Округляем до **4 КБ на пост**.

```
Traffic (write) = 115 × 4 КБ = 460 КБ/с     — копейки
Traffic (read)  = 5787 × 4 КБ = 23 МБ/с      — тоже копейки
```

23 МБ/с — один HDD (100+ МБ/с) справится с пропускной способностью. Но это **оптимистичный** прогноз — чистый поток данных. Реальные запросы будут сканировать индексы, джойнить таблицы, это дороже.

## RPS лайков
Как считали: пользователь читает ленту, видит 10 постов, лайкает ~5 из них.

```
RPS (likes) = RPS (read) × 5 = 5787 × 5 ≈ 25.000
```

Можно считать по-другому: 50M DAU × 10 просмотров × 5 лайков / 86400. Результат тот же (коммутативность). **25.000 RPS на запись — уже серьёзно.** Это не копейки, это близко к KV-нагрузке.

## RPS комментов

Комменты пишут редко. По аналогии с постами — примерно раз в 5 дней пользователь напишет коммент.

```
RPS (comments) = 50.000.000 / 5 / 86400 = 115
```

**115 RPS — копейки**, как и создание постов.

## Что следует из расчётов

1. **Запись постов (115 RPS)** — одного PostgreSQL хватит
2. **Чтение лент (5787 RPS)** — нужно оптимизировать (кэш, pre-built feeds)
3. **Лайки (25K RPS)** — отдельная подсистема, отдельный сервис, отдельная база
4. **Трафик** — не узкое место, HDD справится
5. Подтверждаем ASR: система read-intensive, читаем в 50 раз больше, чем пишем

## Важная оговорка

Это усреднённые, коленочные расчёты. Пиковые RPS могут быть в 2-5 раз выше. Точные цифры — только под реальную нагрузку. Но порядок величин мы поняли.
