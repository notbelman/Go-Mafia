Запись постов и загрузка медиа. Простая часть системы — начинаем с неё.
## Базовая входная точка

```
Client → Load Balancer → API Gateway → сервисы
```

**Load Balancer:** Nginx (асинхронный веб-сервер). Несколько инстансов за DNS.

**API Gateway:** авторизация, аутентификация, rate limiting. Типичный паттерн — подходит для большинства систем. **Важно:** не превращать gateway в монолит. Если поселить туда много бизнес-логики — потом придётся распиливать.

## Post Service + PostgreSQL
```
post:
  id
  created_at
  user_id
  text
  url          ← URL картинки в S3, не сама картинка
```

**Почему PostgreSQL (реляционка), а не NoSQL?** Пост — независимая сущность, но у постов потом появляются связи: хэштеги, категории (IT, природа), отношения. Реляционная модель хорошо ложится на такие данные. При 115 RPS на запись — PostgreSQL справится без проблем, незачем усложнять.

**Картинка хранится не в PostgreSQL.** В таблице только URL. Физически файл лежит в S3. Это стандартный подход — БД хранит метаданные, blob storage хранит файлы.

## Media Service + S3

**Почему отдельный сервис для медиа?** Сейчас грузим только картинки к постам. Потом появятся: аватарки, звуки, видео, картинки для сообщений. Media Service — абстракция, которая занимается всем хранением медиа. Отдельная команда может его развивать.

## Двухэтапная загрузка

**Этап 1:** пользователь грузит картинку → `uploadMedia(media)` → Media Service кладёт в S3 → возвращает URL на фронт.

**Этап 2:** пользователь написал текст, нажал "отправить" → `createPost(post)` → Post Service сохраняет пост с URL картинки в PostgreSQL.

Так работают реальные соцсети (ВК, Twitter): пока картинка грузится, можно писать текст.

## Проблема: загрузил картинку, не создал пост

Пользователь загрузил котика, начал писать... и передумал. Картинка в S3, а поста нет. Решение — **staging bucket (отстойник):**

1. Картинка грузится в отдельный бакет-отстойник
2. Воркер раз в несколько часов дропает всё из отстойника пачкой (можно сегментировать по часам — не нужно сканить и искать)
3. При создании поста воркер перекладывает картинку из отстойника в основной бакет

**Почему не TTL на S3:** не все реализации S3 поддерживают TTL. Отстойник — универсальное решение.

**Почему не Kafka-ивент:** можно, но отстойник проще — не нужно городить подписки и обработчики.
