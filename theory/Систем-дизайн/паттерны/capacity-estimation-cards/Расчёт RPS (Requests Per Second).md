Сколько запросов в секунду будет получать система.

## Формула

```
RPS = DAU × действий_на_пользователя_в_день / 86400
```

## Пример: WhatsApp (чтение)

- DAU = 100.000.000 (100 млн)
- Пользователь читает сообщения 10 раз в день
- RPS read = 100.000.000 × 10 / 86400 ≈ **11.574 RPS**

## RPS на запись

Если соотношение read/write = 5:1 (читают в 5 раз чаще, чем пишут):

```
RPS write = RPS read / 5 ≈ 2.315 RPS
```

Или считаем напрямую: пользователь пишет 2 сообщения в день → 100M × 2 / 86400 ≈ 2.315 RPS.

## Откуда брать входные данные

**DAU** — спрашиваем у бизнеса. Не знает — предлагаем целевую цифру для MVP.

**Действий на пользователя** — спрашиваем или прикидываем из пользовательского опыта. «Сколько в среднем сообщений в день отправляет/читает пользователь?»

**Read/write ratio** — характер нагрузки. Мессенджер: читают больше, чем пишут. Аналитика: пишут больше, чем читают.

## Нюансы

RPS — усреднённый. Пиковый RPS может быть в 2-5 раз выше (все активны вечером, никого ночью). На интервью можно упомянуть пики, но считать по среднему — ок.

Разные операции — разный RPS. Чтение сообщений, отправка, просмотр чатов, статусы — у каждого свой RPS. Считаем для core-операций.
