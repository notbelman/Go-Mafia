**Суть:** Индекс, в который специально добавлены дополнительные данные, чтобы запрос мог полностью обслужиться из индекса — без похода на диск к основным данным.

**Пример:**
Запрос: `SELECT name FROM users WHERE id = 1 AND date = '2024-01-01'`

Обычный индекс по (id, date) → нашли запись в индексе → пошли на диск за name.

Покрывающий индекс по (id, date, name) → нашли запись в индексе → name уже тут. На диск ходить не нужно.

**Зачем:** избавиться от чтения с диска. Индекс часто в RAM — ответ мгновенный.

**Минус:** индекс занимает больше памяти, потому что хранит лишние данные. Запись медленнее — при каждом INSERT/UPDATE нужно обновлять больше данных в индексе.

**Когда использовать:** горячий запрос, который выполняется тысячи раз в секунду. Добавить пару полей в индекс = убрать поход на диск = огромный выигрыш.
