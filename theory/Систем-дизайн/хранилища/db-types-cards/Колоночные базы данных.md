**Суть:** Данные хранятся **по колонкам**, а не по строкам. Каждая колонка — отдельный файл.

**Зачем:** Аналитик хочет посчитать среднее по двум полям из таблицы с 50 колонками. В реляционке придётся вычитать все 50 колонок каждой строки с диска. В колоночной — только 2 нужные колонки. Меньше данных с диска = быстрее.

**Почему быстрее:** У диска есть пропускная способность. Чем меньше данных нужно поднять — тем быстрее результат.

**Сжатие:** Однотипные данные в одной колонке отлично жмутся. ClickHouse сжимает данные из коробки.

**НЕ про транзакции:** Колоночные БД — не для "найти одну строку и обновить". Это для "поднять миллион строк по двум колонкам и агрегировать".

**Примеры:** ClickHouse, Apache Cassandra, Vertica.

**Связь:**
- [[HTAP|OLAP]] — колоночные БД заточены под аналитическую нагрузку
- [[Разреженный индекс (Sparse Index)]] — ClickHouse использует разреженные индексы (засечки на каждую N-ю запись)
- [[Throughput (пропускная способность)]] — выигрыш за счёт меньшего чтения с диска
