- **RPS:** бронирование ~11 RPS (копейки), просмотр ~3472 RPS — нагрузка невысокая
- **Data model:** hotel, room_type (категории комнат с count), available_room_type (доступность по дням)
- **room_type вместо room:** отели работают по категориям (стандарт/люкс), не по отдельным номерам
- **Доступность по дням, не интервалам:** проще декремент/инкремент, без сложных пересечений
- **БД:** PostgreSQL — транзакции, strong consistency, деньги

---

RPS копеечный. Модель данных — самое важное: типы комнат, доступность, интервалы дат.

## Расчёт нагрузки

```
RPS (бронирование) = 30.000.000 / 30 / 86400 ≈ 11 RPS  — копейки
RPS (просмотр)     = 30.000.000 × 10 / 86400 ≈ 3472 RPS — терпимо
```

**11 RPS на бронирование — копейки.** Можно ли сделать монолит? Можно. Но Балун: "Монолит — не про рост, не про скейл. Давайте разберём вариант с микросервисами, чтобы рассмотреть распределённые транзакции."

## Hotel Service + PostgreSQL

Хранит отели, типы комнат, доступность.

### Таблица hotel

```
hotel:
  id
  name
  description
  latitude
  longitude
  ... (адрес и прочая метаинфа)
```

### Таблица room_type (не room!)

**Критически важно:** в отелях нет отдельных записей на каждую комнату. Есть **категории**: стандарт (50 комнат), VIP (30 комнат), президентский люкс (2 комнаты).

```
room_type:
  id
  hotel_id
  name           — "Стандарт", "Люкс"
  description    — параметры (утюг, кондиционер...)
  count          — сколько таких комнат всего
  price          — цена за ночь
```

**count** — общее количество комнат этого типа. Админ инкрементирует (новая комната) или декрементирует (ремонт, затопило).

### Таблица available_room_type (доступность)

Сколько свободных комнат **на каждый день.**

```
available_room_type:
  hotel_id
  room_type_id
  date           — конкретный день (не интервал!)
  count          — сколько свободно в этот день
```

**Почему день, а не интервал (start_date, end_date)?**

С интервалами — сложно. Пример: бронирую пн–ср. В понедельник свободно 2, во вторник 1, в среду 2. Нужно найти **минимум** на интервале (1) и показать его. Пересечения интервалов, поиск минимума — много кода.

Ещё проблема: в понедельник живёшь в одной комнате, во вторник она забронирована другим → переезжаешь. Или отель держит её для тебя, но тогда показывает меньше свободных.

С днями — проще: на каждый день отдельная запись, просто декремент/инкремент.
