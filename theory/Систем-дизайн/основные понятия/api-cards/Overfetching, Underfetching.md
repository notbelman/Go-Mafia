## Overfetching

**Суть:** API отдаёт больше данных, чем нужно клиенту.

**Пример:** Мобильному приложению нужно только имя пользователя. GET /users/5 возвращает имя, email, адрес, историю заказов, аватарку в base64... Мобилка тратит трафик и память на ненужные данные.

## Underfetching

**Суть:** API не додаёт данные — клиенту приходится делать дополнительные запросы.

**Пример:** Нужно показать пост + автора + комментарии. API отдаёт пост, но автора и комментарии — отдельными запросами. Три запроса вместо одного.

## Почему это проблема

Один API переиспользуется для разных платформ:
- Desktop — мощный, хорошая сеть → overfetching терпимо
- Mobile — слабый процессор, дорогой трафик → overfetching больно
- TV — вообще другие потребности

Один endpoint не может угодить всем.

## Решения

- **GraphQL** — клиент сам выбирает поля, нет overfetching по определению
- **BFF (Backend for Frontend)** — отдельный API для каждой платформы
- **Разные endpoints** — /users/5/short, /users/5/full
- **Параметр fields** — GET /users/5?fields=name,email
