**Суть:** При проектировании системы важно понять — будут больше читать или больше писать. От этого напрямую зависит архитектура.

## Read heavy (больше чтения)

**Пример:** соцсети — посты пишут редко, читают постоянно.

**Что это значит для архитектуры:**
- кэширование эффективно (высокий [[Cache Hit, Cache Miss, Hit Rate|hit rate]])
- реплики на чтение
- CDN для статики

## Write heavy (больше записи)

**Пример:** система логов — пишут постоянно, читают редко (только при дебаге).

**Что это значит для архитектуры:**
- оптимизация записи (батчинг, последовательная запись)
- append-only структуры
- кэширование менее эффективно (данные быстро устаревают)

**Зачем знать на интервью:** это один из первых вопросов при проектировании. "Какой характер нагрузки?" → от ответа зависит выбор БД, стратегия кэширования, способ хранения.

**Связь:**
- read heavy → кэширование ([[Cache Aside (Lazy Caching)]], [[Cache Through (сквозное кэширование)]])
- write heavy → [[High throughput приложения]] подходы (батчинг, очереди)
- влияет на выбор алгоритма вытеснения из кэша
