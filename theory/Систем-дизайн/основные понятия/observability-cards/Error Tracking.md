**Суть:** Централизованный сбор ошибок и крашей со всех сервисов в одном месте.

**Как работает:**
1. В приложении происходит exception / panic
2. SDK автоматически отправляет stack trace + контекст в систему error tracking
3. В UI — список ошибок, группировка, частота, первое/последнее появление

**Отличие от логирования:**
- Логирование — поток всех событий (info, warning, error)
- Error tracking — только ошибки, но с полным контекстом (stack trace, переменные, user ID, версия)

**Что отправляется:**
- Stack trace
- Контекст запроса (URL, параметры, headers)
- Информация о пользователе
- Версия приложения
- Окружение (prod, staging)

**Пример:** Sentry — самый популярный инструмент. Подключил SDK → ошибки автоматически летят в Sentry → алерт в Slack.

**Зачем:** быстро узнать о новых ошибках после релиза, понять масштаб проблемы (сколько пользователей затронуто), видеть stack trace без SSH на сервер.
