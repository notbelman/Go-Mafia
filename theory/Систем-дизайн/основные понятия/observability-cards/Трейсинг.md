**Суть:** Отслеживание пути одного запроса через все сервисы в распределённой системе.

**Зачем:** Запрос прошёл через 20 микросервисов. Где-то сломалось. Логи на каждом сервисе отдельно — искать вручную нереально. Трейсинг собирает всю цепочку в одну картинку.

**Ключевые понятия:**
- **Trace** — граф всех операций одного запроса (от входа до ответа клиенту)
- **Span** — одна операция внутри trace (вызов сервиса, запрос в БД, обращение в кэш)
- **Trace ID** — уникальный идентификатор, который пробрасывается через все сервисы

**Как работает:**
1. На входе генерируется trace ID
2. Каждый сервис создаёт span с этим trace ID
3. Span содержит: имя операции, время начала/конца, статус, метаданные
4. Всё собирается в систему трейсинга (Jaeger, Zipkin)
5. В UI видим граф: какой сервис вызвал какой, сколько времени заняло

**Что даёт:**
- найти, где именно ошибка или тормоз
- граф зависимостей сервисов (кто кого вызывает)
- понять полный response time и из чего он складывается

**Проброс контекста:** trace ID передаётся в headers (часто автоматически через middleware/SDK).
