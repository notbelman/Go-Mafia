- **Polling** — клиент каждые N секунд спрашивает сервер «есть что-то новое?». Простейшая реализация, stateless, но холостые запросы нагружают сервер
- **Long Polling** — клиент шлёт запрос, сервер держит соединение до появления данных или таймаута (10-30 сек). Меньше холостых запросов, чем polling
- **WebSocket** — постоянное двустороннее соединение (HTTP upgrade -> ws://). Сервер сам пушит данные клиенту в любой момент. Мгновенная доставка
- Polling подходит при предсказуемой периодичности (курс акций), WebSocket — при непредсказуемой высокой частоте (мессенджер, онлайн-игры)
- Long Polling — компромисс: Балун: «Когда работал в ICQ, у нас был long polling. Не было стриминга — был long polling»
- WebSocket сложнее инфраструктурно: sticky sessions, reconnect при обрывах, stateful-сервер
- Чем выше требования к real-time — тем сложнее инфраструктура и дороже поддержка

| Подход | Периодичность | Задержка | Сложность |
|---|---|---|---|
| Polling | Предсказуемая | До интервала | Простая |
| Long Polling | Непредсказуемая, низкая частота | Минимальная | Средняя |
| WebSocket | Непредсказуемая, высокая частота | Мгновенная | Высокая |

## Polling (опрос)

Клиент периодически спрашивает сервер: «есть что-то новое?» Каждые N секунд — новый запрос.

Клиент каждые 3 секунды шлёт запрос: «какая сейчас цена Яндекса?» Сервер отвечает сразу — есть данные или нет. Клиент ждёт 3 секунды, снова спрашивает.

### Когда подходит Polling

Данные обновляются с **предсказуемой периодичностью**. Курс акций обновляется каждые N секунд — полинг раз в N секунд логичен. Температура за окном — раз в минуту достаточно.

### Когда Polling плохо

Мессенджер: «пришло сообщение?» каждые 5 секунд. Сообщения могут прийти через секунду, а могут через час. Большинство запросов — холостые (ответ: «нет, ничего нового»). Тратим ресурсы впустую.

### Плюсы и минусы Polling

**Плюс:** простейшая реализация. Обычные HTTP-запросы, никакой инфраструктуры. Stateless — сервер не хранит состояние соединений.

**Минус:** холостые запросы нагружают сервер. Задержка доставки = до одного интервала опроса. Не масштабируется при миллионах клиентов, каждый из которых полит каждые 3 секунды.

## Long Polling (длинный опрос)

Клиент шлёт запрос, сервер **не отвечает сразу**, а ждёт — пока не появятся данные или не истечёт таймаут.

1. Клиент спрашивает: «есть новые сообщения?»
2. Сообщение **есть** -> сервер сразу отвечает
3. Сообщения **нет** -> сервер держит соединение 10-30 секунд
4. За это время пришло сообщение -> сервер немедленно отвечает
5. Таймаут истёк, ничего не пришло -> сервер отвечает «пусто»
6. Клиент сразу шлёт новый запрос -> цикл повторяется

### Чем Long Polling лучше обычного Polling

Меньше холостых запросов. Обычный polling каждые 5 секунд — 12 запросов в минуту, большинство впустую. Long polling — клиент «висит» на сервере, запрос уходит только после ответа или таймаута. Если данные приходят редко — запросов в разы меньше.

### Пример из практики

Балун: «Когда работал в ICQ, у нас был long polling. Не было стриминга — был long polling». Классическое применение для мессенджеров до эпохи WebSocket.

### Минусы Long Polling

Сервер держит открытые соединения — потребляет ресурсы (потоки, память). При большом количестве клиентов — десятки тысяч «висящих» соединений. Сложнее масштабировать, чем обычный polling.

## Streaming и WebSockets

Постоянное открытое соединение между клиентом и сервером. Обе стороны могут отправлять данные в любой момент.

### Ключевое отличие от Polling

В polling клиент инициирует каждый запрос. В стриминге — **сервер сам может отправить данные клиенту**, когда появляется событие. Не нужно ждать, пока клиент спросит.

### Как работает WebSocket

1. Клиент открывает WebSocket-соединение (HTTP upgrade -> ws://)
2. Соединение остаётся открытым постоянно
3. Сервер получил событие (новое сообщение, изменение цены) -> сразу пушит клиенту через открытый сокет
4. Клиент тоже может слать данные серверу через тот же сокет

Двусторонний канал — и клиент, и сервер вызывают `write()` когда нужно.

### Когда использовать WebSocket

Нет предсказуемой периодичности событий. Мессенджер — сообщение может прийти через секунду или через час. Нотификации в реальном времени. Онлайн-игры, совместное редактирование.

### Когда Polling лучше WebSocket

Есть чёткая периодичность — курс валют раз в N секунд. Polling проще, stateless, не держит соединения.

### Минусы стриминга

Постоянно открытое соединение потребляет ресурсы (и на клиенте, и на сервере). Сложнее инфраструктура: балансировка sticky sessions, reconnect при обрывах. Stateful — сервер помнит, с кем соединён.
