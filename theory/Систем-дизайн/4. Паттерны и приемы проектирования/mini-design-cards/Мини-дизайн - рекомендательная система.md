- Real-time сбор событий (просмотры, покупки, корзина) через [[Apache Kafka|Kafka]] -> аналитическое хранилище (data lake, ClickHouse, Hadoop)
- Пакетная обработка раз в день: воркер (или [[Асинхронная обработка#MapReduce|MapReduce]]-джоба) анализирует статистику и заполняет БД рекомендаций
- Рекомендашке **не нужна real-time актуализация** — предпочтения пользователя не меняются полностью из дня в день
- Архитектура: клиент -> бэкенд -> Kafka -> data lake -> воркер (раз в день) -> БД рекомендаций -> API рекомендашки -> клиент
- Ключевой урок: видеть разделение на real-time (сбор) и пакетную обработку (анализ). Не всё нужно делать в реальном времени

Пример проектирования, где важно различать real-time и пакетную обработку.

## Задача

Ozon/Amazon: рекомендовать пользователю товары на основе его интересов — что просматривал, что заказывал, что добавлял в корзину.

## Real-time часть (сбор данных)

Постоянный поток событий: пользователь просмотрел товар, добавил в корзину, купил, оценил. Все эти события льются в очередь (Kafka). Из очереди — в аналитическое хранилище (data lake, ClickHouse, Hadoop).

## Пакетная часть (построение рекомендаций)

Воркер (или MapReduce-джоба) **раз в день** берёт накопленную статистику, анализирует и заполняет БД рекомендаций: для каждого пользователя — список рекомендованных товаров.

## Почему раз в день — ок

Рекомендашке не нужна real-time актуализация. У пользователя предпочтения не меняются полностью из дня в день. Если сегодня он интересовался книгами, завтра ему всё ещё можно рекомендовать книги. Раз в день — достаточно.

## Архитектура

```
[Клиент] → [Рекомендашка API] → [БД рекомендаций]
                                        ↑
                                   раз в день
                                        |
[Клиент] → [Бэкенд] → [Kafka] → [Data Lake] → [Воркер]
            события      поток      хранилище    анализ
```

## Ключевой урок

Видеть разделение на real-time (сбор событий, мгновенная доставка) и пакетную обработку (анализ раз в день/час). Не всё нужно делать в реальном времени. Важно спрашивать: «а как часто нужно актуализировать?»

## Связь
- [[Асинхронная обработка#MapReduce|MapReduce]] — может использоваться для пакетного анализа
- [[Асинхронная обработка#Отложенное выполнение (Deferred Execution)|Отложенное выполнение]] — воркер обрабатывает не сразу, а по расписанию
- [[Архитектурные паттерны#Pub/Sub (Publisher-Subscriber)|Pub/Sub]] — сбор событий через очередь
