- **Aggregator** — сервис собирает данные из нескольких микросервисов параллельно, склеивает и отдаёт клиенту единый ответ. Топология — звезда
- **Chain** — запрос проходит через цепочку сервисов последовательно, каждому нужен результат предыдущего. Топология — цепочка
- Aggregator = BFF (Backend for Frontend) = фасад (из GoF). Разные названия — одна идея. Балун: «Некоторые штуки имеют 10 разных названий»
- Chain: latency складывается, отказ любого звена ломает всю цепочку. Три звена — терпимо, десять — проблема
- Aggregator используют, когда данные из разных сервисов независимы. Chain — когда есть последовательная зависимость
- Оба паттерна — про композицию микросервисов для формирования ответа клиенту

| Паттерн | Топология | Вызовы | Latency | Зависимость данных |

| Aggregator | Звезда (параллельно) | Агрегатор -> N сервисов одновременно | Max из N вызовов | Данные независимы |

### Aggregator (агрегатор)

Сервис, который собирает данные из нескольких микросервисов, склеивает и отдаёт клиенту единый ответ.

### Пример Aggregator

Клиент хочет страницу профиля пользователя. Нужны: информация о пользователе (User Service), рейтинг (Rating Service), история заказов (History Service). Три разных сервиса. Клиенту неудобно ходить в три места. Ставим перед ними агрегатор — он сам сходит во все три, соберёт ответ и вернёт клиенту единый JSON.

### Как работает Aggregator

1. Клиент -> запрос в агрегатор
2. Агрегатор -> параллельно (или последовательно) ходит в N сервисов
3. Получает ответы, склеивает
4. Агрегатор -> единый ответ клиенту

### Это BFF?

Backend for Frontend (BFF) — по сути тот же агрегатор, вид сбоку. Прослойка, которая формирует ответ под нужды конкретного фронтенда. Разные названия — одна идея. Балун: «Некоторые штуки имеют 10 разных названий».

### Это не фасад?

Фасад — паттерн из GoF (структурный). Агрегатор — термин из мира микросервисов. Концептуально похожи: скрывают сложность за простым интерфейсом. Но в микросервисном контексте говорят «агрегатор», не «фасад».

### Chain (цепочка)

Запрос проходит через цепочку сервисов последовательно. Каждый сервис обрабатывает свою часть и вызывает следующий.

### Пример Chain

Клиент -> Load Balancer -> Orders Service. Orders нужна информация об оплате — идёт в Payments Service. Payments отвечает -> Orders формирует итоговый ответ -> отдаёт клиенту.

```
Клиент → LB → Orders → Payments
                  ↓
              ответ клиенту
```

### Отличие Chain от Aggregator

**Aggregator:** один сервис параллельно ходит в несколько. Звезда — агрегатор в центре, сервисы вокруг.

**Chain:** сервисы вызывают друг друга последовательно. Цепочка — A -> B -> C -> ответ. Каждому следующему нужен результат предыдущего.

### Минусы Chain

- Latency складывается: каждое звено добавляет задержку
- Отказ любого звена ломает всю цепочку
- Чем длиннее цепочка, тем хуже: три звена — терпимо, десять — проблема

### Когда используется Chain

Когда сервису для ответа нужны данные из другого сервиса, а не просто параллельный сбор. Зависимость последовательная: «сначала узнай оплату, потом сформируй заказ».
