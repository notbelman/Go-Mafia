Запрос проходит через цепочку сервисов последовательно. Каждый сервис обрабатывает свою часть и вызывает следующий.

## Пример

Клиент → Load Balancer → Orders Service. Orders нужна информация об оплате — идёт в Payments Service. Payments отвечает → Orders формирует итоговый ответ → отдаёт клиенту.

```
Клиент → LB → Orders → Payments
                  ↓
              ответ клиенту
```

## Отличие от Aggregator

**Aggregator:** один сервис параллельно ходит в несколько. Звезда — агрегатор в центре, сервисы вокруг.

**Chain:** сервисы вызывают друг друга последовательно. Цепочка — A → B → C → ответ. Каждому следующему нужен результат предыдущего.

## Минусы

- Latency складывается: каждое звено добавляет задержку
- Отказ любого звена ломает всю цепочку
- Чем длиннее цепочка, тем хуже: три звена — терпимо, десять — проблема

## Когда используется

Когда сервису для ответа нужны данные из другого сервиса, а не просто параллельный сбор. Зависимость последовательная: «сначала узнай оплату, потом сформируй заказ».
