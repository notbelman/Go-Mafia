## Условие

    "fmt"

## Решение

```go
func uniqRandn(n int) []int {
    // Предварительно выделяем память под результат (длина 0, ёмкость n)
    res := make([]int, 0, n)
    
    // Хеш-таблица для отслеживания уже сгенерированных уникальных чисел
    uniqCheck := make(map[int]struct{})
    
    for i := 0; i < n; i++ {
        var randInt int
        // бесконечный цикл, пока не сгенерируем уникальное число 
        for {
            randInt = rand.Int()
            // Проверяем, что число уникально
            if _, ok := uniqCheck[randInt]; !ok {
                uniqCheck[randInt] = struct{}{}
                break
            }
        }
        res = append(res, randInt)
    }
    return res
}
```
**Сложность:**
- Временная: O(n) в среднем, O(n²) в худшем случае при частых коллизиях
- Пространственная: O(n) для слайса и map

**Вопросы:**
1. Есть ли шанс уйти в бесконечный цикл, если число не уникально?
	Теоретически да, но практически нет. `rand.Int()` на 64-битной системе возвращает числа из диапазона 0 до 2⁶³-1. Вероятность коллизии ничтожна при разумных `n`. Но если `n` приближается к диапазону генератора — цикл будет крутиться всё дольше, пытаясь найти незанятое число. Бесконечным он станет если все возможные значения уже заняты.
2. Что делать, если нельзя использовать пакет rand?
	Несколько вариантов:
	- `crypto/rand` — криптографически стойкий генератор
	- Fisher-Yates shuffle: создать массив `[0, 1, 2, ..., max]`, перемешать, взять первые `n` элементов — гарантированно уникальные, без бесконечного цикла
	- Использовать время (`time.Now().UnixNano()`) как источник энтропии — ненадёжно, но работает для простых случаев
