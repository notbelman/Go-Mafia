Поскольку при стандартной гарантии _At least once_ дубликаты неизбежны (например, если сообщение записалось, но подтверждение потерялось в сети), консьюмер должен быть **идемпотентным**.

**Идемпотентность** — это способность сервиса обрабатывать дублированные данные так, как будто они пришли один-единственный раз, без негативных последствий для логики приложения. Для обеспечения идемпотентности разработчики используют:

- Специальные фильтры для устранения дублей.
- Проверку уникальных идентификаторов в базе данных (если сообщение с таким ID уже обрабатывалось, оно игнорируется).
