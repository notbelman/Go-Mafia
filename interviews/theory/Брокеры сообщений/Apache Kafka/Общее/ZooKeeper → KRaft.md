## Суть

Kafka нужен кто-то для хранения метаданных кластера (какие брокеры живы, кто лидер партиции, конфиги топиков). Раньше — ZooKeeper, теперь — KRaft (встроенный в саму Kafka).

||ZooKeeper|KRaft|
|---|---|---|
|Метаданные|в ZooKeeper znodes|в Kafka топике|
|Failover контроллера|загрузка из ZK (медленно)|уже в памяти (быстро)|
|Инфраструктура|2 системы|1 система|
|Лимит партиций|~200K|миллионы|

## Проблема с ZooKeeper

- Отдельная распределённая система — нужно деплоить, мониторить, обновлять два кластера вместо одного
- Бутылочное горлышко: каждое изменение партиции = синхронная запись в ZooKeeper
- При падении контроллера — новый должен загрузить всё состояние из ZooKeeper (медленно)
- Ограничивал количество партиций в кластере

## KRaft (Kafka 4.0+, ZooKeeper полностью удалён)

Метаданные хранятся в самой Kafka в специальном топике `__cluster_metadata`. Контроллеры выбирают лидера через Raft-консенсус между собой.

```
ZooKeeper:  Kafka brokers ←→ отдельный ZooKeeper кластер (3-5 нод)
KRaft:      Kafka brokers + controller nodes (всё внутри Kafka)
```
