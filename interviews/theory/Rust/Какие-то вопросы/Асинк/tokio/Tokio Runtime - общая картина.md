Tokio runtime - это среда выполнения асинхронного кода. Состоит из трёх компонентов.

### Компоненты

**Executor (scheduler)** - выполняет задачи. Берёт таску из очереди, поллит её Future, если Pending - откладывает, если Ready - завершает. Использует work-stealing: worker потоки воруют задачи друг у друга для балансировки.

**Reactor (I/O driver)** - ждёт события от ОС через epoll/kqueue/IOCP. Когда событие приходит (сокет готов, данные пришли), будит соответствующую задачу через Waker.

**Timer** - управляет таймаутами и sleep'ами. Когда время вышло - будит задачу.

### Как работает выполнение

1. Вызываешь `tokio::spawn(async { ... })` - задача попадает в очередь
2. Worker thread берёт задачу, вызывает `poll()` на её Future
3. Future выполняется до первого `.await`
4. Если операция не готова - Future возвращает `Pending` и регистрирует Waker
5. Worker откладывает задачу, берёт следующую из очереди
6. Когда I/O готов или таймер сработал - Reactor/Timer дёргает Waker
7. Waker кладёт задачу обратно в очередь
8. Worker снова поллит задачу - она продолжает с места где остановилась
9. Когда Future возвращает `Ready(result)` - задача завершена

### Потоки

Runtime создаёт два пула потоков:

- **Worker threads** (по умолчанию = ядрам CPU) - крутят async задачи, один worker выполняет тысячи тасок конкурентно
- **Blocking threads** (до 512, по требованию) - для spawn_blocking, один поток = одна блокирующая операция

### Почему это эффективно

Обычные потоки дорогие (память, переключение контекста ОС). Tokio запускает мало потоков, но каждый обрабатывает много задач. Задачи переключаются только на `.await` (cooperative scheduling), без участия ОС. Это позволяет держать сотни тысяч соединений на нескольких потоках.
