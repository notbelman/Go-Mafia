title: Отличие & от &mut

Заимствование — это механизм доступа к данным без передачи владения. Это позволяет избежать лишних аллокаций и копирований, сохраняя безопасность памяти.

**Два главных правила (Borrow Checker):**

1. Либо **одна изменяемая ссылка** (`&mut T`), либо **любое количество неизменяемых ссылок** (`&T`).
2. Ссылки должны быть всегда **валидными** (не могут пережить владельца).

```
fn main() {
    let mut s = String::from("hello");

    let r1 = &s; // OK
    let r2 = &s; // OK
    println!("{} and {}", r1, r2);
    // Область видимости r1 и r2 заканчивается здесь (после последнего использования)

    let r3 = &mut s; // OK, так как r1 и r2 больше не используются
    r3.push_str(", world");

    // println!("{}", r1); // ОШИБКА: r1 нельзя использовать после создания r3
}
```

**Senior-уровень: что важно знать?**

- **Data Race Prevention:** Правило "один mutable ИЛИ много immutable" исключает состояние гонки (data race) на этапе компиляции. Если данных никто не меняет, их можно читать из многих мест. Если кто-то меняет — никто другой не должен иметь к ним доступа.
- **Non-Lexical Lifetimes (NLL):** В современных версиях Rust (включая 1.85.0) компилятор очень умен: время жизни ссылки заканчивается в момент её последнего использования, а не в конце блока `{}`. Это делает код менее перегруженным.
- **Deref Coercion:** Rust автоматически преобразует ссылки на типы, реализующие трейт `Deref` (например, `&String` в `&str`). Это позволяет писать более универсальный API.
- **Edition 2024 Note:** Хотя фундаментальные правила заимствования не изменились, в новых идиомах уделяется больше внимания эргономике работы со ссылками в асинхронном контексте и сложных структурах.
