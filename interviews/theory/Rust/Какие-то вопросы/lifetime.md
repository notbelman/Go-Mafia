title: Что такое lifetime
---
**Времена жизни** — это параметры, которые сообщают компилятору, как долго ссылки в структурах или функциях должны оставаться валидными относительно друг друга. Данная версия текста книги предполагает использование идиом **Rust 2024 Edition**.

**Основные концепции:**

1. **Generic Lifetimes:** Позволяют функции принимать ссылки, не зная заранее их конкретного времени жизни, но устанавливая связь между ними.
2. **Lifetime Elision:** Набор правил, позволяющих компилятору выводить времена жизни автоматически (для удобства чтения кода).
	1. Каждый параметр-ссылка получает свой lifetime
	2. Если входной lifetime один - он присваивается всем выходным ссылкам
	3. Если есть `&self` или `&mut self` - его lifetime присваивается выходным
3. **'static:** Специальное время жизни, означающее, что данные живут на протяжении всего времени работы программы (например, строковые литералы).

```
// Пример функции с явными аннотациями
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

**Senior-уровень: механизмы и нюансы**

- **Variance (Вариантность):** На уровне Senior важно понимать ковариантность и контравариантность времен жизни. Например, `&'static str` может быть передано там, где ожидается `&'a str` (ковариантность), потому что `'static` живет дольше любого `'a`.
- **Lifetime Elision Rules:**
    1. Каждому параметру-ссылке назначается свое время жизни.
    2. Если есть ровно один входной параметр-ссылка, его время жизни назначается всем выходным ссылкам.
    3. Если есть `&self` или `&mut self`, время жизни `self` назначается всем выходным параметрам.
- **Bound 'a: 'b:** Означает, что `'a` живет как минимум так же долго, как `'b` (outlives).
- **T vs &T:** Помни, что трейт-баунд `T: 'a` означает, что тип `T` не содержит ссылок, которые живут меньше, чем `'a`.
