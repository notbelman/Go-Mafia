**Что это:** Хеш-таблица: `hash(value) → TID`. Только для `=` операций.

**Использовать:**

- Длинные строковые ключи (URL, токены) - экономия ~20% vs B-tree
- Только точные совпадения, никогда range/сортировка

**Не использовать:**

- В 99% случаев B-tree лучше (универсальнее, тоже быстр на `=`)
- Нужны `>`, `<`, `BETWEEN`, `ORDER BY`, `LIKE`
- Нужен UNIQUE constraint

```sql
CREATE INDEX idx_url ON pages USING HASH(url);
```
