Создание индекса без блокировки таблицы на запись.

## Зачем

Обычный `CREATE INDEX` блокирует INSERT/UPDATE/DELETE на всё время создания.
На таблице 100M строк это минуты простоя.

## Синтаксис
```sql
CREATE INDEX CONCURRENTLY idx_email ON users(email);
```

## Как работает

Два прохода по таблице вместо одного:
1. Сканирует таблицу, строит индекс
2. Ждёт завершения текущих транзакций
3. Второй проход - добавляет изменения, которые произошли во время первого прохода

Поэтому работает ~2x дольше обычного CREATE INDEX.

## Когда падает

Если во время создания возникла ошибка (например, дубликат в UNIQUE индексе):
- Индекс остаётся в состоянии INVALID
- Не используется планировщиком, но занимает место
```sql
-- Проверить невалидные индексы
SELECT indexrelid::regclass, indisvalid 
FROM pg_index WHERE NOT indisvalid;

-- Удалить и пересоздать
DROP INDEX CONCURRENTLY idx_email;
CREATE INDEX CONCURRENTLY idx_email ON users(email);
```
