Альтернатива consistent hashing. Нет кольца — вместо этого для каждого ключа считаем хеш со всеми шардами и выбираем максимум.

## Как работает

1. Хотим записать ключ 123
2. Считаем hash(123, shard_1) = 345
3. Считаем hash(123, shard_2) = 456
4. Считаем hash(123, shard_3) = 121
5. Максимум = 456 → записываем в shard_2

Чтение: точно так же пересчитываем, получаем тот же максимум → идём в shard_2.

## Добавление/удаление шарда

Добавили shard_4 → для каждого ключа пересчитываем hash с новым шардом. Если новый хеш стал максимумом — ключ переезжает. Остальные ключи не двигаются.

При удалении: ключи выпавшего шарда перераспределяются по остальным (у кого следующий максимум).

**Важно:** после добавления/удаления нужно пересчитать и перенести затронутые данные — автоматически они не переедут.

## Сравнение с Consistent Hashing

| | Consistent Hashing | Рандеву |
|---|---|---|
| Структура | Кольцо + virtual nodes | Нет структуры, просто функция |
| Реализация | Сложнее | Проще (несколько строк кода) |
| Добавление шарда | ~1/N данных перемещается | ~1/N данных перемещается |
| Равномерность | Нужны virtual nodes | Зависит от хеш-функции |

## На практике

Встречается реже consistent hashing. Проще в реализации, но на каждый запрос нужно считать N хешей (по числу шардов). При большом N — ощутимый overhead.
