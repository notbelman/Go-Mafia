Прослойка абстракции между приложением и физическими шардами.

## Проблема

Приложение знает о 3 физических шардах → hash(key) % 3. Добавили 4-й → hash(key) % 4 → почти все ключи переехали. Нужно перебалансировать всё.

## Решение

Создаём заранее 1024 (или 1448) виртуальных бакетов. Приложение всегда делает hash(key) % 1024. Не меняется никогда.

Физических шардов 3 → бакеты 0–340 на шарде 1, 341–681 на шарде 2, 682–1023 на шарде 3.

## Добавление физического шарда

Было 3 шарда, стало 4. Перемещаем часть бакетов на новый шард. Для приложения **ничего не меняется** — оно как считало hash % 1024, так и считает. Просто маппинг «бакет → физический шард» обновился.

## Почему много бакетов

Чтобы **никогда не менять** их количество. Изменение количества бакетов = решардинг (пересчёт всех хешей). 1024 бакетов хватает на долго — даже если физических шардов станет 100, по 10 бакетов на шард.

## Virtual Buckets ≠ Virtual Nodes

- **Virtual Buckets** — абстракция над физическими шардами. Приложение работает с бакетами, не знает про физические шарды.
- **Virtual Nodes** — приём внутри consistent hashing. Один физический шард = 100+ точек на кольце для равномерности.

Разные уровни, могут использоваться вместе.
