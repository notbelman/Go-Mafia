Алгоритм распределения данных, при котором добавление/удаление шарда перемещает минимум данных.

## Проблема обычного хеша

hash(key) % N шардов - при добавлении шарда (N -> N+1) почти все ключи меняют свой шард.
Пример: hash("user_123") % 4 = 2, но hash("user_123") % 5 = 3 - нужно переместить.

## Как работает кольцо

1. Представь кольцо от 0 до 2^32 (или 360 градусов)
2. Каждый шард хешируется и ставится на кольцо: hash(shard_ip) -> позиция
3. Каждый ключ хешируется и ставится на кольцо: hash(key) -> позиция
4. Ключ принадлежит ближайшему шарду по часовой стрелке
```
        0
        |
   K1 --+-- Shard A
       /
      /
 Shard C        Shard B
      \        /
       \--K2--/

K1 -> Shard A (ближайший по часовой)
K2 -> Shard B (ближайший по часовой)
```

## Добавление шарда

Новый шард встаёт на кольцо - забирает только ключи между собой и предыдущим шардом.
Остальные ключи не двигаются. Перемещается ~1/N данных вместо почти всех.

## Virtual Nodes

Проблема: 3 шарда могут встать неравномерно, один получит 60% ключей.
Решение: каждый физический шард = 100-200 виртуальных точек на кольце.
Это даёт равномерное распределение даже при малом числе шардов.

## Где используется

- DynamoDB, Cassandra - распределение данных
- Memcached, Redis Cluster - распределение кэша
- CDN - роутинг к ближайшему серверу
