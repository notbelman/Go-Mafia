Строим хэш-таблицу из меньшей таблицы (Build), пробегаем по большей и ищем совпадения за O(1) (Probe).

## Когда выбирается

- Только = в условии JOIN
- Правая(внутренняя) влезает в work_mem
- Нет индексов / данные не отсортированы

## Сложность

O(N + M) — линейная. Build: O(N), Probe: O(M).

## Ограничения

- Не умеет неравенства (`<`, `>`, `BETWEEN`)
- Не отдаёт результат до конца build-фазы (плохо с LIMIT)
- Нужна память под хэш-таблицу

---

## EXPLAIN
```
Hash Join  (cost=30.00..150.00 rows=1000)
  Hash Cond: (o.user_id = u.id)
  ->  Seq Scan on orders o         ← Probe: пробегаем
  ->  Hash                         ← Build: строим хэш-таблицу
        ->  Seq Scan on users u
```

Batches > 1 — хэш-таблица не влезла в work_mem:
```
->  Hash (rows=10000)
      Batches: 8    ← часть на диске, медленно
      Memory Usage: 4096kB
```

Решение: `SET work_mem = '256MB';`
