Обе таблицы отсортированы по ключу JOIN — идём параллельно, один проход по каждой.

## Когда выбирается
- Только = в условии JOIN
- Правая(внутренняя) **НЕ** влезает в work_mem
- Данные уже отсортированы (индекс) или сортировка нужна для ORDER BY

## Сложность
- O(N + M) — если уже отсортированы
- O(N log N + M log M) — если нужна сортировка

## Ограничения

- Только `=` в условии JOIN
- Без индексов — дорогая сортировка

---

## EXPLAIN

Идеально — обе стороны по индексу:
```
Merge Join  (cost=200.00..350.00)
  Merge Cond: (u.id = o.user_id)
  ->  Index Scan using users_pkey on users     ← уже отсортирован
  ->  Index Scan using idx_orders on orders    ← уже отсортирован
```

Плохо — нужна сортировка:
```
Merge Join
  ->  Sort                      ← дорого
        ->  Seq Scan on users
  ->  Sort                      ← ещё дороже
        ->  Seq Scan on orders
```
