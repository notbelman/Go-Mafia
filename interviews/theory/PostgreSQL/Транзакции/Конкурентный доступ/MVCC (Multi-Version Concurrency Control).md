## Что это

Механизм конкурентного доступа: каждая модификация создаёт новую версию строки, а не перезаписывает старую.

**Ключевое:** читатели не блокируют писателей, писатели не блокируют читателей.

## Как работает

| Операция | Что происходит |
|----------|----------------|
| INSERT | Новая версия с xmin = текущий XID |
| DELETE | Старая версия помечается xmax = текущий XID |
| UPDATE | DELETE старой + INSERT новой |
```
Heap (таблица):
┌─────┬─────┬────┬─────────┐
│xmin │xmax │ id │ balance │
├─────┼─────┼────┼─────────┤
│ 100 │ 105 │  1 │ 1000    │  ← старая версия, "удалена" T105
│ 105 │  -  │  1 │ 2000    │  ← актуальная версия
└─────┴─────┴────┴─────────┘
```

**Что такое xmin/xmax?**
- `xmin` — XID транзакции, создавшей эту версию
- `xmax` — XID транзакции, удалившей/заменившей эту версию (0 или null если актуальна)
## Следствия

- UPDATE дороже чем в других СУБД (две операции)
- Таблица "распухает" от старых версий → нужен VACUUM
- Каждая транзакция видит свой "срез" данных через snapshot
