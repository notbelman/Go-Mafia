Подбор водителя для пассажира. Самая сложная бизнес-логика в системе.

## Алгоритм матчинга

1. Пассажир нажал "Вызвать такси" → `createOrder(from, to)`
2. Matching Service получает координаты пассажира → вычисляет geohash
3. Идёт в Geo Service → "Отдай водителей в этом geohash" (из base_driver_position)
4. Получает до **10 свободных водителей**
5. **Синхронно перебирает**: предлагает первому → ждёт 5 секунд → подтвердил? Готово. Нет? Предлагаем второму. И так далее.
6. Водитель подтвердил → уведомляем пассажира → создаём поездку в Ride Service

## Почему синхронный перебор, а не всем сразу

Если предложить всем 10 водителям одновременно: 9 подтвердят и получат отказ ("подтвердил, а заказ не мой"). Плохой UX для водителей. Водитель подумает: "Что произошло? Почему не подтвердилось?"

## Почему укладываемся в 1 минуту

```
Поиск водителей:    ~300 мс (с запасом)
Перебор:            10 × 5 сек = 50 сек
Обратный путь:      ~300 мс
Итого:              ~51 сек < 1 минуты ✓
```

## Как водитель получает предложение

Matching Service → **Notification Service** (через WebSocket) → водитель видит предложение на экране. Водитель подтверждает через свой API Gateway → `applyOrder()`. Или игнорирует — через 5 секунд таймаут, переходим к следующему.

`cancelOrder()` — водитель может явно отказаться (быстрее, чем ждать таймаут). Пассажиру предложат следующего водителя быстрее.

## Проблема: Matching Service упал

Matching Service держит стейт: "сейчас опрашиваю 5-го водителя для пассажира Васи". Если рухнет — стейт потерян. Пассажир ждёт такси, а система забыла про его заказ.

**Решение: прикапываем стейт.** Рядом с Matching Service — in-memory хранилище:

```
matching_status:
  match_id
  user_id
  drivers []      — массив кандидатов
  status          — текущий статус (какого водителя опрашиваем)
```

При падении: пассажир переподключается → новый инстанс Matching Service → читает matching_status → продолжает опрос с того места, где остановились.

**Нужно ли реплицировать этот стейт?** Балун считает, что не обязательно. Крайне маловероятно, что рухнет И Matching Service, И его хранилище одновременно. Но WAL не помешает.

## Нет водителей в geohash

- Сканим соседние ячейки geohash
- Нет нигде → "Нет таксистов поблизости", пустой ответ пассажиру
