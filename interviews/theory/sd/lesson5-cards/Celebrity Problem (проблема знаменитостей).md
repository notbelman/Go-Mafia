Один пользователь с миллионом подписчиков создаёт пост → миллион операций записи для обновления лент. Горячий ключ в fan-out on write.

## Проблема

Максимум друзей = 1.000.000. Павел Дуров написал пост. При fan-out on write нужно обновить миллион лент. Одна операция записи порождает миллион операций — система захлебнётся.

## Решение: гибридный подход

Разделяем пользователей на обычных и знаменитостей по порогу подписчиков (5.000–10.000, точное число покажет эксплуатация).

**Обычный пользователь** написал пост → fan-out on write, пушим в ленты всех друзей. Друзей мало — ок.

**Знаменитость** написала пост → **не пушим** в ленты подписчиков. Просто обновляем ленту самой знаменитости (user feed).

**При чтении:** Feed Service достаёт готовую home feed пользователя, смотрит дату первого поста, проверяет ленты всех знаменитостей, на которых подписан пользователь. Если у знаменитости есть пост свежее — подмёрживает его в ленту на лету и отдаёт.

## Компромисс

Чтение стало чуть дороже (нужно подмёржить посты знаменитостей). Зато запись не порождает миллион операций. Волки сыты, овцы целы.

## Где ещё встречается

Любая система с подписками и горячими ключами: Twitter, Instagram, YouTube (подписки на каналы), новостные агрегаторы. Везде, где один автор может иметь непропорционально много подписчиков.
