Механизм, обеспечивающий эксклюзивный доступ к ресурсу в распределённой системе. В одну единицу времени — только один клиент.

## Реализация через Redis

Блокировка — одна атомарная команда:

```
SET resource_name my_random_value NX PX 30000
```

- **NX** — вставить только если ключа нет (атомарно)
- **PX 30000** — TTL 30 секунд (автоудаление)
- **my_random_value** — уникальное значение клиента

Два клиента одновременно шлют SET NX → только один получит OK. Второй получит отказ — ресурс залочен.

## Зачем TTL

Если клиент взял блокировку и упал — без TTL блокировка останется навсегда. Никто больше не сможет работать с ресурсом. TTL — страховка: через 30 секунд блокировка снимется автоматически.

## Зачем random value

Снятие блокировки — в одной мини-транзакции Redis:

```
GET resource_name
если значение == my_random_value → DELETE resource_name
```

**Без random value — data race:** у блокировки осталось 50мс TTL. Клиент 1 шлёт DELETE, но запрос идёт 100мс. За это время TTL истёк, блокировка удалилась. Клиент 2 успел взять блокировку. И тут приходит DELETE от клиента 1 — удаляет **чужую** блокировку.

Random value решает: клиент 1 проверяет — значение не моё → не удаляю.
