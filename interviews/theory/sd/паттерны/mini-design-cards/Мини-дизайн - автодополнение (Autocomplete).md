Пример проектирования, где важны компромиссы между скоростью и памятью.

## Задача

Google: пользователь вводит «патт» → подсказки: «паттерны проектирования», «паттерн сага», «паттерны». Нужно отдавать топ-N самых популярных слов по префиксу, очень быстро.

## Структура данных: префиксное дерево (Trie)

Каждый узел — буква. Путь от корня до листа — слово. Есть сжатый вариант: где нет разветвления — храним подстроку целиком (`п` → `ривет`, а не `п` → `р` → `и` → `в` → `е` → `т`).

## Проблема масштаба

Пользователь ввёл «п» — сколько слов в русском языке начинается на «п»? Тысячи. Перебрать все листья, найти топ-5 популярных — очень медленно на масштабе Google.

## Решение: кэш популярных в каждом узле

В каждом узле дерева заранее храним N самых популярных завершений. Ввёл «п» → сразу из узла «п» достаём заготовленный топ-5, без обхода дерева вниз.

**Компромисс:** тратим больше памяти (в каждом узле дублируются данные), но отвечаем мгновенно. Нет идеального дизайна — всегда компромисс между скоростью и ресурсами.

## Debounce и Throttle

Пользователь быстро вводит «п», «па», «пат», «патт». Если на каждую букву слать запрос — ответы могут прийти не в том порядке, подсказки будут «моргать».

**Debounce:** ждём 50-100мс после последнего нажатия. Пользователь остановился → шлём запрос. Фильтруем промежуточные нажатия.

**Throttle:** максимум один запрос в N миллисекунд, остальные отбрасываются. Пример из игр: как бы быстро ни кликал — выстрел раз в секунду.

## Обновление дерева

Дерево живёт в памяти сервиса. Как обновить (раз в день, по свежей статистике)?

**Вариант 1:** Rolling deploy — подготовить новую версию дерева, переключить трафик.

**Вариант 2:** Атомарный swap корня — дерево это указатели. Подготовить новое дерево, атомарно подменить указатель на корень. Старое дерево GC уберёт.

## Архитектура

```
[Клиент] → debounce → [Trie-сервис (дерево в памяти)]
                              ↑
                         раз в день
                              |
[Клиент] → [Бэкенд] → [Kafka] → [Аналитика] → [Воркер]
            запросы      поток     что ищут     пересчёт
```

## Ключевые уроки

1. **Компромисс память vs скорость** — кэш популярных в узлах: больше памяти, мгновенный ответ
2. **Debounce/Throttle** — не слать запрос на каждый чих
3. **Данные в памяти — ок**, но нужна отказоустойчивость (N реплик сервиса)
4. **Своя структура данных — ок.** Не всё обязательно хранить в БД. Префиксное дерево в памяти процесса — нормальное решение
