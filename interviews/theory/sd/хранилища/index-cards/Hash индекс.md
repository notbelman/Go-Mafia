**Суть:** Рядом с данными хранится хэш-таблица. Ключ → хэш → позиция данных. Поиск за O(1).

**Когда использовать:** нужно найти ровно одну запись по точному значению ключа. "Найди пользователя с id = 42" — идеальный кейс.

**Преимущество перед B-tree:** O(1) вместо O(T × log_T(N)). Быстрее для точечных запросов.

**Минус:** нельзя искать диапазон. "Найди пользователей с id от 100 до 200" — не работает. Хэш-таблица не упорядочена.

**Сравнение:**

| | B-tree | Hash |
|--|--------|------|
| Точечный поиск | O(log N) | O(1) |
| Диапазон | Да (B+ tree) | Нет |
| Сортировка | Да | Нет |

**Правило:** нужен диапазон или сортировка → B-tree. Только точечный поиск → hash.
