## Кластерный индекс
Строки таблицы **физически отсортированы** по ключу этого индекса на диске. Кластерный индекс = порядок хранения данных.

- в таблице может быть **только один** кластерный индекс (данные нельзя отсортировать двумя способами одновременно)
- по умолчанию в реляционках кластерный индекс = primary key
- вставка может вызывать перестроение (новая строка должна встать на своё место в порядке)

**Таблица без кластерного индекса** называется **heap** — данные лежат в произвольном порядке.

## Некластерный индекс
Отдельная структура данных (B-tree, hash, bitmap, spatial...), которая ссылается на строки таблицы. **Не влияет на физический порядок** хранения данных.

- может быть **много** некластерных индексов на одну таблицу
- это все индексы, которые мы "прикручиваем сверху"

## Соотношение с типами индексов

| Концепция | Примеры |
|-----------|---------|
| Кластерный | Primary key (B-tree, определяет порядок строк) |
| Некластерный | B-tree, hash, bitmap, spatial, inverted — любой дополнительный индекс |

Кластерный/некластерный — это **где и как хранятся данные**. B-tree, hash, bitmap — это **структура данных** индекса. Разные оси классификации.
