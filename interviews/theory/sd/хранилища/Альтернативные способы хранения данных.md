Не всё нужно хранить в БД. Два часто забываемых варианта:

## Хранение на клиенте
У клиента есть память. Не нужно всё тащить с сервера — что-то можно отдать клиенту, чтобы он закэшировал или сохранил у себя.

**Примеры:** токен авторизации, настройки интерфейса, черновик сообщения, последняя позиция в видео.

**Ограничения:** не грузить клиента гигабайтами. Мобилки — мало ресурсов. Но забывать про клиента = упущенная оптимизация.

## CDN (Content Delivery Network)
Сеть кэширующих серверов, расположенных географически близко к пользователям. Для статического контента (картинки, видео, JS/CSS).

**Компоненты:**
- **POP** (Point of Presence) — кэширующий сервер в регионе
- **Origin** — исходное хранилище данных (S3, ваш сервер)
- **Proxy** — определяет, какой POP ближе к пользователю

**Pull-модель (по умолчанию):** пользователь запросил → POP проверяет кэш → нет данных → идёт в Origin → кэширует → отдаёт. Следующий запрос — из кэша.

**Push-модель (редко):** перед релизом контента — заранее раскидать по POPам. Netflix перед анонсом сериала пушит контент на POPы, чтобы при анонсе всё было готово.

**Почему pull чаще:** в CDN платишь за трафик. Push наполняет POPы данными, которые могут никому не понадобиться.

- [[Latency (задержка)]] — CDN уменьшает latency за счёт географической близости
- [[Различие|Push и Pull]] — CDN = практический пример обеих моделей
