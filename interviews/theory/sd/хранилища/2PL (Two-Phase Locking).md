**Суть:** Механизм обеспечения изоляции транзакций через мелкогранулярные блокировки (мьютекс на каждую строку).

**Две фазы:**
1. **Фаза расширения** — транзакция последовательно захватывает блокировки на нужные строки
2. **Фаза сужения** — транзакция последовательно отпускает блокировки в обратном порядке

**Проблема: deadlock**
- Транзакция A: лочит строку 1, потом хочет строку 2
- Транзакция B: лочит строку 2, потом хочет строку 1
- Обе ждут друг друга → пробка на перекрёстке

**Как БД решает deadlock:** менеджер транзакций по таймауту убивает одну из транзакций (rollback), вторая проходит дальше.

**Как предотвратить самим:** захватывать блокировки **в одном и том же порядке** во всех транзакциях. Если все лочат сначала строку 1, потом строку 2 — deadlock невозможен.

**Альтернатива 2PL:** MVCC (Multi-Version Concurrency Control) — версионный подход без блокировок. Используется в PostgreSQL. Update = пометить старую строку (TX Max) + вставить новую. Поэтому INSERT дешевле UPDATE в MVCC-базах.

**Не путать:** 2PL (Two-Phase Locking) ≠ 2PC (Two-Phase Commit) — это разные вещи. 2PC — про распределённые транзакции.
