**Суть:** Правило Джефа Безоса (основатель Amazon) для проектирования микросервисов:
- у каждого сервиса должна быть **своя база данных**
- сервисы общаются **только через API** (интерфейс)
- нельзя лезть в чужую БД напрямую

**Почему:**
- если дать другому сервису доступ к БД — он может её дропнуть, записать мусор, сломать данные
- API ограничивает: авторизация, валидация, rate limiting — контролируем, что можно делать
- изоляция: каждый сервис — хозяин своих данных

**Что с очередями?** Очереди — ok. Даже через очередь я прихожу в API сервиса. Сервис сам решает, как обработать сообщение. Это не обходной путь (как прямая запись в чужую БД).

**Исключения:** инфраструктурные сервисы (трейсинг, логирование, потоки данных) иногда пишут напрямую в общие хранилища. Мандат Безоса — больше про продуктовые сервисы.

**Shared database = нарушение мандата:**
- 3 воркера пишут в одну БД, другой сервис читает → это shared database → формально нарушение
- но в инфре иногда оправдано

**Связь:**
- [[interviews/theory/sd/основные понятия/backend-architecture-cards/Микросервисы|Микросервисы]] → мандат Безоса как правило проектирования
- [[SOA (Service-Oriented Architecture)]] нарушает мандат (общая БД)
- API → каждый сервис предоставляет свой интерфейс (REST, gRPC)
