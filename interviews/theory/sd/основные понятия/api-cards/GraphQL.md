**Суть:** Язык запросов для API. Клиент сам описывает, какие поля ему нужны — как SQL, но для API.

**Пример запроса:**
```graphql
query {
  user(id: 5) {
    name
    email
    posts {
      title
    }
  }
}
```
Клиент получит только name, email и titles постов — ничего лишнего.

**Три типа операций:**
- **Query** — чтение данных
- **Mutation** — изменение данных (аналог POST/PUT/DELETE)
- **Subscription** — подписка на события (реалтайм)

**Плюсы:**
- клиент запрашивает ровно то, что нужно — нет overfetching
- один endpoint для всего (обычно POST /graphql)
- клиент не зависит от того, как бэкенд структурирует данные

**Минусы:**
- сложнее на бэкенде — нужен резолвер для каждого поля
- кэширование сложнее — один endpoint, разные запросы
- может быть тяжёлым для сервера, если клиент запросит слишком глубокую вложенность

**Когда использовать:**
- много разных клиентов с разными потребностями (mobile, desktop, TV)
- нужна гибкость запросов
