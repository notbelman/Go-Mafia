**Суть:** Приложение читает **только из кэша**. Фоновый воркер периодически загружает данные из БД в кэш. Приложение никогда не ходит в БД.

## Чтение

1. Приложение идёт в кэш → получает данные
2. Всё. В БД не ходит никогда.

## Наполнение кэша

Фоновый процесс (воркер, крон) периодически:
1. Читает данные из БД
2. Кладёт в кэш

**Плюсы:**
- минимальный latency на чтение — только кэш, никаких походов в БД
- приложение максимально простое — знает только про кэш

**Минусы:**
- данные могут быть неактуальны (воркер ещё не обновил)
- нужен фоновый процесс для синхронизации
- если данные меняются часто — кэш постоянно устаревает

**Compaction при записи:** если пишем асинхронно батчами, можно использовать compaction — из нескольких записей одного ключа оставляем только последнюю. Экономим на записи.

**Связь:**
- подходит для данных, которые меняются редко (конфигурации, справочники)
- не подходит для часто меняющихся данных (баланс пользователя)
- compaction связан с [[High throughput приложения]] подходами (батчинг)
