**Суть:** Нет отдельного балансировщика. Клиентский код сам знает обо всех инстансах и сам решает, куда отправить запрос.

**Плюсы:**
- нет лишнего сетевого хопа → ниже latency
- нет единой точки отказа (балансировщик не может упасть, его нет)

**Минусы:**
- клиент усложняется логикой балансировки
- при добавлении/удалении инстанса нужно доносить конфигурацию до всех клиентов
- плохо с эксплуатацией

**Итог:** хорошо по перформансу, плохо по удобству сопровождения. Поэтому чаще ставят отдельный балансировщик.

**Связь:**
- альтернатива серверной балансировке (load balancer)
- удобство сопровождения vs производительность — классический трейдофф
- [[low latency приложения|low latency]] — нет хопа через LB
