**Суть:** Атака, при которой злоумышленник намеренно запрашивает данные, которых нет в кэше. Каждый запрос — miss → летит в БД.

**Как работает:** хакер находит ключи, которые гарантированно дают miss (несуществующие пользователи, невалидные ID). Шлёт массу таких запросов → кэш бесполезен → вся нагрузка на БД → БД ложится.

**Почему опасно:** многие проектируют систему так, что кэш держит нагрузку БД. Без кэша БД не справляется. Cache miss attack пробивает кэш насквозь.

**Защита — кэширование ошибок (negative caching):**
- запросили user 5 → его нет в БД → кэшируем **отсутствие** ("user 5 не существует")
- следующий запрос user 5 → кэш отвечает "не существует", в БД не идём

**Главное правило:** кэш должен ускорять, а не держать нагрузку. В идеале БД должна справляться и без кэша. Кэш — ускорение, не костыль.

**Связь:**
- кэширование ошибок — защита от cache miss attack
- связан с формулой эффективности кэша — при высоком miss rate кэш вреден
- rate limiting на [[Reverse Proxy]] — ещё одна линия защиты
