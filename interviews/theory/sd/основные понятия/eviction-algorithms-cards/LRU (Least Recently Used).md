**Суть:** Вытесняем элемент, к которому **дольше всего не обращались**. Логика: если давно не трогали — наверное, уже не нужен.

**Пример:**
```
Обращения: A, B, C, D, A, B, E
Кэш (размер 4): [A, B, C, D]
Обратились к A → A становится "свежим"
Обратились к B → B становится "свежим"
Пришёл E, место кончилось → вытесняем C (самый давний)
```

**Почему самый популярный:**
- простая идея, понятная интуитивно
- хорошо работает на большинстве реальных нагрузок
- закрывает 80–90% задач кэширования

**Реализация:** обычно двусвязный список + хэш-таблица. O(1) на вставку, удаление, обращение.

**Минус:** одно случайное обращение к холодному ключу делает его "свежим". Один запрос — и он вытесняет по-настоящему нужные данные.

**Связь:**
- самый популярный алгоритм — по умолчанию на собеседовании
- [[MRU (Most Recently Used)]] — зеркальная противоположность
- [[LRU-K]] — улучшение, учитывающее K последних обращений
- [[SLRU (Segmented LRU)]] — многоуровневый LRU
