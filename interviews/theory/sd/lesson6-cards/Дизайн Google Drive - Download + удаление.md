Как скачивать файлы и как безопасно удалять с учётом дедупликации.

## Скачивание (Download)

```
Client → Nginx (LB) → Downloader Service → PostgreSQL (метаданные)
                                          → S3 (чанки)
                                          → Client
```

**Алгоритм:**

1. Клиент запрашивает файл по file_id
2. Downloader идёт в PostgreSQL → проверяет `ready`
3. Если `ready = false` → отбиваем запрос (файл не загружен полностью)
4. Если `ready = true` → достаём все chunk_hash из chunk_per_file, отсортированные по index
5. По каждому chunk_hash → идём в S3 → достаём чанк → разжимаем
6. Отдаём клиенту последовательно

**Восстановление скачивания:** клиент может на своей стороне (local storage или кэш) помечать, какие чанки уже скачал. При обрыве — запрашивает только недостающие.

## Удаление: проблема дедупликации

На один чанк могут ссылаться несколько файлов (дедупликация). Нельзя просто удалить чанк из S3 при удалении файла — другие файлы сломаются.

**Наивный подход — счётчик ссылок:** при добавлении +1, при удалении -1. Когда 0 → удаляем. **Проблема:** race condition. Удалил файл → счётчик стал 0 → пошёл удалять из S3. Но между "стал 0" и "удалил" другой пользователь загрузил файл с таким же чанком → счётчик стал 1. А воркер удалит чанк. Потеря данных.

## Решение: удаляем от обратного

**Подход Балуна:**

1. При удалении файла → удаляем записи из PostgreSQL (file, chunk_per_file). **S3 не трогаем.**
2. Периодически (раз в день/неделю) **воркер** проходит по S3:
   - Берёт chunk_hash
   - Проверяет: есть ли хоть одна ссылка на этот чанк в chunk_per_file?
   - Нет ссылок → удаляем из S3
   - Есть ссылки → оставляем

**Почему это безопасно:** воркер ходит в "тихое" время (ночью). Проверяет актуальное состояние базы. Если между проверкой и удалением кто-то добавил ссылку — воркер увидит это и не удалит.

**Минус:** "мёртвые" чанки живут в S3 до следующего прохода воркера. Платим за хранение. Но это дешевле, чем потерять данные.

## Удаление из PostgreSQL

1736 RPS на запись ≈ столько же потенциально на удаление. Балун: "Это не такая большая нагрузка. Пойти по chunk_per_file, поискать, пойти file, поискать, удалить — ок."

Можно удалять синхронно (пользователь нажал "удалить" → сразу удалили из PostgreSQL). Можно асинхронно (пометили флагом → воркер потом удалит). Балун за синхронное — нагрузка позволяет, а при пометке "удалённый" данные копятся.
