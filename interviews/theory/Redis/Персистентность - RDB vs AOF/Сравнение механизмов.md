Хотя Redis работает в RAM, он предоставляет механизмы для сохранения данных на диск, чтобы восстановить состояние после перезагрузки или сбоя.

| Характеристика | RDB | AOF |
| :--- | :--- | :--- |
| **Компактность** | Высокая (бинарный файл) | Низкая (текстовый лог команд) |
| **Скорость старта** | Высокая | Низкая (нужно проиграть все команды) |
| **Сохранность** | Возможны потери за интервал | Максимальная (зависит от настроек fsync) |

⚠️  На практике рекомендуется использовать **гибридный подход** (RDB + AOF). При этом стоит помнить: если включены оба режима, при перезагрузке Redis будет использовать **AOF**, так как в нем содержится более полная версия данных. Для критических данных важно понимать настройки `fsync`: частота сброса данных из буфера ОС на физический диск напрямую влияет на баланс между скоростью и риском потери.
