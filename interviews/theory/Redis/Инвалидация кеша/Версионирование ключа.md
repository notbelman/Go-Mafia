Вместо удаления — меняем версию в ключе. Старый ключ просто истекает по TTL.
```go
// Версия хранится в БД или в отдельном ключе Redis
version := getVersion("user:123") // v3

key := fmt.Sprintf("user:123:v%d", version) // "user:123:v3"
redis.Set(ctx, key, data, 1*time.Hour)

// При обновлении — инкрементим версию
incrVersion("user:123") // v3 → v4
// Теперь ключ "user:123:v3" никто не запрашивает, умрёт по TTL
```

- ✅ Нет гонки при удалении — старый ключ просто игнорируется
- ✅ Можно откатиться к старой версии
- ❌ Старые ключи занимают память до истечения TTL

```
С обычным Delete:
Pod 1: UPDATE БД → Del("user:123")
Pod 2: UPDATE БД → Set("user:123", старые данные)  ← прочитал из БД между UPDATE и Del
Итог: в кэше лежат устаревшие данные, Del уже отработал

С версионированием:
Pod 1: UPDATE БД → incrVersion → v4
Pod 2: UPDATE БД → incrVersion → v5
Pod 1: Set("user:123:v4", ...) ← никто не читает, все ходят за v5
Pod 2: Set("user:123:v5", ...) ← актуальные данные
```
