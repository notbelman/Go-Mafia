Паттерн управления распределёнными транзакциями: набор последовательных локальных транзакций, где каждая обновляет свою БД и публикует событие для следующего шага.

## Зачем

В микросервисах у каждого сервиса своя БД — ACID-транзакция не может охватить несколько сервисов. Saga решает: как сделать атомарный бизнес-процесс (Оплата -> Склад -> Доставка) без единой транзакции.

## Как работает

Ошибка на любом этапе — выполняются компенсирующие действия для всех успешных шагов.
Компенсация — не удаление записи, а логический откат (возврат средств, а не удаление транзакции).

Каждый шаг атомарен внутри своего сервиса.
Обработчики идемпотентны — событие может прийти дважды (at-least-once).

## ACID -> BASE

Saga не даёт мгновенной согласованности. Система в промежуточном состоянии, пока все шаги не завершены. Eventual consistency — данные согласуются со временем.
