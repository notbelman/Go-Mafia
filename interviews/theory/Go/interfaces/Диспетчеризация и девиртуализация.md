- **статическая диспетчеризация**: компилятор знает тип → прямой вызов метода (compile-time)
- **динамическая диспетчеризация**: тип неизвестен → вызов через itab в рантайме (оверхед: прыжок по указателю)
- **девиртуализация**: явный type assertion + вызов на конкретном типе → обходим itab
- бенчмарк: статическая ≈ девиртуализация, динамическая **заметно медленнее**
- девиртуализация — только для горячих циклов, и только если **100% уверены** в типе

---

## Статическая диспетчеризация

```go
type Value struct{ N int }
func (v Value) Add(x int) int { return v.N + x }

v := Value{N: 10}
v.Add(5)  // компилятор ЗНАЕТ: это Value.Add → прямой вызов
```

Компилятор на этапе компиляции точно знает, какую функцию вызвать. ^dispatch-static-def

## Динамическая диспетчеризация

```go
type Adder interface { Add(int) int }

var a Adder = Value{N: 10}
a.Add(5)  // компилятор НЕ знает: что за тип внутри? → itab → fun[0] → вызов
```

Рантайм: прыгаем в `tab.fun[0]` → получаем адрес функции → вызываем с `data` как receiver. ^dispatch-dynamic-mechanism

Дополнительный уровень косвенности — overhead по сравнению со статическим вызовом. ^dispatch-dynamic-overhead

## Девиртуализация

Type assertion возвращает конкретный тип → дальше вызов без itab. ^devirt-def

```go
var a Adder = getAdder()  // динамический тип неизвестен

// Вместо a.Add(5) — динамическая диспетчеризация:
a.(*Value).Add(5) // если getAdder() вернул Value → ок 
				// если вернул OtherValue → паника
// Компилятор знает тип → статическая диспетчеризация
```

Безопаснее с проверкой:
```go
if v, ok := a.(*Value); ok { 
	v.Add(5) // статическая диспетчеризация 
}
```

Девиртуализацию применяют только в горячих циклах, и только при 100% уверенности в типе — иначе паника. ^devirt-when

## Как написать интерфейс руками (суть itab)

```go
const (
    areaIdx = 0
    perimIdx = 1
)

type MyInterface struct {
    methods [2]func() float64  // "таблица виртуальных функций"
}

func NewInterface(s Square) MyInterface {
    return MyInterface{
        methods: [2]func() float64{
            s.Area,      // биндим метод с ресивером
            s.Perimeter, // биндим метод с ресивером
        },
    }
}

func (i MyInterface) Area() float64 { return i.methods[areaIdx]() }
// ↑ прыжок в массив → по указателю → вызов = динамическая диспетчеризация
```

Ручная реализация itab: массив function pointers, биндинг метода с ресивером, косвенный вызов через индекс. ^itab-manual-impl

## Бенчмарк

```
BenchmarkStatic         ~0.3 ns/op   // прямой вызов
BenchmarkDynamic        ~1.8 ns/op   // через itab
BenchmarkDevirtualized  ~0.3 ns/op   // type assertion + прямой вызов
```

Статическая ≈ девиртуализация (~0.3 ns/op). Динамическая — ~1.8 ns/op, оверхед из-за косвенности. ^dispatch-benchmark
