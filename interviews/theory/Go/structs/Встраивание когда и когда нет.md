- **НЕ встраивать**: если раскрытие методов нарушает инкапсуляцию (мьютекс → Lock/Unlock наружу)
- **встраивать**: простые враперы, где методы просто проксируют без логики
- в Go **нет наследования** — есть композиция через встраивание
- под капотом наследование в других языках тоже = композиция (базовая часть внутри объекта)

---

## Плохой пример: мьютекс

```go
type SafeMap struct {
    sync.Mutex                    // встроили мьютекс
    data map[string]string
}

m := SafeMap{data: make(map[string]string)}
m.Lock()   // ✅ удобно, лаконично

// НО: пользователь тоже может вызвать:
m.Lock()
// ... забыл Unlock → deadlock
// Lock/Unlock — детали реализации, не API
```

Встраивание `sync.Mutex` раскрывает `Lock/Unlock` как публичное API — пользователь может вызвать `Lock()` и забыть `Unlock()`, что приводит к дедлоку. ^emb-mutex-bad

## Правильно: явная композиция

```go
type SafeMap struct {
    mu   sync.Mutex              // явное поле, не встроенное
    data map[string]string
}

func (m *SafeMap) Set(k, v string) {
    m.mu.Lock()
    defer m.mu.Unlock()
    m.data[k] = v
}

// m.Lock()  // ❌ не скомпилируется — mu не экспортирован
```

Явное поле с маленькой буквы (`mu`) скрывает `Lock/Unlock`. Пользователь работает только через `Set/Get`. ^emb-mutex-good

## Хороший пример: врапер

```go
// Методы просто проксируют без логики — встраивание уместно
type MyWriter struct {
    io.WriteCloser               // встроили интерфейс
}

// Без встраивания пришлось бы писать:
// func (w *MyWriter) Write(p []byte) (int, error) {
//     return w.wc.Write(p)      // просто проксирует
// }
// func (w *MyWriter) Close() error {
//     return w.wc.Close()       // просто проксирует
// }
```

Если методы **только проксируют** — встраивание убирает бойлерплейт. ^emb-wrapper-good

## Наследования нет — есть композиция

```go
type Person struct{ Name string }
func (p Person) Intro() string { return p.Name }

type Woman struct {
    Person                       // не наследование!
    Title string                 // расширение
}
func (w Woman) Intro() string {  // перекрытие, не override
    return w.Title + " " + w.Name
}
```

В большинстве языков наследование под капотом тоже = базовая часть внутри объекта. Go просто делает это явным. ^emb-no-inheritance

## Критерий решения

Спроси себя: **хочу ли я, чтобы ВСЕ методы встроенного типа были доступны снаружи?** Если да → встраивай. Если нет (есть «опасные» методы) → явная композиция. ^emb-decision-criterion
