- **наивно:** массив пар — поиск O(n). Direct addressing (ключ = индекс) — O(1), но разреженный массив
- **хэш-функция** — преобразование из большого множества в маленькое (ключ → индекс бакета)
- 4 свойства хорошей: **эффективная, необратимая, детерминированная, равномерно распределяющая**
- **коллизия** неизбежна: большое множество → маленькое. Два способа борьбы: цепочки и открытая адресация
- **load factor** = count / buckets. При >0.6–0.7 → переиндексация (не просто копирование — пересчёт хэшей)

## Наивные подходы

**Массив пар** — храним `{key, value}`. Поиск O(n) — в худшем случае проходим весь массив. ^ht-naive-array

**Direct addressing** — ключ = индекс массива. Поиск O(1), но если 5 пользователей с max ID = 1_000_000, массив на миллион элементов почти пуст. ^ht-direct-addressing

**Хэш-функция** — решает проблему: преобразует ID из большого множества (миллион) в маленькое (размер массива). Простейшая: `key % capacity`. ^ht-hash-function

## 4 свойства хорошей хэш-функции

1. **Эффективная** — вычисление не должно занимать много времени
2. **Необратимая** — нельзя по хэшу восстановить ключ (не шифрование!)
3. **Детерминированная** — один ключ → всегда один результат
4. **Равномерно распределяющая** — не должна всё складывать в один бакет

## Коллизия

Разные ключи → одинаковый хэш. Неизбежна: из большого множества в маленькое. ^ht-collision-inevitable

```
key=8:       8 % 5 = 3
key=1000003: 1000003 % 5 = 3  ← коллизия!
```

^e29387

Коллизий нет только если входное множество меньше выходного (крайне редко). ^ht-collision-example

## Load factor и переиндексация

`load_factor = count / buckets`. При >0.6–0.7 → переиндексация: выделить ×2 памяти, **пересчитать хэш** каждого элемента (индекс бакета зависит от capacity). ^ht-load-factor-formula

Просто копировать нельзя — элементы окажутся не в тех бакетах. ^ht-reindex-why
