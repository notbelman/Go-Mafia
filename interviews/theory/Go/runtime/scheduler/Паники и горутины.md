- паника долетает до верхушки стека горутины → крашит **весь процесс**
- перехватить панику из другой горутины **нельзя** (у каждой свой стек, раскручивается один)
- паттерн: recover на верхушке стека обработчика (TCP/HTTP), чтобы одна паника не убила весь сервер
- `log.Println` синхронизирован (горутины не перемешивают вывод), `fmt.Println` — нет

## Паника = раскрутка одного стека

У каждой горутины свой стек. Паника раскручивает стек **конкретной** горутины. ^panic-own-stack

Если долетает до верхушки и никто не перехватил (`recover`) — крашится весь процесс. Все остальные горутины (тысячи конкурентных запросов) отхватят ошибку. ^panic-crash-all

## Перехват паники другой горутины
```go
// НЕ РАБОТАЕТ — перехватить панику из другой горутины невозможно
func main() {
    defer func() { recover() }()  // этот recover бесполезен
    go func() {
        panic("boom")  // раскручивается стек ЭТОЙ горутины
    }()                 // main горутина — другой стек
}
```

Перехватить панику из другой горутины **невозможно** — у каждой горутины свой изолированный стек.

## Паттерн: recover в обработчике

```go
func handleConn(conn net.Conn) {
    defer func() {
        if r := recover(); r != nil {
            log.Printf("recovered: %v", r)
        }
        conn.Close()
    }()
    // обработка запроса...
    // если паника — этот клиент получит ошибку,
    // но остальные 10,000 запросов продолжат работу
}
```

Стандартная практика для TCP/HTTP серверов: на верхушке стека каждого обработчика — `recover`. Один клиент получит 500, но сервер не упадёт.

## Паттерн: never-exit (переподъём фоновой задачи)

```go
func neverExit(name string, action func()) {
    defer func() {
        if r := recover(); r != nil {
            log.Printf("%s crashed: %v, restarting", name, r)
            go neverExit(name, action)  // НЕ рекурсия — новая горутина, новый стек
        }
    }()
    action()
}
```

Это **не рекурсия**: `go neverExit(...)` запускает новую горутину с отдельным стеком.

## log.Println vs fmt.Println

`log.Println` синхронизирован — сообщения из разных горутин не перемешиваются. ^log-synchronized

`fmt.Println` — нет, строки могут перемешаться при конкурентной записи. ^fmt-not-synchronized
