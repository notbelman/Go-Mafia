- M = поток ОС. Реально выполняет код на CPU. Может быть больше чем GOMAXPROCS (из-за syscalls)
- состояния: spinning (ищет работу) → running → syscall → parked (спит)
- **g0 — служебный стек:** каждый M имеет специальную горутину g0. **стек** для планировщика(schedule, findrunnable), GC, создания горутин, создания новых горутин, сборки мусора, роста стеков. Переключение: пользовательская G ↔ g0.
- лимит M: 10000 (`runtime.SetMaxThreads`), реально активных ≤ GOMAXPROCS
- новый M создаётся когда: все заняты + есть свободный P с работой + нет запаркованных M

[[GMP Flashcards - machine]]

**Структура runtime.m:**
```
├── g0         — служебная горутина (стек для scheduler, GC)
├── curg       — текущая пользовательская G (или nil)
├── p          — привязанный P (или nil)
├── nextp      — P который заберёт после разблокировки
├── spinning   — флаг "кручусь в поиске работы"
├── blocked    — заблокирован на syscall
├── park       — семафор для парковки
└── id         — уникальный ID потока
```
^m-struct-fields

**g0 — служебный стек:** каждый M имеет специальную горутину g0. ^m-g0-def

Её стек используется для: работы планировщика (`schedule`, `findrunnable`), создания новых горутин, сборки мусора, роста стеков. ^m-g0-usages

Переключение между пользовательской G и g0 происходит при каждом вызове планировщика. ^m-g0-switch

**Состояния M:**

**spinning** — ищет работу (крутится в цикле, GOMAXPROCS/2 раз), не паркуется сразу, чтобы быстро подхватить G. ^m-state-spinning

**running** — выполняет G на привязанном P. ^m-state-running

**syscall** — заблокирован в системном вызове, P отвязан и отдан другому M. ^m-state-syscall

**parked** — нет работы, спит; проснётся когда появится G. ^m-state-parked

**Лимиты:** максимум 10000 M по умолчанию (`runtime.SetMaxThreads(n)`). ^m-limit

M создаётся при блокирующем syscall, после завершения паркуется в thread pool для переиспользования. Реально активных M ≤ GOMAXPROCS. ^m-thread-pool

**Когда создаётся новый M:** все текущие M заняты + есть свободный P с работой + нет запаркованных M в thread pool. ^m-creation-condition

## Связь
- [[G (Goroutine)]] — что M выполняет
- [[P (Processor)]] — ресурсы, к которым M привязывается
- [[Handoff]] — когда M уходит в syscall, P отдаётся другому M
