- GMP:
	- G (Goroutine) — задача для выполнения (стек + регистры)
	- M (Machine)   — поток ОС, реально выполняет код на CPU
	- P (Processor) — логический процессор: очередь G + mcache + ресурсы
- эволюция: 1 поток → M:N + глобальная очередь (contention) → **шардирование очереди (на P) = GMP**
- M без P не может выполнять Go-код
- G — миллионы, P = GOMAXPROCS (default NumCPU), M — до 10000, активных ≤ GOMAXPROCS
- планировщик = код (не отдельный поток), выполняется на каждом M

GMP — модель планировщика Go.
[[GMP Flashcards - overview]]
## Эволюция модели

**Модель 1 — один поток, глобальная очередь.** Один M, все G в одной очереди. Работает, но не использует многоядерность. ^gmp-model1

**Модель 2 — M:N, глобальная очередь.** N горутин на M потоков. Проблема: одна очередь на всех, защищена мьютексом. Каждый M, чтобы взять горутину, должен захватить мьютекс → пока один M держит мьютекс, остальные стоят и ждут (contention). Чем больше потоков, тем хуже. ^gmp-model2-contention

Lock-free тоже не спасает — инвалидация кэш-линий. ^gmp-model2-lockfree

**Модель 3 — GMP (шардирование).** Нарезали глобальную очередь на локальные. Как шардирование БД — та же концепция. ^gmp-model3-sharding

## Компоненты

```
G (Goroutine) — задача для выполнения (стек + регистры)
M (Machine)   — поток ОС, реально выполняет код на CPU
P (Processor) — логический процессор: очередь G + mcache + ресурсы
```
^gmp-components

**Планировщик — не отдельный поток.** Это код, который выполняется на каждом M. Выбирает следующую горутину, переключает контекст. ^gmp-scheduler-not-thread

## Как связаны

```
    G1 G2 G3         G4 G5 G6
       │                │
       ▼                ▼
   ┌───────┐        ┌───────┐
   │  P0   │        │  P1   │      P:M = 1:1
   └───┬───┘        └───┬───┘
       │                │
       ▼                ▼
   ┌───────┐        ┌───────┐
   │  M0   │        │  M1   │
   └───────┘        └───────┘
```
^gmp-diagram

Соотношение P:M = 1:1 в нормальной ситуации (когда нет syscall). M без P не может выполнять Go-код. ^gmp-p-m-ratio

## Количество

```
G — миллионы (ограничено памятью)
P — GOMAXPROCS (по умолчанию = NumCPU)
M — до 10000 (runtime.SetMaxThreads), реально активных ≤ GOMAXPROCS
```
^gmp-counts
