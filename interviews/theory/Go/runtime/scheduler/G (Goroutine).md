- структура runtime.g: стек (начинается с **2KB**, растёт до 1GB), сохранённые регистры (gobuf), статус, ID
- при переключении: регистры сохраняются в стек, меняются stack pointer / base pointer / Program Counter(следующая инструкция). **Стек не копируется**
- завершённые G не уничтожаются → пул gFree для переиспользования
- goid **не публичный** — Go не хочет чтобы код зависел от ID горутины (антипаттерн, используй context)
- жизненный цикл: Runnable → Running → Waiting → Running → Dead → пул gFree

**Структура runtime.g:**
```
├── stack        — начало и конец стека (2KB → до 1GB / 512MB)
├── stackguard0  — для проверки переполнения стека
├── sched        — gobuf: сохранённые регистры (sp, pc, bp...)
├── status       — состояние (runnable, running, waiting, dead...)
├── goid         — уникальный ID (не доступен публично)
├── startpc      — адрес функции горутины
├── gopc         — откуда вызвали go func()
├── preempt      — флаг "нужно вытеснить"
├── m            — на каком M выполняется (или nil)
├── waitsince    — когда начала ждать (для pprof)
└── waitreason   — причина ожидания ("chan receive", "sleep"...)
```
^g-struct-fields

[[GMP Flashcards - goroutine]]
**Стек — 2KB vs 2-8MB:** поток ОС получает 2-8MB стека сразу. ^g-stack-os-thread

Горутина начинает с 2KB и растёт динамически. ^g-stack-initial

Максимальный размер стека горутины: 1GB (64-bit) / 512MB (32-bit). ^g-stack-max

**Контекст-свитчинг:** при переключении регистры пушатся в стек горутины. ^g-switch-registers

При возобновлении — поднимаются обратно. Stack pointer и base pointer переключаются на стек другой горутины. ^g-switch-sp-bp

Стек не копируется — просто меняются указатели. ^g-stack-no-copy

**Жизненный цикл:**
```
go func() → Runnable → Running → Waiting (chan/mutex/IO)
                ↑                      │
                └────── событие ───────┘
            Running → Dead → пул gFree → переиспользование
```
^g-lifecycle

Завершённые G не уничтожаются — помещаются в пул `gFree` и переиспользуются при создании новых горутин. Это снижает аллокацию и давление на GC. ^g-gfree-pool

**Почему goid не публичный:** Go не хочет чтобы код зависел от ID горутины. Это антипаттерн — используйте context для передачи данных. ^g-goid-private

Поля `waitsince` и `waitreason` в структуре g используются профилировщиком (pprof) для диагностики заблокированных горутин. ^g-wait-pprof

Поле `preempt` — флаг асинхронного вытеснения. Если выставлен, горутина будет вытеснена при следующей безопасной точке. ^g-preempt-flag
