- tracing ищет **живые** объекты (ref counting ищет мёртвые) — семантически противоположные подходы, все что не живые - мертвые
- STW: остановить мутаторы → обойти граф от root set → пометить живые → удалить непомеченные
	- **мутаторы** - потоки которые выполняют что-то, мутирую память
	- **root set** - стеки всех горутин + глобальные переменные + runtime-структуры, место, **откуда начинаются все цепочки ссылок на heap**
- **Проблема**: Чем больше куча → тем больше граф → тем дольше обход → тем дольше паузы.
- **Sweep (Go):** освободить белые (непомеченные) объекты. Быстро, но heap остаётся фрагментированным.
- **Copying:** перенести живые объекты в новое место компактно, старое освободить целиком. Дольше, но нет фрагментации.

[[GC Flashcards - tracing_stw]]
## Идея

В отличие от ref counting, tracing ищет **живые** объекты, а не мёртвые. Всё, до чего не дошли — мусор. ^tracing-idea

**Мутаторы** — потоки, выполняющие бизнес-логику (называются так, потому что мутируют память: создают объекты, изменяют ссылки). ^mutators

## Алгоритм (простейший, STW)

```
1. Остановить все мутаторы (Stop the World)
2. Обойти граф ссылок от root set (стеки + глобальные)
   - можно параллельно, несколькими потоками
3. Пометить все живые объекты
4. Непомеченные = мусор → удалить
```

**Root set:** стеки всех горутин + глобальные переменные. Оттуда начинаются все цепочки ссылок в heap. ^root-set

Фаза маркировки может выполняться **параллельно несколькими потоками** внутри STW. ^mark-parallel

## Фаза очистки: Sweep vs Copying

**Sweep (Go):** освободить белые (непомеченные) объекты. Быстро, но heap остаётся фрагментированным. ^sweep

**Copying:** перенести живые объекты в новое место компактно, старое освободить целиком. Дольше, но нет фрагментации. ^copying

## Проблема STW

Чем больше куча → тем больше граф → тем дольше обход → тем дольше паузы. Для больших приложений неприемлемо: циклические спайки latency на время каждой сборки. ^stw-problem

## Как уменьшить паузы

**Поколения:** сканировать не всю кучу, а только молодые объекты (чаще умирают). ^reduce-generations

**Concurrent GC:** не останавливать мутаторы, работать параллельно с ними. Go пошёл по пути concurrent (без поколений). ^reduce-concurrent
