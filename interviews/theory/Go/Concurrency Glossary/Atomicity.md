- **Атомарность** — операция выполняется **целиком или не выполняется вообще**. Промежуточное состояние невидимо ^atom-def
- **Три уровня**: инструкция CPU (`atomic.Add`), критическая секция (mutex), транзакция (ACID-A) ^atom-levels
- `i++` **НЕ атомарно** — это load → inc → store. Классический вопрос на собесе ^atom-increment

---

```go
// НЕ атомарно (3 операции)
i++

// Атомарно (уровень CPU)
atomic.AddInt64(&i, 1)

// Атомарно (уровень КС)
mu.Lock(); i++; mu.Unlock()
```
^atom-examples

## Уровни

**CPU**: `atomic.AddInt64` — одна инструкция, неделима аппаратно ^atom-cpu

**Критическая секция**: `mu.Lock(); a++; b++; mu.Unlock()` — другие горутины видят **либо** старое состояние обоих, **либо** новое ^atom-cs

**Транзакция**: BEGIN → UPDATE → UPDATE → COMMIT — вся группа атомарна (ACID-A) ^atom-tx

## Собес: "является ли X атомарным?"

Ответ почти всегда **"нет"**, если это не `atomic.*` или не защищено мьютексом. Даже присваивание `interface{}` неатомарно (два слова: type + data). ^atom-interview
