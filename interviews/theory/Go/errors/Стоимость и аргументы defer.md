- аргументы defer **вычисляются сразу** — в момент регистрации, не в момент выполнения ^defer-args-eval
- замыкание (closure) в defer **захватывает переменную по ссылке** — видит финальное значение ^defer-closure-ref
- стоимость defer: до Go 1.14 — **~50 ns**, с Go 1.14 — **~0 ns** (open-coded defer) ^defer-cost
- open-coded defer — компилятор инлайнит вызов, без стека defer-записей ^defer-open-coded
- **ограничения open-coded defer**: > 8 defer'ов в функции ИЛИ defer внутри цикла → откат к старому механизму (~50 ns) ^defer-open-coded-limit
- в горячих циклах defer **внутри** тела цикла всё ещё может быть заметен ^defer-hot-loop
- **порядок при return**: (1) вычисляется выражение return → присваивается в результат, (2) выполняются defer'ы, (3) функция возвращает результат вызывающему ^defer-return-order
- `recover()` без паники возвращает `nil` ^recover-no-panic

## Аргументы вычисляются сразу

```go
func main() {
    x := 10
    defer fmt.Println(x)  // x вычисляется СЕЙЧАС → запоминается 10
    x = 20
    fmt.Println(x)
}
// 20
// 10  ← defer получил x=10, а не 20
```

Аргумент `x` передаётся в `fmt.Println` в момент регистрации defer — дальнейшие изменения `x` не видны. ^defer-args-example

## Замыкание — захват по ссылке

```go
func main() {
    x := 10
    defer func() {
        fmt.Println(x)  // замыкание видит переменную x по ссылке
    }()
    x = 20
    fmt.Println(x)
}
// 20
// 20  ← замыкание видит финальное значение x
```

Разница: `defer f(x)` — значение копируется сразу. `defer func() { f(x) }()` — замыкание захватывает **переменную**, не значение. ^defer-closure-example

## Классическая ловушка: defer в цикле

```go
for i := 0; i < 3; i++ {
    defer fmt.Println(i)  // аргумент вычисляется сразу
}
// 2
// 1
// 0  ← LIFO + каждый defer запомнил своё значение i
```

```go
for i := 0; i < 3; i++ {
    defer func() {
        fmt.Println(i)  // замыкание захватывает переменную i
    }()
}
// 3
// 3
// 3  ← все замыкания видят финальное i=3 (после выхода из цикла)
```

^defer-loop-trap

## Стоимость defer

**До Go 1.14:**

```
BenchmarkDefer    ~50 ns/op
```

Каждый defer создавал запись в heap-allocated linked list — аллокация + запись + вызов при выходе. ^defer-cost-old

**С Go 1.14 (open-coded defer):**

```
BenchmarkDefer    ~0 ns/op (инлайн)
```

Компилятор для простых случаев генерирует код вызова прямо в теле функции (перед return), без создания defer-записей. Накладные расходы практически нулевые. ^defer-cost-new

**Ограничения open-coded defer — когда откатывается к старому механизму:**

1. В функции **> 8 defer'ов** — bitmask только 8 бит
2. defer **внутри цикла** — количество вызовов неизвестно на этапе компиляции
3. Произведение (кол-во defer × кол-во return) **> 15** — слишком раздует бинарник

При откате — снова ~50 ns/op, heap-allocated linked list. ^defer-open-coded-fallback

## Порядок выполнения при return (ВАЖНО!)

```go
func count() (result int) {
    defer func() {
        result++
    }()
    return 0
}
// count() == 1
```

**Три шага — именно в таком порядке:**

```
1. return 0       → result = 0  (вычисляется выражение, присваивается в именованный результат)
2. defer          → result++    (выполняются все defer'ы в LIFO порядке)
3. фактический возврат → возвращается result = 1
```

defer выполняется **ПОСЛЕ** присваивания результата return, но **ДО** фактического возврата из функции. Поэтому defer-замыкание может изменить именованный результат. ^defer-return-order-detail

**Ещё пример — подмена ошибки:**

```go
func ReadFile(path string) (err error) {
    f, err := os.Open(path)
    if err != nil {
        return err
    }
    defer func() {
        closeErr := f.Close()
        if err == nil {       // основная операция прошла ок
            err = closeErr    // подменяем на ошибку закрытия
        }
    }()
    // ... работа с файлом
    return nil  // err = nil, потом defer проверит и может подменить
}
```

Порядок: `return nil` → `err = nil` → defer проверяет `err == nil` → если Close() упал, подменяет `err`. ^defer-return-error-replace

## Именованные возвращаемые значения

defer-замыкание имеет доступ к именованным возвращаемым значениям и может их изменить **после** return. Это работает потому что замыкание захватывает переменную по ссылке, а именованный результат — это обычная переменная в scope функции. ^defer-named-return

## recover() без паники

```go
func main() {
    defer func() {
        r := recover()
        fmt.Println(r)  // <nil> — паники не было
    }()
    fmt.Println("ok")
}
// ok
// <nil>
```

Если паники не было, `recover()` просто возвращает `nil`. С Go 1.21+ это можно отличить от `panic(nil)`, который оборачивается в `*runtime.PanicNilError`. ^recover-no-panic-example

## Сводка

|Ситуация|Что видит defer|
|---|---|
|`defer f(x)`|Значение x **на момент регистрации**|
|`defer func() { f(x) }()`|Значение x **на момент выполнения** (замыкание)|
|`defer func() { result++ }()`|Именованный возврат — может изменить|
