- **null-terminated** (C) — `\0` в конце. Плюс: нет доп. памяти. Минус: `len()` за O(n)
- **Pascal strings** — поле size рядом. `len()` за O(1), +4-8 байт памяти
- **immutable** (Go, Java, JS) — конкатенация создаёт новую строку. Безопасность, concurrency
- **mutable** (C++) — растёт как slice (ptr + len + cap). Быстрая модификация, но гонки данных
- **SSO** (C++) — строки <16 байт хранятся в полях ptr+cap, без аллокации в heap
- **COW** (Copy-on-Write) — шаринг при чтении, копирование при записи (домашка Deep Go)

---

## Null-terminated (C)

```
['h','e','l','l','o','\0']
```
`\0` (байт с кодом 0, не символ '0') — признак конца. Плюс: 0 доп. памяти. Минус: `strlen()` = O(n), нужно добежать до нулика. ^null-terminated

## Pascal strings

```
[size=5]['h','e','l','l','o']
```
Отдельное поле size. `len()` = O(1). Минус: +4 или +8 байт. ^pascal-strings

## Immutable (Go, Java, C#, JavaScript)

Конкатенация: аллокация на сумму длин + копирование обеих строк. ^immutable-concat-cost

Плюсы: безопасный sharing, concurrency без блокировок, ключи в map. Минус: O(n²) при конкатенации в цикле. ^immutable-tradeoffs

## Mutable (C++)

Как slice: ptr + len + cap. Растёт с амортизированной O(1). Плюс: модификация in-place. Минус: гонки данных, нельзя безопасно шарить. ^mutable-tradeoffs

## SSO (Small String Optimization)

В C++: если строка ≤16 байт, данные хранятся прямо в полях ptr и cap (побайтово). Определяется по size: если < порога → данные внутри структуры, иначе → ptr в heap. В Go **не нужно** — есть escape analysis. ^sso-cpp

## COW (Copy-on-Write)

Несколько объектов шарят один буфер. При изменении — копия перед записью. Ref counting для отслеживания. Домашка Deep Go: реализовать COW буфер с `Clone()` и `Close()`. ^cow

## Linked list строки (Erlang, Haskell)

Каждый символ — узел списка. Вставка/удаление O(1). Итерация и хранение неэффективны. ^linked-list-strings
