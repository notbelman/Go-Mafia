- underlying array на стеке до **64 КБ**, больше → heap (массив — до 10 МБ)
- при реаллокации (append с переполнением) — **всегда heap**
- хак: массив до 10 МБ на стеке → `arr[:]` → underlying array на стеке даже >64 КБ
- `io.Reader` принимает буфер снаружи → буфер может **остаться на стеке**, переиспользоваться

[[slice Flashcards - allocation]]
## Порог: 64 КБ

```go
s1 := make([]byte, 65_536)   // 64 КБ → стек ✅
s2 := make([]byte, 65_537)   // 64 КБ + 1 → heap
```

Порог для underlying array слайса — **64 КБ**. Для массива (`[N]T`) — **10 МБ**. Разница в ~150 раз. ^slice-alloc-threshold

## Реаллокация → всегда heap

```go
s := make([]int, 0, 3)  // маленький, на стеке
s = append(s, 1, 2, 3)  // влезло, всё ещё стек
s = append(s, 4)         // реаллокация → новый array в heap
```

Даже если исходный срез был на стеке — после реаллокации (`append` с переполнением cap) новый underlying array всегда аллоцируется в **heap**. ^slice-alloc-realloc-heap

## Хак: большой underlying array на стеке

```go
var arr [1_000_000]byte    // ~1 МБ, стек (массив до 10 МБ)
s := arr[:]                // срез → underlying array на стеке!
```

^slice-alloc-hack-stack

Трюк позволяет обойти порог в 64 КБ: создаём массив (лимит 10 МБ), берём срез от него. Underlying array остаётся на стеке. Полезно для буферов в hot path. ^slice-alloc-hack-why

## Почему io.Reader принимает буфер снаружи

```go
// ✅ Буфер создаётся снаружи — может остаться на стеке
func (r *R) Read(p []byte) (n int, err error)

// ❌ Буфер создаётся внутри — уедет в heap (возвращается наружу)
func (r *R) Read() ([]byte, error)
```

^slice-alloc-ioreader-sig

Стандартная сигнатура `io.Reader` экономит аллокации: один буфер переиспользуется, а не создаётся на каждый `Read`. Если буфер создаётся внутри и возвращается — компилятор вынужден поместить его в heap (escape analysis). ^slice-alloc-ioreader-why
