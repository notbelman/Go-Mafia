### Recv: буфер пуст, никто не ждёт

Горутина-получатель засыпает в `recvq` и ждёт sender. ^recv4-desc

```
ДО:
  буфер: [_, _, _]
  qcount: 0
  sendq: пусто

G1: x := <-ch

  lock()
  создаём sudog (elem = &x)
  встаём в recvq
  unlock()
  gopark()   → G1: running → waiting 💤

  ... G1 спит в recvq ...

G2: ch <- D

  lock()
  recvq не пуст → достаём G1
  G1.elem = D   → копируем D в стек G1 (в его x)
  unlock()
  goready(G1)   → G1 в runqueue

ПОСЛЕ:
  recvq: пусто
  
  G1: проснулся, x = D ✓
  G2: отправил, продолжает работу ✓
```

^recv4-steps

**sudog** — вспомогательная структура, которую рантайм создаёт для заблокированной горутины. Хранит указатель на переменную куда нужно положить данные (`elem = &x`). ^recv4-sudog

`gopark()` переводит горутину из состояния `running` → `waiting`. ^recv4-gopark

Когда приходит sender, он сам копирует данные **прямо в стек** спящего G1 через `G1.elem`, не кладя в буфер. ^recv4-direct-write
