Механизм хранения элементов в буферизованном канале, реализованный внутри структуры `hchan`. Он позволяет горутинам обмениваться данными асинхронно, пока буфер не заполнен. ^rb-def

### 1. Принцип работы

Кольцевой буфер — это массив фиксированного размера с двумя указателями:

- `sendx` — куда писать следующий элемент ^rb-sendx
- `recvx` — откуда читать следующий элемент ^rb-recvx

```
make(chan int, 4) → буфер на 4 элемента

Начальное состояние:
[ _ | _ | _ | _ ]  sendx=0, recvx=0, qcount=0
  ^
  sendx, recvx

После ch <- 1:
[ 1 | _ | _ | _ ]  sendx=1, recvx=0, qcount=1
      ^

После ch <- 2, ch <- 3:
[ 1 | 2 | 3 | _ ]  sendx=3, recvx=0, qcount=3
              ^

После <-ch (читаем 1):
[ _ | 2 | 3 | _ ]  sendx=3, recvx=1, qcount=2
      ^

После ch <- 4, ch <- 5:
[ 5 | 2 | 3 | 4 ]  sendx=1, recvx=1, qcount=4
      ^            ↑ sendx обнулился и записал в начало

Буфер полон (qcount == dataqsiz), следующий send заблокируется.
```

При достижении конца массива индекс "заворачивается" в начало — поэтому буфер называется кольцевым. ^rb-wrap

`qcount` отслеживает сколько элементов сейчас в буфере:

- `qcount == 0` → буфер пуст, читать нечего ^rb-qcount-empty
- `qcount == dataqsiz` → буфер полон, писать некуда ^rb-qcount-full

### 3. Математика индексов и производительность

Кольцевой буфер обеспечивает операции добавления и удаления за **O(1)**, так как данные не сдвигаются в памяти. ^rb-o1

**Pointer Arithmetic**: Адрес i-го элемента вычисляется как `c.buf + i * elemsize`. ^rb-ptr-arith

**Оптимизация инкремента**: Хотя логически индексы работают через операцию остатка (`sendx % dataqsiz`), рантайм Go заменяет дорогую операцию деления на **явную проверку условия** для ускорения работы CPU: ^rb-inc-opt

```go
c.sendx++
if c.sendx == c.dataqsiz { c.sendx = 0 }
```
