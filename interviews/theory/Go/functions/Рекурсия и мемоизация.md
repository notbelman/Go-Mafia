- **прямая** рекурсия: f → f. **Косвенная**: f → g → f ^recursion-types
- **хвостовая рекурсия** — последний вызов = сам себя, без дополнительных операндов → можно развернуть в цикл ^tail-recursion-def
- в Go **нет оптимизации хвостовой рекурсии** ("не нужно в языке с циклами") ^no-tco-go
- **мемоизация** — кэширование результатов: не вычислять повторно (основа динамического программирования) ^memoization-def

## Обычный vs хвостовой факториал

```go
// Обычная рекурсия — дополнительный операнд (n *)
func factorial(n int) int {
    if n == 0 { return 1 }
    return n * factorial(n-1)  // n * ... нужно запомнить на стеке
}

// Хвостовая рекурсия — аккумулятор в параметре
func fastFactorial(n int) int {
    return tailFact(n, 1)
}
func tailFact(n, acc int) int {
    if n == 0 { return acc }
    return tailFact(n-1, n*acc)  // последний вызов — сам себя, без операндов
}
```

В языках с TCO (C++, Scheme) `tailFact` разворачивается в цикл с одним фреймом. ^tco-languages

В Go — **нет**: оба варианта одинаково расходуют стек. Бенчмарк подтверждает: производительность идентичная. ^go-no-tco-bench

## Почему нет TCO в Go

Цитата из обсуждений: *"Tail call optimization is not needed in a language with loops. When a programmer writes recursive code, they want to think about a call stack, or they write a loop."* ^tco-rationale

## Мемоизация — Fibonacci

```go
func memoFib(n int) int {
    cache := make([]int, n+1)

    var fib func(int) int       // 1. объявить переменную
    fib = func(k int) int {     // 2. присвоить (self-reference)
        if k <= 1 { return 1 }
        if cache[k] != 0 { return cache[k] }  // уже вычислено
        cache[k] = fib(k-1) + fib(k-2)        // вычислить и запомнить
        return cache[k]
    }

    return fib(n)
}
```

Паттерн self-reference: сначала `var fib func(int) int`, затем присвоение — иначе рекурсия внутри анонимной функции невозможна. ^memo-self-ref

## Зачем мемоизация

Дерево рекурсии Fibonacci без кэша:
```
fib(5) → fib(4) + fib(3)
          │         │
     fib(3)+fib(2)  fib(2)+fib(1)   ← fib(3) вычислен дважды
     │               │                ← fib(2) вычислен трижды
    ...             ...
```

С мемоизацией: каждое значение вычисляется **один раз** → O(n) вместо O(2^n). ^memo-complexity
