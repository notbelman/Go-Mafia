- Стек Трайбера — lock-free стек на связанном списке. Push и Pop = один CAS-луп на голове ^treiber-def
- Высокий contention: все горутины оперируют одной точкой (головой) → не лучшая структура для конкурентного доступа ^treiber-contention
- Подвержен ABA-проблеме (в Go защищает GC) ^treiber-aba

## Идея

Стек = связанный список, операции только с головой. CAS атомарно обновляет указатель на голову. ^treiber-idea

## Push

```go
func (s *Stack) Push(val int) {
    node := &Item{value: val}
    for {
        head := atomic.LoadPointer(&s.head)
        node.next = head                              // next → старая голова
        if atomic.CompareAndSwapPointer(&s.head, head, unsafe.Pointer(node)) {
            return  // голова обновлена на новый элемент
        }
        // кто-то встроился → повторяем
    }
}
```

^treiber-push

## Pop

```go
func (s *Stack) Pop() int {
    for {
        head := atomic.LoadPointer(&s.head)
        if head == nil {
            return -1  // стек пуст
        }
        next := atomic.LoadPointer(&(*Item)(head).next)
        if atomic.CompareAndSwapPointer(&s.head, head, next) {
            return (*Item)(head).value  // голова сдвинута на next
        }
        // кто-то встроился → повторяем
    }
}
```

^treiber-pop

## Почему CAS, а не просто присваивание

Между `Load` и обновлением головы другая горутина может изменить стек. CAS проверяет: "голова всё ещё та, что я загрузил?" Если да — обновляем. Если нет — повторяем. ^treiber-why-cas

## Проблема: высокий contention

У стека **одна точка входа и выхода** — голова. Все горутины конкурируют за неё. Много CAS-неудач → много повторных итераций. ^treiber-one-point

Очередь лучше: голова (pop) и хвост (push) разнесены → меньше contention. ^treiber-vs-queue
