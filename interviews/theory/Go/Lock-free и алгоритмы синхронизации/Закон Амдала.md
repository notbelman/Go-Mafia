- Закон Амдала: ускорение программы ограничено последовательной частью. S(N) = 1 / ((1-P) + P/N) ^amdahl-def
- P = доля параллелизуемого кода, N = количество ядер. Даже бесконечное N не поможет если (1-P) > 0 ^amdahl-params
- Практическое применение: перед параллелизацией — оцени P, посчитай ожидаемое ускорение, сравни с бенчмарком ^amdahl-practice

---

## Формула

```
           1
S(N) = -----------
       (1-P) + P/N
```

**P** — доля кода, которую можно распараллелить (0..1)
**N** — количество ядер (фактор параллельности)
**1-P** — доля кода, которая остаётся последовательной
**S(N)** — итоговое ускорение ^amdahl-formula

## Пример

90% кода параллелится (P=0.9), 10 ядер (N=10):

```
S(10) = 1 / (0.1 + 0.9/10) = 1 / (0.1 + 0.09) = 1 / 0.19 = 5.26x
```

Ожидали 10x, получили 5.26x. 10% последовательного кода съели половину ускорения. ^amdahl-example

## Предел при N -> бесконечности

```
S(inf) = 1 / (1-P)

P=0.5 -> максимум 2x (сколько бы ядер ни было)
P=0.9 -> максимум 10x
P=0.99 -> максимум 100x
```

^amdahl-limit

## Практика: бенчмарк подтверждает

```go
func calculate(parallelFactor int) {
    // 50% последовательный код
    for i := 0; i < 1_000_000; i++ { /* work */ }

    // 50% параллелизуемый код
    var wg sync.WaitGroup
    chunk := 1_000_000 / parallelFactor
    for i := 0; i < parallelFactor; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for j := 0; j < chunk; j++ { /* work */ }
        }()
    }
    wg.Wait()
}
```

P=0.5:

```
N=1:  базовое время T
N=2:  S = 1/(0.5 + 0.25) = 1.33x  -> T/1.33 (бенчмарк подтверждает)
N=4:  S = 1/(0.5 + 0.125) = 1.6x  -> T/1.6  (бенчмарк подтверждает)
```

^amdahl-bench

## Когда применять

**Да**: небольшая функция, можно глазами оценить P. Перед решением о параллелизации — посчитай. ^amdahl-when-yes

**Нет**: огромная кодовая база, трудно оценить P. ^amdahl-when-no

**Вывод**: если последовательная часть большая — параллелизация не поможет. Сначала оптимизируй последовательную часть. ^amdahl-conclusion
