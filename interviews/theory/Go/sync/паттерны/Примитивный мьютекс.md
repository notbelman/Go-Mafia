- Примитивный мьютекс = атомарный флаг + **очередь ожидания**: не получил лок → засыпай, а не крутись
- Ключевая идея: **park** (усыпить поток) и **unpark** (разбудить) через OS/runtime
- Мост между spin lock (жжём CPU) и полноценным мьютексом (Go sync.Mutex)

---

## Проблема spinning

Spin lock жжёт CPU в цикле. Если критическая секция длинная или потоков много — это катастрофа. Решение: поток **засыпает** и просыпается когда лок освободится. ^primitive-spinning-problem

## Реализация — два состояния

```go
type Mutex struct {
    state atomic.Int32  // 0 = свободен, 1 = захвачен
    sema  chan struct{} // очередь ожидания (упрощённо)
}

func NewMutex() *Mutex {
    return &Mutex{sema: make(chan struct{}, 1)}
}

func (m *Mutex) Lock() {
    // fast path: пробуем захватить
    if m.state.CompareAndSwap(0, 1) {
        return  // получили лок без засыпания
    }
    // slow path: не получилось — засыпаем
    for {
        if m.state.CompareAndSwap(0, 1) {
            return
        }
        <-m.sema  // park — засыпаем в очереди
    }
}

func (m *Mutex) Unlock() {
    m.state.Store(0)
    // пробуем разбудить одного ожидающего
    select {
    case m.sema <- struct{}{}: // unpark
    default:
    }
}
```

^primitive-impl

## Fast path / Slow path

Ключевая оптимизация:
- **Fast path**: CAS(0→1) — если лок свободен, захватываем без системных вызовов. Одна атомарная операция ^primitive-fast-path
- **Slow path**: лок занят — уходим в очередь ожидания (park). Дороже, но не жжём CPU ^primitive-slow-path

В реальных мьютексах перед slow path часто **крутятся немного** (hybrid: spin + park). Go `sync.Mutex` делает именно так. ^primitive-hybrid

## Futex (Linux)

На уровне OS за park/unpark отвечает **futex** (Fast Userspace Mutex):
- `futex_wait(addr, expected)` — если `*addr == expected`, усыпить поток ^futex-wait
- `futex_wake(addr, count)` — разбудить `count` потоков, ждущих на `addr` ^futex-wake

Быстрый путь (лок свободен) не трогает ядро вообще — чистый userspace CAS. ^futex-fast-path

## Go sync.Mutex — гибридный подход

```
Lock():
  1. CAS(0→1) — fast path
  2. Не получилось → spin несколько раз (если есть шанс)
  3. Всё ещё занят → park через runtime semaphore
```

^go-mutex-algorithm

Два режима:
- **Normal**: потоки встают в FIFO-очередь, но проснувшийся конкурирует с новыми ^go-mutex-normal-mode
- **Starvation**: если поток ждал >1мс — переключается в строгий FIFO ^go-mutex-starvation-mode
