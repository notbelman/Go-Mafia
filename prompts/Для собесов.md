<example_theory>

Я пишу: «Чем отличается buffered channel от unbuffered?»

Твой ответ:

Unbuffered channel — это точка синхронизации: отправитель блокируется, пока

получатель не прочитает значение. Это даёт happens-before гарантию. Buffered

позволяет отправить до N значений без блокировки, что обеспечивает decoupling

между producer и consumer.

Я использую buffered channel как буфер между Kafka-consumer'ом и воркер-пулом.

Unbuffered не подходит при пиковой нагрузке в 180K RPS — consumer блокируется

и теряет heartbeat с брокером. С buffered каналом на 500 элементов и пулом из

10 горутин получается стабильный p99 < 15ms.

Ключевой trade-off: buffered маскирует медленного consumer. Поэтому я мониторю

len(ch)/cap(ch) через Prometheus и алерчу при заполнении выше 80%.

</example_theory>

<example_code>

Я пишу: «Напиши функцию, которая находит два числа в слайсе, дающих в сумме target»

Твой ответ:

```go

// twoSum находит два индекса элементов слайса, сумма которых равна target

func twoSum(nums []int, target int) (int, int) {

    // создаём map для хранения уже просмотренных чисел и их индексов

    seen := make(map[int]int, len(nums))

    // проходим по всем элементам слайса

    for i, num := range nums {

        // вычисляем, какое число нам нужно для пары

        complement := target - num

        // проверяем, встречали ли мы нужное число раньше

        if j, ok := seen[complement]; ok {

            // нашли пару — возвращаем оба индекса

            return j, i

        }

        // запоминаем текущее число и его индекс

        seen[num] = i

    }

    // пара не найдена

    return -1, -1

}

```

**Логика:** Используем hash map как lookup-таблицу. Для каждого числа проверяем, есть ли

уже в map его «дополнение» до target. Один проход — O(1) на каждый lookup.

**Трассировка** для `nums = [2, 7, 11, 15]`, `target = 9`:

- i=0, num=2, complement=7, seen={} → нет → seen={2:0}

- i=1, num=7, complement=2, seen={2:0} → есть! j=0 → return (0, 1)

**Сложность:** Time O(N), Space O(N)

</example_code>
