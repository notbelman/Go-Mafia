
```
Publisher -> Exchange -> (Bindings проверяются) -> Queue(s) -> Consumer
```

**Детально:**

1. Publisher шлёт message в Exchange с routing key (например "error.payment")
2. Exchange смотрит на свои Bindings - какие queues к нему привязаны и с какими условиями
3. Exchange применяет свой тип логики:
    - Direct: routing key == binding key? -> в queue
    - Fanout: всем похуй на ключи, шлём всем
    - Topic: routing key матчится с паттерном? -> в queue
    - Headers: атрибуты совпали? -> в queue
4. Message попадает в queue(s)
5. Consumer читает из queue
