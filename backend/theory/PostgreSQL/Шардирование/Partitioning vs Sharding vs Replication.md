
||**Partitioning**|**Sharding**|**Replication**|
|---|---|---|---|
|**Что это**|Разбиение таблицы на части внутри одного сервера|Разбиение данных по разным серверам|Копирование данных на другие серверы|
|**Решает проблему**|Большие таблицы тормозят|Один сервер не тянет нагрузку/объём|Один сервер = single point of failure|
|**Масштабирует**|Ничего (тот же сервер)|Write + Storage|Read|
|**PostgreSQL**|Нативно (`PARTITION BY`)|Citus, postgres_fdw, или вручную|Нативно (streaming/logical)|
|**Сложность**|Низкая|Высокая|Средняя|


## Когда что

```
"Запросы по большой таблице тормозят, особенно по датам"
→ Partitioning (RANGE BY date)

"Один сервер не справляется с записями / данные не влезают"
→ Sharding (Citus или ручное)

"Нужна отказоустойчивость / больше read capacity"
→ Replication (streaming + replica для SELECT)

"Всё вместе"
→ Sharding + Replication внутри каждого шарда
    (как делает MongoDB, Cassandra)
```

## Визуально

```
Partitioning (один сервер):
┌─────────────────────────────┐
│        [PostgreSQL]         │
│  ┌───────┬───────┬───────┐  │
│  │ 2023  │ 2024  │ 2025  │  │  ← партиции по годам
│  └───────┴───────┴───────┘  │
└─────────────────────────────┘

Sharding (много серверов):
┌─────────┐  ┌─────────┐  ┌─────────┐
│ Shard 1 │  │ Shard 2 │  │ Shard 3 │
│ users   │  │ users   │  │ users   │
│ A-H     │  │ I-P     │  │ Q-Z     │  ← по первой букве
└─────────┘  └─────────┘  └─────────┘

Replication (копии):
┌──────────┐      ┌──────────┐
│  Master  │ ---> │ Replica  │
│  (R/W)   │ WAL  │  (R)     │
└──────────┘      └──────────┘
```
