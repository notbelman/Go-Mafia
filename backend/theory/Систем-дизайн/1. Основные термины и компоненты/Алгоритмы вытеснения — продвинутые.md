- **LRU-K** — вытесняем по **K-му с конца** обращению, а не по последнему. LRU-2: одно случайное обращение ничего не меняет — нужны минимум 2, чтобы стать "свежим"
- **SLRU (Segmented LRU)** — несколько уровней: cold → warm → hot. Каждое обращение поднимает на уровень выше. Вытеснение сначала из cold. Совмещает идеи [[Алгоритмы вытеснения — основные|LRU]] (давность) и [[Алгоритмы вытеснения — основные|LFU]] (частотность)
- **Second Chance** — FIFO + бит "used". Пора вытеснять → бит=1 → сбрасываем в 0, даём второй шанс. Бит=0 → вытесняем. Дешёвое улучшение FIFO
- **Clock** — Second Chance без перемещения элементов. Кольцевой буфер + указатель-стрелка. Используется в **Linux** для управления виртуальной памятью
- **2Q (Two Queues)** — две FIFO + LRU. Новые → "отстойник" (FIFO1). Обратились повторно → основной кэш (LRU). Защита от прогревочных данных (полный скан таблицы не вытеснит горячие)
- **Алгоритм Белади (OPT)** — теоретический идеал: вытесняем того, к кому обратятся **позже всех** в будущем. Нужно знать будущее → нереализуем. Эталон для сравнения
- Все продвинутые алгоритмы решают одну проблему: **защита от случайного вымывания** горячих данных холодными

## LRU-K

Вытесняем по **K-му с конца обращению**, а не по последнему.

### Зачем
Обычный LRU: случайно обратились к холодному элементу → он стал "свежим" → вытеснил нужные данные. Одно обращение испортило кэш.

LRU-2: одно случайное обращение ничего не меняет — смотрим на **предпоследнее**. Чтобы стать "свежим", нужны минимум 2 обращения.

### Пример
```
Элемент A: обращения в моменты [1, 5, 100]
Элемент B: обращения в моменты [2, 99]

LRU-1: последнее  → A=100, B=99  → вытесняем B
LRU-2: предпоследнее → A=5, B=2  → вытесняем B (но по другой логике)
```

Чем больше K, тем консервативнее алгоритм.

## SLRU (Segmented LRU)

Несколько уровней [[Алгоритмы вытеснения — основные|LRU]]: cold → warm → hot.

### Как работает
1. Новый элемент → **cold** (самый нижний уровень)
2. Обратились → переходит в **warm**
3. Обратились ещё раз → переходит в **hot**
4. Вытеснение — сначала из cold, потом из warm, hot последним

### Зачем
Совмещает идеи [[Алгоритмы вытеснения — основные|LRU]] (давность) и [[Алгоритмы вытеснения — основные|LFU]] (частотность). Чем чаще обращаются — тем выше уровень — тем сложнее вытеснить.

### Отличие от LFU
Нет числового счётчика. Просто уровни. Элемент может "остыть" — если давно не обращались, опускается обратно.

## Second Chance

FIFO + бит "used". Даём элементу второй шанс перед вытеснением.

### Как работает
1. Очередь FIFO. При обращении к элементу — `used = 1`
2. Пора вытеснять → смотрим голову очереди:
   - `used = 0` → **вытесняем**
   - `used = 1` → сбрасываем в 0, перемещаем в конец (второй шанс)

### Пример
```
Очередь: [A(1), B(0), C(1), D(1)]

Вытеснение:
  A(1) → сброс в 0, в конец → [B(0), C(1), D(1), A(0)]
  B(0) → вытесняем B ✓
```

### Плюсы и минусы
- **Плюс:** дешёвое улучшение FIFO — один бит на элемент
- **Минус:** если у всех `used = 1` → полный проход очереди, сброс всем в 0

## Clock

Second Chance **без перемещения** элементов. Кольцевой буфер + указатель ("стрелка часов").

### Как работает
1. Элементы расположены по кругу
2. Указатель движется по кругу
3. Пора вытеснять → смотрим элемент под стрелкой:
   - `used = 0` → **вытесняем**, стрелка остаётся
   - `used = 1` → сбрасываем в 0, двигаем стрелку дальше

```
        ┌───┐
   ┌───→│ A │ used=1  → сброс в 0, двигаем
   │    └───┘
   │              ┌───┐
   │         ┌───→│ B │ used=0  → вытесняем ✓
   │         │    └───┘
┌───┐     ┌───┐
│ D │     │ C │
└───┘     └───┘
  стрелка ↻
```

### Отличие от Second Chance
Не перемещаем элементы в конец — просто двигаем указатель. Дешевле.

### Где используется
**Linux** — управление виртуальной памятью. Ядро решает, какие страницы выгрузить из RAM на диск.


## 2Q (Two Queues)

Две FIFO-очереди + LRU. Новые элементы проходят через "отстойник", прежде чем попасть в основной кэш.

### Как работает
1. Новый элемент → **FIFO1** (входная очередь, "отстойник")
2. Вытесняется из FIFO1 → **FIFO2**
3. Если обратились, пока в FIFO1 или FIFO2 → переносим в **LRU** (основной кэш)

### Зачем отстойник
- защита от "прогревочных" данных — элемент попал один раз и больше не нужен
- в LRU попадают только те, к кому обратились **повторно**
- [[Кэширование — основы|горячие данные]] защищены от вымывания холодными

### Пример
Полный скан таблицы прогрузил кучу данных. Без 2Q — они вытеснят горячие данные. С 2Q — осядут в FIFO1/FIFO2 и не доберутся до LRU.



## Алгоритм Белади (OPT)

Вытесняем элемент, к которому обратятся **позже всех остальных** в будущем. Теоретически идеальный — минимально возможное количество промахов.

### Проблема
Нужно знать будущее. **Нереализуем** на практике.

### Зачем знать
- эталон для сравнения — любой реальный алгоритм сравнивают с Белади
- на собеседовании показывает глубину знаний
