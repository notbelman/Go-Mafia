- **Forward Proxy** — прокси, о которой **клиент знает**. Клиент осознанно отправляет запрос через прокси. Пример: VPN
- **Reverse Proxy** — прокси, о которой **клиент не знает**. Стоит за доменным именем. Пример: заходишь на google.com — не знаешь, что за ним прокси
- Reverse proxy = **единая точка входа** ("средневековый замок — одни ворота, стража на входе"): authn, authz, rate limiting, кэширование, SSL termination, [[Балансировка — алгоритмы|балансировка]]
- Forward proxy может **переложить протокол** — клиент шлёт REST, прокси конвертирует в gRPC для целевого сервиса
- **L7 балансировщик ≈ reverse proxy** — Nginx и то, и другое. Внутри прокси может быть логика балансировки, и наоборот
- [[Кэширование — основы#Cache Miss Attack|Cache Miss Attack]] — rate limiting на reverse proxy = первая линия защиты

## Сравнение

| | Forward Proxy | Reverse Proxy |
|---|---|---|
| Клиент знает? | Да | Нет |
| Защищает | Клиента (анонимность) | Сервер (точка входа) |
| Пример | VPN | Nginx перед бэкендами |
| Типичный кейс | Обход блокировок | Единая точка входа в [[Архитектура бэкенда|микросервисы]] |

## Forward Proxy

Прокси, о которой **клиент знает**. Клиент осознанно отправляет запрос через прокси.

```
┌────────┐      ┌───────────────┐      ┌────────┐
│ Клиент │ ───→ │ Forward Proxy │ ───→ │ Сервер │
│ (знает)│      │   (VPN)       │      │        │
└────────┘      └───────────────┘      └────────┘
```

### Зачем
- обход ограничений доступа (блокировки) — VPN
- анонимность — сервер видит IP прокси, а не клиента
- клиент явно настраивает адрес прокси

### Перекладка протокола
Клиент использует API прокси. Прокси может переложить протокол — клиент шлёт REST, прокси конвертирует в gRPC для целевого сервиса.

## Reverse Proxy

Прокси, о которой **клиент не знает**. Клиент идёт на доменное имя, а за ним стоит прокси.

```
┌────────┐      ┌───────────────┐      ┌──────────┐
│ Клиент │ ───→ │ Reverse Proxy │ ───→ │ Backend A│
│(не знает)     │  (Nginx)      │ ───→ │ Backend B│
└────────┘      └───────────────┘      └──────────┘
```

**Аналогия:** средневековый замок — одни ворота, стража на входе. Всё остальное огорожено стенами.

### Что делает (точка входа)
- аутентификация, авторизация
- rate limiting — ограничение частоты запросов
- кэширование ответов
- сжатие / шифрование данных
- SSL termination
- [[Балансировка — алгоритмы|балансировка нагрузки]] на бэкенды

### Балансировщик ≈ прокси
[[Балансировка — уровни и DNS|L7 балансировка]] на практике часто одно и то же. Nginx — и балансировщик, и прокси.
