- **Stateless** — сервис не хранит состояния (ни в памяти, ни на диске). Каждый запрос самодостаточный. [[Масштабирование|Горизонтальное масштабирование]] тривиально
- **Stateful** — сервис хранит состояние: сессии, [[Кэширование — основы|кэш в памяти]], файлы. Масштабирование — головная боль: миграция данных, [[Балансировка — алгоритмы|sticky sessions]]
- Stateless: упал инстанс → ничего не потеряли. Stateful: упал → **потеряли состояние**
- [[Кэширование — основы|Внутреннее кэширование (in-process)]] делает сервис stateful

## Сравнение

| | Stateless | Stateful |
|---|---|---|
| [[Масштабирование\|Горизонтальное масштабирование]] | Просто: докинул инстанс — работает | Больно: куда мигрировать данные? Как попадать в нужный инстанс? |
| [[Балансировка — алгоритмы\|Балансировка]] | Любая — без разницы, куда попал запрос | Нужна умная: [[Балансировка — алгоритмы\|sticky sessions]], хэширование |
| Отказоустойчивость | Упал инстанс — ничего не потеряли | Упал инстанс — потеряли состояние |

## Stateless

Сервис не хранит никакого состояния: ни в памяти, ни в файловой системе. Каждый запрос самодостаточный.

## Stateful

Сервис хранит состояние: сессии, кэш в памяти, файлы под ногами и т.д.

## Почему важно

**Главный вывод:** stateless масштабируется тривиально. Stateful — всегда головная боль: миграция данных, партиционирование, умная балансировка.
