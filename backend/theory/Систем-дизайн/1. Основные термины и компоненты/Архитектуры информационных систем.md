- **Файл-сервер** — сервер отдаёт файл целиком, в сыром виде. Вся обработка на клиенте. Пример: Google Drive, Dropbox
- **Клиент-сервер** — сервер сам фильтрует, ищет, сортирует → отдаёт клиенту только то, что попросили. ~95% всех систем
- **P2P** — нет разделения на клиента и сервер. Все узлы одноранговые — каждый и запрашивает, и отдаёт. Примеры: блокчейн, торренты
- Ключевое отличие файл-сервера от клиент-сервера — **кто обрабатывает данные**: клиент или сервер
- Клиент-сервер доминирует потому что: клиент не нагружается логикой, сервер контролирует доступ (authn, authz, rate limiting), объём данных ограничен
- P2P — специфичные задачи, где нужна **децентрализация** и нет централизованного хранилища
- На интервью: по умолчанию проектируем **клиент-сервер**, если задача явно не требует P2P

## Сравнение

| | Файл-сервер | Клиент-сервер | P2P |
|---|---|---|---|
| Кто обрабатывает | Клиент | Сервер | Все узлы |
| Контроль доступа | Нет | Да (authn, authz) | Нет центра |
| Масштабируемость | Плохая | Хорошая | Зависит от протокола |
| Пример | Google Drive | ~95% всех систем | Блокчейн, торренты |

## Файл-сервер

Клиент запрашивает данные → сервер отдаёт файл целиком, без фильтрации, сортировки, поиска. Вся обработка ложится на клиента.

```
Клиент: "дай пользователя с ID 5"
Сервер: отдаёт файл со ВСЕМИ пользователями
Клиент: сам ищет нужного
```

**Почему устарела:**
- небезопасно отдавать клиенту все данные
- клиент нагружается логикой обработки
- не у всех клиентов хватает ресурсов (CPU, RAM)

**Где живёт сейчас:** Google Drive, Dropbox — загрузка/скачивание файлов целиком, без обработки на сервере.

**Граница с клиент-сервером:** тонкая. Если сервер делает хоть какую-то выборку (фильтрация по ключу, offset внутри файла) — это уже ближе к клиент-серверу.

## Клиент-сервер

Клиент запрашивает данные → сервер сам идёт в хранилище, фильтрует, ищет, сортирует → отдаёт только то, что клиент попросил.

```
Клиент: "дай пользователя с ID 5"
Сервер: идёт в базу → находит пятого → отдаёт только его
```

**Почему доминирует (~95% систем):**
- клиент не нагружается логикой
- безопасно: сервер контролирует доступ — аутентификация, авторизация, rate limiting
- сервер контролирует объём отдаваемых данных

## P2P (Peer-to-Peer)

Нет разделения на клиента и сервер. Все узлы одноранговые — каждый одновременно и запрашивает данные, и отдаёт их другим.

```
       ┌───────┐
  ┌───→│ Peer A│←────┐
  │    └───────┘     │
  │                  │
  ▼                  ▼
┌───────┐      ┌───────┐
│ Peer B│←────→│ Peer C│
└───────┘      └───────┘
Каждый и клиент, и сервер одновременно
```

**Примеры:** блокчейн (TON и др.), торренты — сам скачиваешь и сам раздаёшь.

**Когда используется:** специфичные задачи, где нет централизованного хранилища и нужна децентрализация. Нельзя натянуть на задачи с централизованным контролем — можно, но будет больно в эксплуатации.
