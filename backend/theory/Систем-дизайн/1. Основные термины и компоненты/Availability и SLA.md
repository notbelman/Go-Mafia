- **Downtime ≠ "упал"** — сервис может быть поднят, но отвечать пятисотками. Всё равно недоступен
- **Надёжность ≠ доступность**: надёжность — сервис не упал (про отказы), доступность — сервис отвечает на запросы

- **SLI** — метрика (что меряем: uptime, latency). **SLO** — цель на команду ("держим 99.99%"). **SLA** — соглашение с клиентом (что будет, если нарушим: возврат денег, скидки)
- Цепочка: SLI (измеряем показатель) → SLO (ставим цель) → SLA (обещаем клиенту последствия за нарушение)
- Пример Google Drive: SLI = availability, SLO = 99.95% для standard storage, SLA = если упало до 99% → Google возмещает 10%

## Availability (доступность, девятки)

Процент времени в году, когда сервис способен обрабатывать запросы.

- **Uptime** — сервис готов обрабатывать запросы
- **Downtime** — не обязательно "упал". Может быть поднят, но отвечает пятисотками — всё равно недоступен

**Надёжность ≠ доступность:**
- надёжность — сервис не упал (про отказы)
- доступность — сервис отвечает на запросы (может быть поднят, но не отвечать)

**На практике:** больше 4–5 девяток бессмысленно. Сеть моргнёт, телефон зависнет — пользователь не увидит разницы. Зато стоить будет катастрофически дорого.

## SLI, SLO, SLA

| Уровень | Для кого | Про что | Пример (Google Drive) |
|---|---|---|---|
| **SLI** (Service Level Indicator) | Все | Метрика, по которой меряем | availability |
| **SLO** (Service Level Objective) | Разработчики | Цель, которую держим | 99.95% для standard storage |
| **SLA** (Service Level Agreement) | Клиенты | Последствия, если не держим | упало до 99% → возмещение 10% |

**SLI** — конкретный показатель (uptime, latency, error rate).

**SLO** — цель на команду разработки. "Вы должны держать доступность 99.99%". Внутренняя история, про разработчиков.

**SLA** — соглашение с клиентом. Что произойдёт, если SLO нарушено: возврат денег, скидки, бонусы. Внешняя история, про клиентов.

```
SLI → измеряем показатель → SLO → ставим цель → SLA → обещаем последствия
```
