- **LRU (Least Recently Used)** — вытесняем тот, к кому **дольше всего не обращались**. Самый популярный, закрывает 80–90% задач. Реализация: двусвязный список + хэш-таблица, O(1)
- **LFU (Least Frequently Used)** — вытесняем тот, к кому **реже всего обращались** (счётчик). Горячие ключи никогда не вытеснятся, но старые накопленные счётчики трудно сбросить
- **LRU с TTL** — LRU + время жизни элемента. Элемент вытесняется либо по LRU, либо по TTL — что раньше. Самый практичный вариант. Redis/Memcached поддерживают из коробки
- **MRU (Most Recently Used)** — зеркало LRU: вытесняем **последний** использованный. Редкий, для специфичных кейсов (последовательный скан)
- **Random / FIFO / LIFO** — базовые, не учитывают частоту и давность. Random — иногда самое простое решение. FIFO — основа для продвинутых (Second Chance, 2Q)
- LRU — критерий **давность**. LFU — критерий **частота**. LRU с TTL — давность + **гарантия свежести**
- Минус LRU: одно случайное обращение к холодному ключу делает его "свежим" → вытесняет нужные данные. Решают [[Алгоритмы вытеснения — продвинутые|LRU-K, SLRU, 2Q]]

## Сравнение

| Алгоритм | Критерий вытеснения | Плюс | Минус |
|---|---|---|---|
| **LRU** | Дольше всего не обращались | Покрывает 80–90% задач, O(1) | Одно случайное обращение портит кэш |
| **LFU** | Реже всего обращались (счётчик) | Горячие ключи защищены | Старые накопленные счётчики трудно сбросить |
| **LRU + TTL** | LRU или TTL — что раньше | Гарантия свежести | — |
| **MRU** | Последний использованный | Для последовательного скана | Редкий, нишевый |
| **Random** | Случайный | Просто | Может выкинуть горячий ключ |
| **FIFO** | Первый пришёл | Основа для продвинутых | Не учитывает обращения |

## LRU (Least Recently Used)

Вытесняем элемент, к которому **дольше всего не обращались**.

```
Обращения: A, B, C, D, A, B, E
Кэш (размер 4): [A, B, C, D]

Обратились к A → A "свежий"
Обратились к B → B "свежий"
Пришёл E, место кончилось → вытесняем C (самый давний)
```

### Почему самый популярный
- простая идея, понятная интуитивно
- хорошо работает на большинстве реальных нагрузок
- закрывает 80–90% задач кэширования

### Реализация
Двусвязный список + хэш-таблица. O(1) на вставку, удаление, обращение.

### Минус
Одно случайное обращение к холодному ключу делает его "свежим" → вытесняет по-настоящему нужные данные. Решают [[Алгоритмы вытеснения — продвинутые|LRU-K, SLRU, 2Q]].


## LFU (Least Frequently Used)

У каждого элемента **счётчик обращений**. Вытесняем с минимальным счётчиком.

```
A: 100 обращений
B: 50 обращений
C: 3 обращения    ← вытесняем
```

### LRU vs LFU

| | LRU | LFU |
|---|---|---|
| Критерий | Давность последнего обращения | Частота обращений |
| Вытесняет | Самый давний | Самый редкий |

### Плюсы
- [[Кэширование — основы|горячие ключи]] с высокой частотой никогда не вытеснятся
- хорошо, когда частотность стабильна

### Минусы
- элемент накопил счётчик давно, уже не нужен, но всё ещё в кэше — трудно вытеснить
- новые элементы уязвимы — маленький счётчик, легко вытесняются


## LRU с TTL

К обычному LRU добавляется **TTL** (Time To Live) — время жизни. Элемент вытесняется либо по LRU, либо по TTL — что раньше.

**Зачем:** даже если к элементу обращаются часто, через N минут он всё равно протухнет. Гарантия свежести данных.

**Пример:** TTL = 5 минут. Элемент в кэше 6 минут → вытесняется, даже если обращались секунду назад.

**Самый практичный вариант** — Redis, Memcached поддерживают TTL из коробки. TTL как простейшая стратегия [[Кэширование — инвалидация|инвалидации]].

## MRU (Most Recently Used)

Зеркальная противоположность LRU — вытесняем элемент, к которому обращались **последним**.

### Когда имеет смысл
Специфичные кейсы, где недавно запрошенные данные точно больше не понадобятся. Пример: последовательный скан — прочитал страницу, она больше не нужна.

На практике редкий. По умолчанию — LRU.

## Random, FIFO, LIFO

Базовые алгоритмы. Кэш ограничен по размеру → нужно решить, кого выкинуть.

| Алгоритм | Логика | Минус |
|---|---|---|
| **Random** | Случайный элемент | Может выкинуть горячий ключ |
| **FIFO** | Первый пришёл → первый вытеснен | Не учитывает обращения после вставки |
| **LIFO** | Последний пришёл → первый вытеснен | Редкий, специфичный |

**Общий минус:** не учитывают частоту и давность обращений.

FIFO — основа для продвинутых алгоритмов ([[Алгоритмы вытеснения — продвинутые|Second Chance, 2Q]]).
