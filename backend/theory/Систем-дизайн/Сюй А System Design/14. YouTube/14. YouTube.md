- **Видеостриминг (YouTube/Netflix).** Загрузка + просмотр видео. **5M DAU**, 5 видео/день, 10% загружают по 1 видео. Макс. файл 1 ГБ. Мобильные, браузер, Smart TV
- **150 ТБ/день** нового видео (5M × 10% × 300 МБ). Стоимость CDN: **$150K/день** (5M × 5 × 0.3 ГБ × $0.02). CDN — главная статья расходов
- Два процесса: **загрузка** (видео → BLOB → перекодирование → CDN) и **стриминг** (CDN → клиент, протоколы MPEG-DASH / HLS / Smooth Streaming)
- **Перекодирование:** исходное видео → разные форматы, разрешения (360p–4K), кодеки (H.264, VP9). Модель **DAG** — разделение на этапы: видео/звук/метаданные → кодирование → миниатюра → водяной знак → сборка
- **Архитектура перекодирования:** препроцессор (разделение на GOP) → планировщик DAG → диспетчер ресурсов (3 очереди + планировщик заданий) → рабочие узлы → временное хранилище → закодированное видео
- **Оптимизация скорости:** параллельная загрузка по GOP, центры загрузки ближе к юзерам (CDN), очереди сообщений между модулями (скачивание → кодирование → загрузка)
- **Оптимизация стоимости:** только популярные видео в CDN, остальные на видеосерверах (длинный хвост). Непопулярные кодируются по требованию. Региональные — не за пределы региона
- **Безопасность:** предварительно подписанный URL (pre-signed URL) для загрузки, DRM (FairPlay/Widevine/PlayReady), AES-шифрование, водяные знаки

## Перекодирование видео — подробно

### Зачем перекодировать
- Необработанное видео **огромное** (час в 60fps HD = сотни ГБ)
- Разные устройства/браузеры поддерживают **разные форматы**
- Качество видео должно **адаптироваться** к скорости сети (adaptive bitrate)

### Формат = контейнер + кодек
- **Контейнер:** видеофайл + аудио + метаданные (.mp4, .avi, .mkv)
- **Кодек:** алгоритм сжатия (H.264, VP9, HEVC)

### Модель DAG (Directed Acyclic Graph)

![[14.8.png]]

Исходное видео разделяется на: **видео** + **звук** + **метаданные**

Задания для видео:
- **Анализ** — проверка качества, целостность
- **Кодирование** — разные разрешения (360p, 480p, 720p, 1080p, 4K)
- **Миниатюра** — автогенерация или загрузка пользователем
- **Водяной знак** — идентификация контента

![[14.9.png]]

### Архитектура перекодирования

![[14.10.png]]

| Компонент | Описание |
|---|---|
| **Препроцессор** | Разделение видео на GOP (Group of Pictures), генерация DAG, кэширование GOP |
| **Планировщик DAG** | Делит задания на этапы → в очередь диспетчера |
| **Диспетчер ресурсов** | 3 очереди (заданий, рабочих узлов, выполнения) + планировщик. Выбирает оптимальный узел |
| **Рабочие узлы** | Выполняют задания: кодирование, миниатюры, водяные знаки, слияние |
| **Временное хранилище** | Метаданные в памяти, видео/аудио в BLOB. Удаляется после завершения |

![[14.15.png]]

![[14.17.png]]

### GOP (Group of Pictures)
Видеопоток делится на **независимо воспроизводимые блоки** по несколько секунд. Позволяет параллельную загрузку и кодирование.

![[14.23.png]]

## Оптимизация безопасности

### Pre-signed URL для загрузки

![[14.27.png]]

1. Клиент → POST /upload → серверы API
2. API возвращает **предварительно подписанный URL** (доступ к объекту в S3)
3. Клиент загружает видео по этому URL

### Защита видеороликов

| Метод | Описание |
|---|---|
| **DRM** | FairPlay (Apple), Widevine (Google), PlayReady (Microsoft) |
| **AES-шифрование** | Шифрование + политика авторизации. Расшифровка при воспроизведении |
| **Водяные знаки** | Логотип/название поверх видео |

## Оптимизация стоимости CDN

**Принцип длинного хвоста:** большинство просмотров = горстка популярных видео. Остальные — редко.

| Оптимизация | Описание |
|---|---|
| **Популярные → CDN** | Только топ видео в CDN, остальные на видеосерверах |
| **Кодирование по требованию** | Непопулярные не кодировать заранее |
| **Региональное** | Популярные только в регионе → не распространять за его пределы |
| **Своя CDN** | Netflix строит свою CDN + партнёрство с ISP (Comcast, AT&T) |

## Обработка ошибок

| Ошибка | Решение |
|---|---|
| Ошибка загрузки | Retry |
| Ошибка разделения видео | Если клиент не может → разделение на сервере |
| Ошибка перекодирования | Retry |
| Ошибка препроцессора | Перегенерировать DAG |
| Ошибка планировщика DAG | Перепланировать задание |
| Отказ очереди диспетчера | Использовать реплику |
| Отказ рабочего узла | Retry на другом узле |
| Отказ сервера API | Stateless → перенаправить на другой |
| Отказ кэша метаданных | Данные реплицированы → другой сервер |
| Отказ БД метаданных | Master → promote slave. Slave → другой slave |

## Дополнительные вопросы

- **Масштабирование API** — stateless → горизонтально
- **Масштабирование БД** — репликация + шардирование
- **Прямая трансляция** — другие требования к латентности и протоколу, меньше параллельной обработки
- **Запрет контента** — нарушение авторских прав, незаконный контент → обнаружение при загрузке + жалобы пользователей
