Каждая инструкция RUN, COPY, ADD создаёт новый read-only слой. При запуске контейнера сверху добавляется тонкий writable слой.
```
Образ (read-only слои):
┌─────────────────────┐
│ ENTRYPOINT ["/app"] │  слой 4
├─────────────────────┤
│ RUN go build        │  слой 3
├─────────────────────┤
│ COPY . .            │  слой 2
├─────────────────────┤
│ FROM golang:1.22    │  слой 1 (базовый)
└─────────────────────┘

Контейнер:
┌─────────────────────┐
│ writable layer      │  ← логи, tmp файлы (удаляется с контейнером)
├─────────────────────┤
│ образ (read-only)   │
└─────────────────────┘
```

**Кэширование:** Docker кэширует каждый слой. Если инструкция и её входные данные не изменились — слой берётся из кэша. Но если слой изменился — все слои после него пересобираются.
```dockerfile
# ❌ Плохо: любое изменение кода инвалидирует кэш зависимостей
COPY . .
RUN go mod download
RUN go build

# ✅ Хорошо: зависимости кэшируются отдельно
COPY go.mod go.sum ./
RUN go mod download     ← кэшируется пока go.mod не изменился
COPY . .
RUN go build
```

**Группировка RUN:** каждый RUN — отдельный слой. Объединяй связанные команды чтобы уменьшить количество слоёв и размер:
```dockerfile
# ❌ 3 слоя, apt cache остаётся
RUN apt-get update
RUN apt-get install -y curl
RUN rm -rf /var/lib/apt/lists/*

# ✅ 1 слой, чище
RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*
```
