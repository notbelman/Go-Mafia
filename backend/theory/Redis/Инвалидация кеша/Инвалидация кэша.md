
| Стратегия       | Когда кэш обновляется           | Консистентность | Сложность   | Риск stale данных  |
| :-------------- | :------------------------------ | :-------------- | :---------- | :----------------- |
| TTL             | По истечении времени            | Низкая          | Минимальная | Да, в пределах TTL |
| Event-based     | При записи в БД                 | Высокая         | Средняя     | Минимальный        |
| Pub/Sub         | Подписчики получают уведомление | Высокая         | Высокая     | Минимальный        |
| Версионирование | При смене версии ключа          | Высокая         | Средняя     | Нет                |
## На практике: комбинация

Обычно используют TTL + Event-based вместе:
```go
func UpdateTrip(id string, data Trip) error {
    err := db.UpdateTrip(id, data)
    if err != nil {
        return err
    }
    redis.Del(ctx, "trip:"+id)  // event-based: сразу удаляем
    return nil
}

func GetTrip(id string) (*Trip, error) {
    cached, err := redis.Get(ctx, "trip:"+id).Result()
    if err == nil {
        return unmarshal(cached), nil
    }
    trip, _ := db.GetTrip(id)
    redis.Set(ctx, "trip:"+id, marshal(trip), 30*time.Second) // TTL как подстраховка
    return trip, nil
}
```

TTL — страховка на случай если event-based не сработал (баг, забыли удалить, сервис упал). Event-based — основной механизм для быстрой актуализации.
