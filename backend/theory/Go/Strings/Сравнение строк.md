- сравнение == идёт в 3 шага: **len → указатели → побайтово** ^cmp-algorithm
- если ptr совпадает и len совпадает → **O(1)**, без итерации по данным ^cmp-ptr-o1
- работает потому что строки **immutable** — если указатели одинаковые, данные точно одинаковые ^cmp-why-works
- почему проверяется len: **подстроки** шарят ptr с разным len (`s[1:3]` и `s[1:5]`) ^cmp-why-len
- пакет `unique` — сравнение Handle за O(1) для любых строк ^cmp-unique

## Алгоритм сравнения

```
1. len(s1) != len(s2) → false           // O(1)
2. ptr(s1) == ptr(s2) → true            // O(1) — тот же участок памяти
3. побайтовое сравнение                  // O(n)
```

## Бенчмарк: одинаковый ptr vs разный ptr

```go
// Разный ptr — побайтовое сравнение O(n)
b := make([]byte, 1<<20)  // 1 MB
s1 := string(b)           // аллокация + копия
s2 := string(b)           // аллокация + копия
s1 == s2                   // медленно — 1 MB побайтово

// Одинаковый ptr — мгновенно O(1)
s1 := string(b)
s2 := s1                   // копия header, тот же ptr
s1 == s2                   // быстро — проверка ptr + len
```

Разница в десятки-сотни раз на длинных строках. ^cmp-benchmark-diff

## Почему проверяется и len

```go
s := "hello world"
s1 := s[0:5]   // "hello" — ptr на начало s, len=5
s2 := s[0:8]   // "hello wo" — ptr на начало s, len=8

// ptr одинаковый! Но строки разные → нужна проверка len
```

## Почему работает (immutable)

В языках с mutable строками такая оптимизация невозможна: даже если ptr совпадает, кто-то мог изменить данные. В Go строки неизменяемые → одинаковый ptr гарантирует одинаковые данные. ^cmp-immutable-guarantee

## Ещё быстрее: unique

```go
h1 := unique.Make(s1)
h2 := unique.Make(s2)
h1 == h2  // O(1) всегда — сравнение указателей Handle
```

`unique.Make` интернирует строку — гарантирует что одинаковые строки имеют один Handle. После этого любое сравнение — O(1) независимо от длины и совпадения ptr. ^cmp-unique-mechanism
