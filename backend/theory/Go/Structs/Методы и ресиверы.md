- метод = **функция**, первым аргументом которой неявно идёт ресивер (указатель или значение) ^method-is-func
- в ассемблере **нет методов** — только функции; ресивер = синтаксический сахар ^method-asm-sugar
- можно вызвать метод через тип: `Data.Print(obj)` — так и работает под капотом ^method-explicit-call
- на nil-указателе метод **вызовется** (если внутри нет разыменования) ^method-nil-receiver
- методы с `_` — можно создать много, но вызвать нельзя ^method-blank-ident

---

## Метод = функция с ресивером

```go
type Data struct{ Value int }

func (d Data) Print() { fmt.Println(d.Value) }

obj := Data{Value: 42}

// Привычный вызов
obj.Print()

// Как это работает под капотом (вызов через тип)
Data.Print(obj)

// С указателем — то же самое
ptr := &Data{Value: 42}
(*Data).Print(ptr)
```

Ассемблер знает только функции. `obj.Print()` → `Data.Print(obj)`. ^method-lowering-example

## Nil receiver

```go
type Data struct{ Value int }

func (d *Data) Safe() { fmt.Println("ok") }
func (d *Data) Unsafe() { fmt.Println(d.Value) } // разыменование!

var d *Data // nil

d.Safe()    // ✅ напечатает "ok" — нет обращения к полям
d.Unsafe()  // ❌ panic: nil pointer dereference
```

Метод вызывается на nil, потому что это просто вызов функции с nil первым аргументом. Panic только при разыменовании. ^nil-receiver-example

## Синтаксический сахар с указателями

```go
ptr := &Data{Value: 10}

// Мы пишем:
ptr.Print()

// Под капотом:
(*ptr).Print()  // автоматическое разыменование
```

Go упрощает работу с указателями: не нужно писать `(*ptr).Method()` или `->`. ^ptr-auto-deref

## Методы с `_`

```go
func (_ Data) method1() {}
func (_ Data) method1() {}  // ✅ можно несколько с одним именем _
// method1()                // ❌ нельзя вызвать
```

Аналогично функциям с `_` из лекции про функции. ^blank-method-example
