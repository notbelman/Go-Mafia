- встроенное поле = **анонимное поле**: имя поля = имя типа
- можно пропускать промежуточные поля при обращении (`c.Value` вместо `c.B.A.Value`)
- нельзя рекурсивно встраивать себя (неизвестен размер), но **можно указатель на себя**
- конфликт имён при встраивании нескольких типов → компилятор: ambiguous selector → явно указывать
- методы с одинаковой сигнатурой **перекрываются** (не переопределяются)

---

## Анонимное поле — имя = имя типа

```go
type Bar struct{ Data int }

type Foo struct {
    Bar          // встроенное (анонимное) поле, имя = "Bar"
}

f := Foo{Bar: Bar{Data: 42}}

// Два способа доступа:
f.Data       // пропустили анонимное поле Bar
f.Bar.Data   // явно через имя типа
```

Встроенное (анонимное) поле имеет имя = имя типа. Доступ к полям/методам возможен напрямую (promotion) или через имя типа. ^embt-anon-field

## Пропуск нескольких уровней

```go
type A struct{ Value int }
type B struct{ A }
type C struct{ *B }

c := C{B: &B{A: A{Value: 10}}}

c.Value       // пропустили B и A
c.B.Value     // пропустили A
c.B.A.Value   // полный путь
```

То же самое с методами: `c.Print()` → `c.B.A.Print()`. ^embt-multilevel

## Нельзя рекурсивно

```go
type Node struct {
    Node         // ❌ ошибка компиляции: неизвестен размер
}

type Node struct {
    *Node        // ✅ указатель — размер известен (8 байт)
}
```

Прямая рекурсия запрещена — компилятор не знает размер. Указатель на себя — разрешён, размер указателя фиксирован (8 байт на 64-битных системах). ^embt-no-recursive

## Конфликт имён

```go
type D1 struct{ Value int }
type D2 struct{ Value int }

type Base struct {
    D1
    D2
}

b := Base{}
// b.Value      // ❌ ambiguous selector — у D1 и D2 есть Value
b.D1.Value      // ✅ явно
b.D2.Value      // ✅ явно
```

То же с методами: если у D1 и D2 одинаковый метод Print — нужно `b.D1.Print()`. ^embt-name-conflict

При конфликте компилятор выдаёт ошибку `ambiguous selector` — нужно явно указывать путь. ^embt-ambiguous-error

## Перекрытие методов

```go
type Person struct{ Name string }
func (p Person) Intro() string { return "Mr/Mrs " + p.Name }

type Woman struct {
    Person
}
func (w Woman) Intro() string { return "Mrs " + w.Name }

w := Woman{Person: Person{Name: "Екатерина"}}
w.Intro()        // "Mrs Екатерина" — метод Woman перекрыл Person
w.Person.Intro() // "Mr/Mrs Екатерина" — явно вызвали Person
```

**Перекрытие, не переопределение.** Метод Person никуда не делся — доступен явно через `w.Person.Intro()`. ^embt-override

Перекрытие (shadowing) — внешний метод приоритетнее. Внутренний не удаляется — просто не вызывается по умолчанию. ^embt-shadow-rule

## Встраивание интерфейса в структуру

Можно встраивать интерфейс в структуру — структура автоматически удовлетворяет интерфейсу. Но незаполненное поле-интерфейс будет `nil` → panic при вызове. ^embt-interface-embed
