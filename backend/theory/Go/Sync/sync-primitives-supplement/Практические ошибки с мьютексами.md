- гранулярность: минимум действий под мьютексом (аналогия с кассой — кетчуп и кошелёк готовьте заранее) ^mutex-granularity-principle
- утечка ссылки: возврат среза из-под мьютекса = data race (копия или for-each callback) ^mutex-ref-leak
- проблема API: между top() и pop() вклинивается другая горутина → объединять в один метод ^mutex-api-problem

## Лишняя синхронизация

```go
// ПЛОХО: value локальная в каждой горутине, зачем мьютекс?
go func() {
    var value int
    mu.Lock()
    for i := 0; i < 10; i++ {
        value++
    }
    mu.Unlock()
    fmt.Println(value)
}()
```

Если переменная **локальная** — никто её не шарит. Мьютекс = бессмысленный overhead. ^mutex-unnecessary-sync

## Локальный мьютекс

```go
// ПЛОХО: каждая горутина создаёт СВОЙ мьютекс
go func() {
    var mu sync.Mutex  // локальный!
    mu.Lock()
    counter++
    mu.Unlock()
}()
```

Мьютекс должен быть **разделяемый**, иначе взаимное исключение не работает. ^mutex-must-be-shared

## Гранулярность блокировок

```go
// ПЛОХО: fmt.Println под мьютексом
mu.Lock()
item := cache[key]
fmt.Println(item)  // зачем это под локом?
mu.Unlock()

// ХОРОШО: только доступ к shared state под мьютексом
mu.Lock()
item := cache[key]
mu.Unlock()
fmt.Println(item)  // локальная копия, синхронизация не нужна
```

Аналогия: подходишь на кассу — кетчуп и кошелёк уже с тобой. В критической секции делаешь минимум, чтобы остальные ждали меньше. ^mutex-granularity-code

## Утечка ссылки из-под мьютекса

```go
// ПЛОХО: возвращаем срез — указывает на тот же массив
func (b *Buffer) GetAll() []int {
    b.mu.Lock()
    defer b.mu.Unlock()
    return b.data  // ← снаружи пишут без синхронизации = data race
}

// ХОРОШО: копия
return append([]int{}, b.data...)

// ХОРОШО: for-each callback
func (b *Buffer) ForEach(fn func(int)) {
    b.mu.Lock()
    defer b.mu.Unlock()
    for _, v := range b.data { fn(v) }
}
```

^mutex-ref-leak-code

## Проблема API: top() + pop()

```go
// Оба метода синхронизированы, но МЕЖДУ ними — дыра
v := stack.Top()   // вернул 2
// ← сюда встраивается другая горутина, делает Pop()
stack.Pop()        // ожидали снять 2, а сняли 1

// РЕШЕНИЕ: один метод
func (s *Stack) PopTop() (int, bool) {
    s.mu.Lock()
    defer s.mu.Unlock()
    // top + pop атомарно
}
```

^mutex-api-toctou

## Рекурсивный лок

```go
func (c *Cache) Get(key string) int {
    c.mu.Lock()
    defer c.mu.Unlock()
    if c.Size() > 0 { ... }  // Size() тоже делает Lock → deadlock!
}

// РЕШЕНИЕ: приватный метод с суффиксом Locked
func (c *Cache) sizeLocked() int { return len(c.data) }
```

Суффикс `Locked` = «вызывать только когда мьютекс уже захвачен». Паттерн из стандартной библиотеки (sync.Map). ^mutex-recursive-locked-pattern

## Не встраивать тип мьютекса

```go
// ПЛОХО: пользователь видит Lock/Unlock
type Cache struct {
    sync.Mutex  // встроен → Cache.Lock() доступен снаружи
    data map[string]int
}

// ХОРОШО: инкапсулировать
type Cache struct {
    mu   sync.Mutex  // приватное поле
    data map[string]int
}
```

^mutex-embed-problem
