- **Data race** = 2+ горутины + одна переменная + минимум 1 запись + **нет happens-before**. Результат — **Undefined Behavior** ^dr-def
- Компилятор и CPU могут переупорядочить операции, кэшировать значения — программа может выдать **любой** результат ^dr-ub
- Исправление: mutex, channel, atomic, не шарить данные ^dr-fix

---

## Пример

```go
var n int
go func() { n++ }()  // запись
fmt.Println(n)        // чтение — DATA RACE
```
^dr-example

`n++` — это **3 операции** (load → inc → store). Между ними может встроиться другая горутина. ^dr-increment-not-atomic

## Как исправить

| Способ | Пример |
|:--|:--|
| Mutex | `mu.Lock(); n++; mu.Unlock()` |
| Channel | `ch <- n` |
| Atomic | `atomic.AddInt64(&n, 1)` |
| Не шарить | каждая горутина — своя копия |
^dr-fixes

## Почему UB, а не просто "неправильное значение"

Компилятор **имеет право** оптимизировать код в предположении что data race нет. Если race есть — оптимизации ломают логику непредсказуемо: убранные проверки, переупорядоченные записи, бесконечные циклы. ^dr-why-ub
