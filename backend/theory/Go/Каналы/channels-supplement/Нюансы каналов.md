- continue внутри select → работает на **внешний for**. break внутри select → работает на **select**
- канал = указатель → копия шарит тот же hchan, сравнение = сравнение указателей
- аргументы функции вычисляются **слева направо** → `process(fetch1(), fetch2())` = последовательно, не конкурентно

---

## break и continue в select

```go
for {
    select {
    case v := <-ch:
        if v == 2 {
            continue  // → следующая итерация FOR (не select!)
        }
        if v == 3 {
            break     // → выход из SELECT (не for!)
        }
        fmt.Println(v)
    }
}
```

Частая ловушка. `continue` внутри select применяется к ближайшему внешнему `for`. `break` внутри select применяется к самому `select`, а не к `for`. ^nuance-break-continue

Если нужно выйти из for изнутри select — используйте label:
```go
loop:
    for { select { case ...: break loop } }
```
^nuance-break-label

## Копирование и сравнение

Канал — это указатель на внутреннюю структуру `hchan`. Копирование канала копирует только указатель — оба значения указывают на один объект. ^nuance-chan-pointer

```go
src := make(chan int)
clone := src        // копия указателя — тот же hchan
src <- 42
fmt.Println(<-clone) // 42 — шарят один объект

ch1 := make(chan int)
ch2 := ch1
fmt.Println(ch1 == ch2) // true — один указатель
```

Сравнение каналов (`==`) — это сравнение указателей: указывают ли они на одну и ту же `hchan`. ^nuance-chan-compare

## Канал = объект первого класса

Канал можно передавать как аргумент функции, возвращать из функции, хранить в поле структуры, использовать как тип другого канала (канал каналов): ^nuance-first-class

```go
chan chan int          // канал каналов
chan (<-chan string)   // канал read-only каналов
```

## Ловушка с аргументами функций

Аргументы функции вычисляются **слева направо** и **все до вызова** функции. ^nuance-args-order

```go
// ПОСЛЕДОВАТЕЛЬНО: fetch1 блокирует → 2 сек, потом fetch2 → ещё 2 сек = 4 сек
process(<-fetch1(), <-fetch2())

// КОНКУРЕНТНО: оба запущены, потом читаем = 2 сек
ch1, ch2 := fetch1(), fetch2()
process(<-ch1, <-ch2)
```

Первый `<-fetch1()` блокируется до получения результата, только потом начинается `fetch2()`. Конкурентности нет. ^nuance-args-sequential

## len/cap без синхронизации

`len(ch)` и `cap(ch)` безопасно вызывать из разных горутин без мьютексов. ^nuance-len-cap-safe

Но **нельзя** использовать len для принятия решений о чтении/записи — race condition между проверкой и операцией. ^nuance-len-cap-no-decision

## Блокировка горутины навсегда

```go
select {}           // пустой select
<-make(chan int)     // чтение из канала, куда никто не пишет
var ch chan int; <-ch // чтение из nil
```

Три способа заблокировать горутину навсегда. Используется в тестах/бенчмарках. ^nuance-block-forever
