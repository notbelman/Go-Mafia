```
──────────────────────────────────────────────────
G1 хочет ПОЛУЧИТЬ, но никто не отправляет
──────────────────────────────────────────────────

G1: x := <-ch

lock()
нечего взять → создаём sudog (elem = &x)
встаём в recvq
unlock()
gopark()   → G1 спит 💤

hchan:
  sendq: пусто
  recvq: [sudog1]
            ↓
          G1, &x   ← куда положить результат

──────────────────────────────────────────────────
G2 отправляет
──────────────────────────────────────────────────

G2: ch <- 10

lock()
recvq не пустой → достаём sudog1
пишем 10 в sudog1.elem (&x)   // Direct Copy в стек G1
unlock()
goready(G1)   → G1 в runqueue

G1: проснулся, x = 10 ✓
G2: продолжает работу ✓
```
^recvq-example-full

**Ключевой момент:** поле `elem` в `sudog` хранит **указатель на переменную** в стеке получателя (`&x`). Sender пишет данные напрямую туда — это Direct Copy без промежуточного буфера. ^recvq-direct-copy
