- **producer-side**: интерфейс в том же пакете, что и реализация
- **consumer-side**: интерфейс у потребителя, приватный, минимальный — **Go коммьюнити предпочитает этот подход**
- producer: плюс — легко менять сигнатуру в одном месте; минусы — связанность пакетов, лишние методы, сложно подменить
- consumer: плюсы — нет связанности, только нужные методы, гибкость; минус — сложнее менять сигнатуру
- исключение: когда абстракция **точно полезна** потребителям → producer-side (пример: `encoding` в stdlib)

---

## Producer-side (интерфейс у реализации)

```go
// пакет storage — реализация + интерфейс вместе
package storage

type Storage interface {  // ← огромный интерфейс
    GetUser(id int) (*User, error)
    UpdateUser(u *User) error
    DeleteUser(id int) error
    ListUsers() ([]*User, error)
    // ... ещё 10 методов
}

type MySQLStorage struct{}
func (s *MySQLStorage) GetUser(id int) (*User, error) { ... }
// ... все методы

// пакет service — зависит от storage
package service

type ClientService struct {
    repo storage.Storage  // ← зависимость от пакета storage
}

func (s *ClientService) Update(u *User) error {
    return s.repo.UpdateUser(u)  // нужен ТОЛЬКО UpdateUser
}
```

Проблема: `ClientService` получает **все** методы Storage, хотя нужен только `UpdateUser`. ^producer-problem

## Consumer-side (интерфейс у потребителя)

```go
// пакет storage — только реализация
package storage

type MySQLStorage struct{}
func (s *MySQLStorage) GetUser(id int) (*User, error) { ... }
func (s *MySQLStorage) UpdateUser(u *User) error { ... }
// ... все методы

// пакет service — свой маленький интерфейс
package service

type userUpdater interface {  // приватный! только то, что нужно
    UpdateUser(u *User) error
}

type ClientService struct {
    repo userUpdater  // ← не зависит от пакета storage
}
```

Инжектим в `main`: `NewClientService(mysqlStorage)` — MySQLStorage реализует `userUpdater` (утиная типизация). ^consumer-injection

Consumer-side: нет связанности между пакетами, только нужные методы, легко подменить реализацию (заглушки). ^consumer-advantages

Producer-side: легко менять сигнатуру в одном месте, но связанность пакетов, лишние методы у потребителя, сложно подменить. ^producer-tradeoffs

## Сравнение

| | Producer | Consumer |
|---|---|---|
| Связанность | service → storage | нет |
| Лишние методы | да | нет |
| Подмена реализации | сложно (заглушки) | просто |
| Изменение сигнатуры | просто (одно место) | сложнее |

^placement-comparison

## Исключение: stdlib

```go
// encoding/ определяет интерфейсы на стороне PRODUCER
type Marshaler interface {
    MarshalJSON() ([]byte, error)
}
// Реализуют: encoding/json, encoding/xml, encoding/binary...
```

Когда **точно знаем**, что абстракция будет полезна многим потребителям → producer-side оправдан. ^producer-exception
