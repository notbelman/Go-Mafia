- интерфейс с методами = **16 байт**: указатель на `itab` + указатель на `data`
- `data` → конкретный объект (реализация); `itab` → дескриптор (тип + таблица методов)
- itab **уникальна для пары** (интерфейс, конкретный тип)
- early binding (компиляция) нерационален → вместо этого **late binding**: itab вычисляется при **первом** присваивании, потом **кэшируется** глобально
- вызов метода через интерфейс = `tab.fun[N]` → адрес функции → вызов с `data` как receiver

---

## Структура в runtime

```go
// runtime/runtime2.go
type iface struct {
    tab  *itab          // таблица типа и методов
    data unsafe.Pointer // указатель на конкретное значение
}

type itab struct {
    inter *interfacetype // описание интерфейса (какие методы нужны)
    _type *_type         // конкретный тип значения (динамический тип)
    hash  uint32         // хеш типа (для быстрого type switch)
    _     [4]byte
    fun   [1]uintptr     // таблица методов (реально [n]uintptr)
}
```

`iface` занимает **16 байт**: два указателя — `tab` и `data`. ^iface-size

`itab` уникальна для пары (интерфейс, конкретный тип). ^iface-itab-unique

Поле `hash` в `itab` используется для **быстрого type switch** — не нужно сравнивать строки типов. ^iface-hash-typeswitch

Поле `fun` в `itab` — таблица методов: реально `[n]uintptr`, объявлена как `[1]uintptr` для совместимости с C-стилем массивов переменной длины. ^iface-fun-table

## Визуально

```
var w io.Writer = os.Stdout

w (iface, 16 байт)
+--------+--------+
|  tab   |  data  |
+---+----+----+---+
    |         |
    v         v
  itab      *os.File (конкретное значение)
+------------------+
| inter: io.Writer |
| _type: *os.File  |
| hash: 0x...      |
| fun[0]: Write ---+-→ (*os.File).Write
+------------------+
```

## Вызов метода (dynamic dispatch)

```go
w.Write(buf)

// Runtime делает:
// 1. берёт w.tab.fun[0] — адрес метода Write для *os.File
// 2. вызывает эту функцию с w.data как receiver
```

Вызов метода через интерфейс — **два уровня косвенности**: обращение к `tab.fun[N]` (адрес метода) → вызов функции с `data` как receiver. ^iface-dispatch-steps

## Late binding и кэширование

Компилятор генерирует **метаданные** отдельно: для каждого типа (список методов) и для каждого интерфейса (список методов). Itab **не** вычисляется на этапе компиляции для всех возможных пар — это было бы нерационально (не все пары реально используются). ^iface-no-early-binding

При **первом** присваивании `io.Writer = *os.File` runtime вычисляет itab, затем **кэширует** глобально. Повторное присваивание той же пары → берётся из кэша, без пересчёта. ^iface-late-binding-cache
