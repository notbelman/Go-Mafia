- все элементы в **одном массиве**, без связных списков ^oa-single-array
- коллизия → **пробирование** (probing): ищем следующую свободную ячейку ^oa-probing
- плюс: **cache-friendly** (данные рядом). Минус: поиск до первой **пустой** ячейки ^oa-tradeoff
- удаление: нельзя просто удалить — сломается поиск. Нужен **tombstone** или сдвиг элементов ^oa-delete-problem
- виды пробирования: линейное (+1), квадратичное, double hashing, cuckoo hashing ^oa-probing-types
- **Go 1.24 Swiss Table** — открытая адресация с SIMD оптимизациями, если оптимизация недоступна, то fallback на обычную мапу ^oa-swiss-table

## Как работает

```
table[4]:  [_, key5:500, _, key3:300]

Вставка key=9 (9%4=1):
  slot 1 занят → пробируем slot 2 → свободен → вставляем

table[4]:  [_, key5:500, key9:900, key3:300]
```
^oa-insert-example

**Поиск:** `hash % cap` → проверяем ячейку → не тот ключ → следующая → ... → пустая ячейка → стоп (не найден). ^oa-search

## Проблема удаления

```
table: [_, key5, key9, key1, _]
                  ↑
Удалили key9 → [_, key5, _, key1, _]

Ищем key1: hash%4=1 → slot1 (key5, не то) → slot2 (пусто!) → стоп
Но key1 в slot3! Поиск сломался.
```
^oa-delete-broken

**Решения:**
1. **Tombstone** — пометить "deleted", поиск проходит через tombstone дальше ^oa-tombstone
2. **Сдвиг** — подвинуть элементы с коллизией влево (дорого в худшем случае) ^oa-shift

## Виды пробирования

- **Линейное** — `(hash + i) % cap` (просто +1). Кластеризация: заполненные участки растут ^oa-linear
- **Квадратичное** — `(hash + i²) % cap`. Меньше кластеризация ^oa-quadratic
- **Double hashing** — `(hash + i * hash2(key)) % cap`. Вторая хэш-функция ^oa-double-hash
- **Cuckoo hashing** — две таблицы, два хэша, выталкивание элементов ^oa-cuckoo

## Swiss Table (Go 1.24)

Открытая адресация + SIMD инструкции для параллельного сравнения tophash. ^oa-swiss-simd

Не на всех процессорах доступна (нужна векторизация). На процессорах без SIMD — fallback на классическую реализацию. ^oa-swiss-fallback
