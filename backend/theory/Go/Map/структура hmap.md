- map переменная — это **указатель на hmap** (не объект структуры как slice/string)
- ключевые поля: count (len), **B** (лог2 бакетов), hash0 (seed), buckets, oldbuckets
- B в лог2 форме: экономия памяти + **готовая битовая маска** для `hash & (2^B - 1)`
- `make(map, N)` резервирует **как минимум** N элементов (может больше из-за бакетов по 8)
- начинается с **1 бакета** без указания размера

---
[[map Flashcards - hmap_struct]]
**Зачем каждое поле:**
```go
type hmap struct {
    count      int            // количество элементов в map (то что возвращает len())
    flags      uint8          // биты состояния: идёт запись (hashWriting=4),
                              // итерация (iterator=1), итерация по старым бакетам
                              // (oldIterator=2), same-size grow (sameSizeGrow=8)
    B          uint8          // log2 количества бакетов. 2^B = число бакетов.
                              // Используется как битовая маска: hash & (2^B - 1) = номер бакета
    noverflow  uint16         // приблизительное количество overflow бакетов
    hash0      uint32         // случайный seed для хеш-функции, генерируется при make(map).
                              // Защита от HashDoS
    buckets    unsafe.Pointer // указатель на массив из 2^B бакетов (текущие данные)
    oldbuckets unsafe.Pointer // указатель на старый массив бакетов при resize.
                              // nil если resize не идёт
    nevacuate  uintptr        // индекс следующего бакета для эвакуации.
                              // Все бакеты с индексом < nevacuate уже переехали.
                              // По нему runtime решает: читать из buckets или oldbuckets
    extra      *mapextra      // указатели на overflow бакеты (чтобы GC не собрал их раньше времени)
}
```

^hmap-struct-fields

map переменная — это указатель на hmap (не объект, как slice или string). ^hmap-is-pointer

B хранится в лог2 форме: экономия памяти + готовая битовая маска `hash & (2^B - 1)` для определения номера bucket без деления. ^hmap-b-log2

hash0 — случайный seed для хеша, инициализируется при создании map. Защита от HashDoS-атак. ^hmap-hash0-dos

flags содержит биты состояния: идёт ли запись, итерация и т.д. При записи ставится бит, при чтении проверяется. ^hmap-flags-bits

oldbuckets и nevacuate используются во время resize: oldbuckets — старый массив вёдер, nevacuate — сколько вёдер уже переехало. ^hmap-oldbuckets

**Пример `m := map[string]int{"a": 1, "b": 2, "c": 3}`:**
```
m (указатель)
   │
   ▼
 hmap
┌─────────────────────────────────────────┐
│ count = 3         (3 элемента)          │
│ B = 1             (2^1 = 2 ведра)       │
│ hash0 = 0xA7F2    (случайный seed)      │
│ buckets ──────┐                         │
│ oldbuckets = nil (resize не идёт)       │
│ nevacuate = 0                           │
└───────────────│─────────────────────────┘
                ▼
        [bucket 0] [bucket 1]
            │          │
            ▼          ▼
        "a"→1      "b"→2
        "c"→3
```

## make(map, N) — резервирование

Указание N — это **не точный cap** (как в slice). Это "как минимум N элементов, сразу без resize": ^hmap-make-not-exact-cap

| make(map, N) | бакетов | макс. элементов |
| :----------- | :------ | :-------------- |
| N ≤ 8        | 1       | 8               |
| N = 20       | 4       | 32              |
| N = 28       | 8       | 64              |
|              |         |                 |

^hmap-make-table

Бенчмарк: резервирование перед заполнением в цикле — **на порядок быстрее** (нет переиндексаций). ^hmap-make-perf

Без указания размера map начинается с 1 бакета. ^hmap-default-one-bucket
