- из конца `s[:len-1]` — **O(1)**, но элемент остаётся в памяти
- из начала `s[1:]` — **O(1)**, но жрёт cap, рано или поздно реаллокация
- из середины `slices.Delete(s, i, j)` — **O(n)**, сдвиг элементов
- трюк O(1): swap с последним + отрезать конец (если порядок неважен)
- очистка: `nil` (отказ от памяти), `s[:0]` (сохранить cap), `clear()` (занулить)
- **memclr оптимизация**: присваивание zero value быстрее обычного (SIMD)

[[slice Flashcards - delete_clear]]
## Удаление из конца — O(1)

```go
s = s[:len(s)-1]  // отрезали последний
// Элемент остаётся в памяти! GC не освободит underlying array.
```
^delete-end

Элемент остаётся в памяти потому что underlying array не освобождается — slice просто уменьшает len. GC не может забрать память, на которую ещё есть ссылка через ptr слайса. ^delete-end-memory-leak

## Удаление из начала — O(1), но жрёт cap

```go
s = s[1:]  // сдвинули начало
// Каждый раз теряем 1 элемент cap. Рано или поздно — реаллокация.
```
^delete-front

Каждое `s[1:]` увеличивает ptr на один элемент и уменьшает cap на 1. Элементы в начале массива остаются в памяти, недоступны, но GC не забирает — всё ещё часть того же underlying array. ^delete-front-cap

## Удаление из середины — O(n)

```go
s = append(s[:i], s[i+1:]...)  // классика
s = slices.Delete(s, i, i+1)   // Go 1.21+ — читабельнее
```
^delete-middle

`slices.Delete` доступен с Go 1.21. Сложность O(n) — необходим сдвиг всех элементов правее индекса. ^delete-middle-go121

**Трюк O(1) для удаления из середины** (если порядок неважен): swap удаляемого элемента с последним, затем `s[:len(s)-1]`. ^delete-swap-trick

## Стек / очередь на slice

```go
// Push back / Pop back (стек)
s = append(s, x)                       // push
x, s = s[len(s)-1], s[:len(s)-1]       // pop

// Pop front (очередь) — неэффективно
x, s = s[0], s[1:]                     // pop front O(1) но жрёт cap
s = append([]int{x}, s...)             // push front O(n)
```
^stack-queue

Для очередей лучше circular buffer — pop front через `s[1:]` теряет cap и вызывает реаллокацию. ^queue-circular-buffer

## Очистка — 4 способа

```go
s = nil           // отказ от памяти, len=0, cap=0, GC заберёт array
s = s[:0]         // len=0, cap сохранён, память остаётся
clear(s)          // занулит все элементы, len и cap не меняются
clear(s[1:3])     // занулит только элементы [1:3]
```
^clear-four-ways

**Разница nil vs s[:0]:** `nil` — GC может забрать underlying array (len=0, cap=0, ptr=nil). `s[:0]` — len=0, но cap сохранён и ptr указывает на тот же массив, память остаётся занятой. ^clear-nil-vs-zero

**`clear(s)`** — занулит все элементы (zero value для типа), но len и cap остаются прежними. Доступна с Go 1.21. ^clear-builtin

## Memclr оптимизация

```go
// Быстро — включается memclr (возможно SIMD)
for i := range s { s[i] = 0 }

// Медленнее — обычное присваивание
for i := range s { s[i] = 5 }
```
^memclr

**Memclr оптимизация:** Go компилятор распознаёт паттерн присваивания zero value в цикле (`s[i] = 0` для числовых типов) и заменяет на `memclr` — низкоуровневую операцию очистки памяти, которая может использовать SIMD инструкции. Присваивание ненулевого значения такой оптимизации не получает. ^memclr-detail
