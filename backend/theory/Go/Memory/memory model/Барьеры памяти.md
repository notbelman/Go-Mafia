- Барьер памяти — инструкция, запрещающая reordering через себя. Стена: инструкции сверху не прыгают вниз, снизу — вверх ^barrier-definition
- 4 базовых: LoadLoad, LoadStore, StoreLoad, StoreStore. Полный барьер = все четыре ^barrier-four-types
- Влияют ТОЛЬКО на порядок инструкций. Не отменяют другие оптимизации ^barrier-scope

## Load и Store

Два типа операций с памятью:
- **Load** (чтение): прочитать значение из адреса ^barrier-load-def
- **Store** (запись): записать значение по адресу ^barrier-store-def

4 комбинации reordering (что с чем может переставиться): ^barrier-4-combos

```
LoadLoad    — чтение переставилось с чтением
LoadStore   — чтение переставилось с записью
StoreLoad   — запись переставилась с чтением
StoreStore  — запись переставилась с записью
```

^a15465

## Логические барьеры

Названия разные на разных архитектурах. Логические — универсальная абстракция. ^barrier-logical-abstract

**LoadLoad барьер**: все чтения ДО барьера завершатся ДО всех чтений ПОСЛЕ барьера. ^barrier-loadload

**StoreStore барьер**: все записи ДО барьера завершатся ДО всех записей ПОСЛЕ барьера. ^barrier-storestore

**LoadStore барьер**: все чтения ДО барьера завершатся ДО всех записей ПОСЛЕ барьера. ^barrier-loadstore

**StoreLoad барьер**: все записи ДО барьера завершатся ДО всех чтений ПОСЛЕ барьера. (Самый дорогой.) ^barrier-storeload-expensive

## Полный барьер (Full fence)

Все 4 барьера сразу. Стена: **ничто** не перепрыгивает. ^barrier-full-fence

```
    инструкция A
    инструкция B     ← могут переставляться между собой
    ════════════     ← ПОЛНЫЙ БАРЬЕР
    инструкция C
    инструкция D     ← могут переставляться между собой
```

A и B **никогда** не окажутся после барьера. C и D **никогда** — до. ^barrier-full-guarantee

## Барьеры с меньшими гарантиями

**Барьер записи (Store fence)**: только записи не прыгают. Чтения могут. ^barrier-store-fence

**Барьер чтения (Load fence)**: только чтения не прыгают. Записи могут. ^barrier-load-fence

Чем слабее барьер — тем больше свободы процессору для оптимизации. Как изоляции транзакций: сильнее гарантия = меньше пропускная способность. ^barrier-tradeoff

## Acquire / Release

**Acquire** (вход в критическую секцию): ничто не может **выпрыгнуть вверх** из барьера. Инструкции могут запрыгнуть внутрь сверху. ^barrier-acquire

**Release** (выход из критической секции): ничто не может **выпрыгнуть вниз** из барьера. Инструкции могут запрыгнуть внутрь снизу. ^barrier-release

```
    ── acquire ──    (Lock)
    критическая      ← ничто не выпрыгнет за acquire/release
    секция
    ── release ──    (Unlock)
```

^01a6a3

Мьютекс = acquire при Lock() + release при Unlock(). В C++ можно явно задать memory_order_acquire / memory_order_release. ^barrier-mutex-acq-rel

## Важно

Барьеры **не отменяют оптимизации**. Они запрещают только reordering. Другие оптимизации (register allocation, inlining, constant folding) продолжают работать. ^barrier-not-disable-opts
