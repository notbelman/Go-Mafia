- MESI — протокол когерентности кэша: гарантирует что все ядра **в конечном счёте** увидят одни данные ^mesi-definition
- Барьеры памяти — гарантируют **порядок** видимости: что именно увидят и когда ^mesi-barriers-order
- MESI решает одну проблему (когерентность), создаёт другую (медленно) → reordering решает скорость → создаёт проблему порядка → барьеры решают порядок ^mesi-chain-summary

## Цепочка проблем и решений

```
Проблема: у каждого ядра свой кэш, данные расходятся
    ↓ решение
MESI: протокол когерентности (Invalidate при записи)
    ↓ новая проблема
Медленно: ядро ждёт подтверждения инвалидации
    ↓ решение
Store buffer + reordering: не ждём, выполняем следующие инструкции
    ↓ новая проблема
Порядок нарушен: другое ядро видит записи в неправильном порядке
    ↓ решение
Барьеры памяти: явно запрещаем reordering где нужно
```

Каждое решение порождает новую проблему. Это фундаментальный паттерн в системном программировании. ^mesi-chain-pattern

## Что делает MESI

**Базовая гарантия**: если ядро 0 записало X=42, то ядро 1 **в конечном счёте** увидит X=42 (а не старое значение). Кэш-линия будет инвалидирована, следующее чтение пойдёт за свежими данными. ^mesi-guarantee

**Чего MESI НЕ гарантирует**: порядок. Если ядро 0 записало X=42 потом Y=1, ядро 1 может увидеть Y=1 раньше чем X=42 (из-за store buffer, reordering). ^mesi-no-order-guarantee

## Что делают барьеры

**Строгая гарантия**: если между записью X и записью Y стоит барьер, то любое ядро, увидевшее Y=1, гарантированно уже видит X=42. ^mesi-barrier-guarantee

```
Ядро 0:
    X = 42
    ── StoreStore барьер ──
    Y = 1

Ядро 1:
    if Y == 1 → X гарантированно 42
```

Без барьера: ядро 1 может увидеть Y=1 но X=0 (старое значение). ^mesi-no-barrier-problem

## Аналогия

**MESI** = почта доставляет все письма (когда-нибудь). ^mesi-analogy-mesi

**Барьеры** = гарантия что письмо A доставлено **до** письма B. ^mesi-analogy-barrier

Без барьеров: оба письма дойдут, но может B раньше A. ^mesi-analogy-no-barrier
