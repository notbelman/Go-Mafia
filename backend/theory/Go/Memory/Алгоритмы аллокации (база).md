- **линейный**: сдвиг указателя, нет выборочного освобождения (только free all). Кейс: уровни в играх
- **блочный (pool)**: нарезка на блоки одного размера, множество свободных блоков, кэш-локальность
- **стековый**: header перед каждой аллокацией (размер блока), освобождение по header
- **malloc**: headers + free blocks + сегменты + дефрагментация. Проблемы: contention + фрагментация
- свойства аллокатора **противоречат** друг другу: скорость ↔ безопасность ↔ потребление памяти

## Свойства аллокатора (компромиссы)

Скорость работы, масштабируемость (несколько CPU), потребление памяти (overhead метаданных), фрагментация, безопасность. ^alloc-properties

Невозможно оптимизировать всё: добавляешь безопасность — теряешь скорость. В Go аллокатор нельзя настраивать. ^alloc-tradeoff

## Линейный аллокатор

```
create(16)  →  [начало .............. конец]
                ^указатель

alloc(4)    →  [████ ............... конец]
                    ^указатель (сдвинулся на 4)

alloc(8)    →  [████ ████████ ...... конец]
                             ^указатель
```
^alloc-linear-diagram

Освобождение только целиком (free all). Идеален когда наплодили объектов → всё махом удалили (уровень в игре, батч обработки). ^alloc-linear-usecase

## Блочный (pool) аллокатор

```
create(16, blockSize=4)  →  нарезка на блоки:
  free: {0x00, 0x04, 0x08, 0x0C}

alloc()  →  достаёт 0x00 из множества, отдаёт пользователю
alloc()  →  достаёт 0x04

delete(0x00)  →  возвращает 0x00 в множество free блоков
```
^alloc-pool-diagram

Хранит объекты **одинакового размера**. Кейс: однотипные реквесты, сообщения. ^alloc-pool-usecase

Проблема: пользователь может принести некорректный указатель при delete (проверка = overhead). ^alloc-pool-problem

## Стековый аллокатор

```
alloc(2)  →  [header=2][██]
alloc(6)  →  [header=2][██][header=6][██████]

delete()  →  читаем header, понимаем сколько освободить
```
^alloc-stack-diagram

Header — базовая концепция: используется в БД (page layout), файловых системах, аллокаторах. Header может быть до или после данных, разного размера. ^alloc-header-concept

## malloc (General Purpose Allocator)

Объединяет headers + free blocks + сегменты. При нехватке памяти — выделяет новый сегмент (не двигает старые данные). Дефрагментация: объединение смежных свободных блоков. ^alloc-malloc-how

**Проблемы:** contention (потоки конкурируют за общий лок), фрагментация кучи (маленькие свободные куски не объединяются → большой объект не влезает). ^alloc-malloc-problems
