## Суть

Код разделён на горизонтальные слои по ответственности. Каждый слой зависит только от слоя ниже.

```
Presentation (HTTP handlers, UI)
      ↓
Business Logic (сервисы, правила)
      ↓
Data Access (репозитории, ORM, SQL)
      ↓
Database
```

## Ключевые правила

- Зависимости **только сверху вниз** — presentation вызывает business, business вызывает data access
- Слой не знает о слоях выше себя
- Closed layer: вызов только соседнего слоя. Open layer: можно прыгнуть через слой

## Проблемы

- **Бизнес-логика зависит от БД**: business layer импортирует data access layer → смена БД = переписать бизнес-логику
- **Сквозная связанность**: изменение в нижнем слое ломает верхние
- **Тестируемость**: нельзя протестировать business logic без поднятия БД (зависимость направлена вниз, к инфраструктуре)
- **Тяготеет к монолиту**: без дисциплины слои сливаются

## Layer vs Tier

**Layer** — логическое разделение кода (в одном процессе). **Tier** — физическое разделение (разные серверы). 3 layers на 1 сервере — ок. 3 tiers = 3 сервера.
