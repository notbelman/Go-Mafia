- `go` **не запускает** горутину сразу — лишь создаёт. Запуск может произойти спустя время (недетерминизм)
- `runtime.Goexit()` из main → программа работает, пока есть другие горутины
- при завершении main — defer других горутин **НЕ** вызываются
- замыкание переменной цикла: до Go 1.22 — общая переменная (все видят последнее значение), с 1.22 — новая переменная на каждую итерацию
- `runtime.LockOSThread()` — закрепляет горутину за одним потоком ОС (CGO, OpenGL)
- **Go 1.26:** `goroutineleak` pprof-профиль — GC находит горутины заблокированные на unreachable primitives (channel/mutex/cond); такие горутины никогда не проснутся

## go ≠ немедленный запуск

Инструкция `go` создаёт горутину, но планировщик недетерминирован. Горутина может стартовать не во время итерации, а когда цикл уже завершился. ^gn-go-not-immediate

```go
runtime.GOMAXPROCS(1)
var i int
go func() {
    for { i++ }
}()
fmt.Println(i) // чаще всего 0 — горутина не успела стартовать
```
^gn-go-not-immediate-example

## Замыкание переменной цикла

**До Go 1.22:** переменная цикла создавалась один раз, горутины замыкали общую переменную → все видели последнее значение. ^gn-closure-pre122

```go
for i := 0; i < 5; i++ {
    go func() {
        fmt.Println(i)  // До 1.22: часто пять пятёрок
    }()                  // С 1.22: каждая итерация — новая переменная
}
```
^gn-closure-example

**С Go 1.22:** на каждой итерации создаётся новая переменная — проблема решена. ^gn-closure-post122

## runtime.Goexit() из main
```go
func main() {
    go func() {
        time.Sleep(3 * time.Second)
        fmt.Println("done")
    }()
    runtime.Goexit()
}
// 1. main горутина завершена, но процесс жив
// 2. программа работает ещё 3 секунды, пока живы другие горутины
// 3. все горутины завершились → "no goroutines (main called runtime.Goexit) - deadlock!" → краш (exit code 2)
```
^gn-goexit-main-example

**Суть:** `runtime.Goexit()` убивает только main горутину. Остальные горутины продолжают работать. Но когда последняя из них завершится — runtime обнаруживает что горутин больше нет, а main не вернулся нормально → deadlock → краш. ^gn-goexit-mechanics

**Итого:** `runtime.Goexit()` в main **всегда** приводит к крашу в конце. Полезен только чтобы дождаться завершения других горутин перед этим крашем. ^gn-goexit-conclusion

## Завершение программы

Программа завершается когда завершается **main горутина** (return из main). Все остальные горутины останавливаются на том месте, где были. Их defer **не вызываются**. ^gn-main-exit

## runtime.LockOSThread()

Закрепляет горутину за конкретным потоком ОС. Редкий случай: CGO, OpenGL (библиотеки требуют работы из одного потока), специфичные системные вызовы. ^gn-lock-os-thread

```go
runtime.LockOSThread()
defer runtime.UnlockOSThread()
// весь код этой горутины будет на одном M
```
^gn-lock-os-thread-example

## Goroutine leak profile (Go 1.26)

GC определяет горутины заблокированные на channel/mutex/cond, primitive которого **недостижим** от любой runnable горутины → такие горутины никогда не проснутся — это и есть утечка. ^gn-leak-profile-mechanic

Включить при сборке: `GOEXPERIMENT=goroutineleakprofile`. pprof endpoint: `/debug/pprof/goroutineleak`. Go 1.27: планируется включить по умолчанию. ^gn-leak-profile-enable

```go
// Типичная утечка: ранний return, горутины-писатели заблокированы навсегда
ch := make(chan int) // unbuffered
go func() { ch <- 1 }() // горутина заблокирована
go func() { ch <- 2 }() // горутина заблокирована
return // ch — локальная переменная, стала unreachable → goroutineleak детектирует
```
^gn-leak-profile-example

**Ограничение:** не ловит утечки через global variables — если primitive достижим через глобал, горутина технически reachable и не попадёт в отчёт. ^gn-leak-profile-limitation
