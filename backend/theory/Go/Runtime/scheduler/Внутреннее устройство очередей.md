## LRQ — кольцевой буфер (ring buffer)

```
runq [0] [1] [2] ... [255]     ← массив из 256 указателей на G
       ↑               ↑
     head             tail

push (владелец P):  runq[tail % 256] = G; tail++
pop  (владелец P):  G = runq[head % 256]; head++
steal (другой P):   CAS на head — забрать половину с головы
```
^queues-lrq-structure

**Почему 256:** компромисс. Больше — реже overflow в GRQ, но больше памяти на P. Меньше — чаще overflow, больше contention на GRQ. 256 = степень двойки, дешёвый `% 256` через битовую маску. ^queues-lrq-why256

**Lock-free для владельца:** P читает/пишет свою LRQ без локов — он единственный writer (push в tail, pop из head). Синхронизация нужна только при **краже**: другой P делает CAS на head. Contention возникает только когда кто-то крадёт — это редко. ^queues-lrq-lockfree

**При переполнении:** `tail - head >= 256` → половина горутин (128) из головы LRQ + новая G переносятся в GRQ одним батчем. Не по одной — амортизация стоимости мьютекса. ^queues-lrq-overflow

## runnext — один слот

```go
runnext = адрес G5 (0xAAAA)

// atomic.Swap(&runnext, 0xBBBB)
// внутри CPU одна инструкция XCHG:
//   1. читает что лежит по &runnext → 0xAAAA
//   2. записывает туда 0xBBBB
//   3. возвращает 0xAAAA
// всё атомарно, одна операция

old := atomic.Swap(&runnext, &G9)  // old = &G5, runnext = &G9

runq[tail % 256] = old             // кладём &G5 в хвост LRQ
tail++
```
^queues-runnext-struct

Не очередь, не буфер — просто указатель. `atomic.Swap`: положить новую G, получить старую (старая уходит в LRQ). Самая быстрая операция: один atomic swap, без CAS-loop. ^queues-runnext-swap

## GRQ — связный список

```
gQueue {
    head *g
    tail *g
}
```
^queues-grq-struct

Защищена `sched.lock` (мьютекс). Нет ограничения размера. Push/pop — O(1) через head/tail. Батч-операции: можно переложить группу G за один lock/unlock. ^queues-grq-props

## Почему не lock-free для GRQ

Lock-free очередь (например, Michael-Scott queue) тоже имеет contention — CAS-инвалидация кэш-линий между ядрами. При большом количестве P разница с мьютексом минимальна. Мьютекс проще, а GRQ дёргается редко (1/61 тик + fallback) — contention низкий. ^queues-grq-why-not-lockfree
