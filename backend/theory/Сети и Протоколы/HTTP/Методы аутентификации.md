- **Session/Cookie** (stateful): сервер хранит сессию в Redis, клиент хранит session_id в cookie. Легко отозвать, но нужен shared state
- **JWT** (stateless): `header.payload.signature`. Сервер ничего не хранит, любой сервер проверит. Нельзя отозвать до exp (workaround: blacklist)
- **OAuth 2.0**: **делегирование** доступа ("разрешаю приложению X читать мои данные в Y без передачи пароля"). Authorization Code Flow — самый безопасный
- **Basic**: `Authorization: Basic base64(user:pass)` в каждом запросе. Просто, но пароль в каждом запросе → только HTTPS

## Session + Cookie (Stateful)

```
1. POST /login {email, password}
2. Сервер: session_id = random() → Redis: session:abc123 = {user_id: 456, role: "admin"}
3. Ответ: Set-Cookie: session_id=abc123; HttpOnly; Secure; SameSite=Strict
4. Каждый запрос: Cookie: session_id=abc123 (браузер автоматически)
5. Сервер: Redis GET session:abc123 → user_id=456
```

**Плюсы**: легко отозвать (DELETE из Redis), меньше данных в запросе, браузер автоматически.
**Минусы**: нужен Redis/БД, sticky sessions или shared state, CSRF уязвимость.

## JWT (Stateless)

```
header:    {"alg": "HS256", "typ": "JWT"}
payload:   {"user_id": 456, "role": "admin", "exp": 1735689600}
signature: HMAC-SHA256(base64(header) + "." + base64(payload), secret)

Результат: eyJhbGci... . eyJ1c2Vy... . SflKxwRJ...
```

**Проверка**: декодируем → пересчитываем signature с секретом сервера → сравниваем → проверяем exp.

**Access Token** (15 мин) + **Refresh Token** (7 дней):
```
Access истёк → POST /token {grant_type: refresh_token, refresh_token: "..."}
→ Новый access token
```

**Плюсы**: stateless (любой сервер проверит), масштабируемость, микросервисы.
**Минусы**: нельзя отозвать до exp (blacklist в Redis = стал stateful), больше размер, XSS если в localStorage.

## OAuth 2.0

"Разрешаю приложению X читать мои данные в Y **без передачи пароля**."

### Authorization Code Flow (самый безопасный)

```
1. Client → redirect: GET /authorize?client_id=123&redirect_uri=.../callback&scope=read
2. User логинится в Google/GitHub, нажимает "Разрешить"
3. Auth Server → redirect: .../callback?code=abc456
4. Client backend → POST /token {code: abc456, client_secret: xxx}
5. Auth Server → {access_token: "ey...", refresh_token: "...", expires_in: 3600}
6. Client → GET /api/user, Authorization: Bearer ey...
```

### Client Credentials Flow

Machine-to-machine (сервис → сервис, без пользователя):
```
POST /token {grant_type: client_credentials, client_id: 123, client_secret: xxx}
```

**OAuth vs JWT**: OAuth — **протокол** (КАК получить токен). JWT — **формат** (ЧТО передаётся). OAuth часто использует JWT как access_token.

## Basic Authentication

```
Authorization: Basic YWRtaW46c2VjcmV0MTIz
                     ↑ base64("admin:secret123")
```

**Base64 — НЕ шифрование**. Только HTTPS. Пароль в **каждом** запросе. Нет logout (браузер кэширует).

Use case: dev окружение, простые internal API, CLI tools.

## Сравнение

| | Session/Cookie | JWT | OAuth 2.0 | Basic |
|:--|:--|:--|:--|:--|
| State | Stateful (Redis) | **Stateless** | Зависит | Stateless |
| Отзыв | **Легко** | Сложно (blacklist) | Зависит | Невозможно |
| Масштаб | Shared Redis | **Любой сервер** | Зависит | Любой |
| Браузер | Автоматически (Cookie) | Вручную (header) | Redirect flow | Браузер кэширует |
| Use case | Web-приложения | API, микросервисы | Сторонний доступ | Dev/internal |
