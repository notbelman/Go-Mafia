- **protoc** (Google) — официальный, ручная установка плагинов, bash-скрипты. **buf** — современная замена: декларативная конфигурация, встроенный линтер, **buf breaking** (детектор ломающих изменений), 2x быстрее
- Хранение: **отдельный репозиторий** (рекомендуется для нескольких команд/языков). В репо сервиса — ОК для маленьких проектов
- CI: `push .proto → buf lint → buf breaking (vs main) → buf generate → commit gen/`. Без **buf breaking** — один PR может сломать всех клиентов
- Генерируется: `.pb.go` (структуры, Marshal/Unmarshal) + `_grpc.pb.go` (клиент, серверный интерфейс, Register). **Не редактируем**

## protoc vs buf

**protoc**: длинные CLI-флаги, ручная установка плагинов, bash-скрипты. Хрупко.

**buf**: декларативная конфигурация:
```yaml
# buf.gen.yaml
version: v2
plugins:
  - remote: buf.build/protocolbuffers/go
    out: gen/go
  - remote: buf.build/grpc/go
    out: gen/go
```

Плюсы buf: `buf lint` (стиль), `buf breaking` (ломающие изменения), remote-плагины, 2x быстрее.

## Хранение

**Отдельный репозиторий** (рекомендуется):
```
proto-repo/
├── order/v1/order.proto
├── user/v1/user.proto
└── buf.yaml
```
Один владелец контракта → генерация для Go, Python и т.д.

**В репо сервиса** — ОК для маленьких проектов, рискует рассинхроном.

## CI pipeline

```
push .proto → buf lint → buf breaking (vs main) → buf generate → commit gen/
```

`buf breaking` ловит: удалённые поля, изменённые типы, переименованные сервисы.

## Что генерируется в Go

`.pb.go` — структуры, Marshal/Unmarshal (от `protoc-gen-go`).
`_grpc.pb.go` — клиент, серверный интерфейс, Register (от `protoc-gen-go-grpc`).
