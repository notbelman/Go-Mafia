- Protobuf передаёт по сети `номер_поля + значение`. **Имя поля НЕ передаётся**. Номера и типы = контракт, имена — нет
- **Безопасно**: переименовать поле, добавить новое (старые клиенты игнорируют). **Сломает**: изменить номер, изменить тип, удалить без `reserved`
- **reserved** — запрещает переиспользование удалённых номеров. Без reserved: новое поле может получить старый номер → данные интерпретируются неправильно

---

Protobuf передаёт по сети пары `номер_поля + значение`. Имя поля НЕ передаётся.

**Правило:** номера и типы полей — контракт. Имена — нет.

| Действие | Безопасно? |
|:---------|:-----------|
| Переименовать поле | ✅ Имя не передаётся |
| Добавить новое поле | ✅ Старые клиенты игнорируют |
| Изменить номер поля | ❌ Сломает |
| Изменить тип поля | ❌ Сломает |
| Удалить поле без reserved | ❌ Номер могут переиспользовать |

Если совпадают номера и типы, но разные имена и package — сериализация работает, но gRPC-роутинг сломается (package входит в имя сервиса).
```protobuf
message User {
    reserved 3, 5;        // удалённые номера — нельзя переиспользовать
    reserved "old_field";
    int64 id = 1;
    string name = 2;
    string email = 4;     // 3 пропущен — был удалён
}
```
