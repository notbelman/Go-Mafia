## Формат карточки

Каждая карточка — один `.md` файл. Имя файла = название карточки (Windows-safe, без спецсимволов). Внутри файла **без `# Заголовок`** — сразу контент.

### Структура: TL;DR + детали

Карточка состоит из двух частей, разделённых `---`:

**Часть 1 — TL;DR (шпаргалка, 4-10 строк).** Это то, что видно на Obsidian Canvas в компактном виде. Ключевые правила, числа, подводные камни — то, что нужно помнить на собеседовании. Буллеты с жирным выделением главного. Никакого кода в этой части (кроме инлайн-кода).

**Часть 2 — Детали (после `---`).** Полный конспект: примеры с кодом, объяснения, нюансы, бенчмарки. Секции через `##`. Это то, что видно при открытии карточки в полном виде.

```markdown
- **ключевой факт 1** — краткое пояснение
- **ключевой факт 2** — конкретные числа, правила
- **подводный камень** — что стреляет, чего избегать
- **на собесе** — что спрашивают, что отвечать
- Балун: "Цитата, если яркая и запоминающаяся."

---

## Секция 1 (Зачем / Как работает / Суть)

Содержание с примерами кода, объяснениями, конкретными числами.

## Секция 2 (Детали / Трейдоффы)

Содержание.

## Связь
- [[Название другой карточки]] — краткое пояснение связи
```

### Пример

Файл: `Range подводные камни.md`

```markdown
- range копирует выражение **один раз** перед циклом → append внутри range НЕ бесконечный
- value — всегда **копия**, модификация не изменит slice/array
- Go 1.22+: **новая переменная** на каждой итерации (фикс замыканий в горутинах)
- range по массиву копирует **ВЕСЬ массив** → решение: `range &arr` или `range arr[:]`
- модификация: по индексу `a[i]` (быстрее) или через `[]*T`

---

## Копирование выражения

...код, объяснения...

## Связь
- [[Array основы]] — range по массиву vs по срезу
```

## Регенерация существующих карточек

Когда нужно обновить существующую карточку под новый формат:

1. **Добавляем TL;DR сверху** — 4-10 строк буллетов с ключевыми фактами
2. **Добавляем `---`** после TL;DR
3. **Полотно (детали) НЕ трогаем** — существующий контент остаётся как есть
4. Если в существующей карточке был `# Заголовок` — убираем его (имя файла = заголовок)

То есть регенерация = добавление шапки, а не переписывание карточки.

## Ключевые правила формата

1. **Атомарность.** Одна карточка = одна концепция / один паттерн / один компонент. Если карточка больше 2 экранов — разбивай.
    
2. **Имя файла — самодостаточное.** `Range подводные камни.md`, не `Паттерн 3.md`. Windows-safe: без `:`, `*`, `?`, `<`, `>`, `|`, `/`, `\`. Без номеров-префиксов.
    
3. **TL;DR — самодостаточная шпаргалка.** Человек видит карточку на canvas в маленьком размере и за 2 секунды вспоминает тему. Правила, числа, подводные камни. Жирным выделять ключевые слова/числа. Без кода (кроме инлайна). 4-10 строк.
    
4. **Детали — полный конспект.** Примеры с кодом, объяснения, бенчмарки. Секции через `##`. Обычно 2-5 секций.
    
5. **Живой язык, не учебник.** Конспект для себя. Примеры из реального мира, аналогии, конкретные числа. "Файл 100 ГБ, на 50 ГБ сеть моргнула" — хорошо. "В случае прерывания сетевого соединения" — плохо.
    
6. **Цитаты Балуна.** Если фраза яркая и помогает запомнить — `Балун: "..."`. Можно в TL;DR, можно в деталях. 0-2 на карточку.
    
7. **Код и схемы.** Блоки кода (SQL, Go, псевдокод) или ASCII-схемы — только в части деталей (после `---`). В TL;DR — только инлайн-код.
    
8. **Конкретные числа.** RPS, трафик, размеры — обязательно. Числа — якоря для памяти.
    
9. **Без воды.** Никаких "как мы знаем", "важно отметить". Сразу к делу.

## Секция "Связь" (wikilinks)

В конце каждой карточки — секция `## Связь` со ссылками в формате `[[название файла без .md]]`.

### Правила связей

1. **Только смысловые связи.** Не "из одного урока", а "Circuit Breaker прекращает ретраи → связан с Retry".
    
2. **Краткое пояснение** после каждой ссылки: `[[Retry]] — ретраи безопасны только для идемпотентных запросов`.
    
3. **2-5 связей** на карточку. Только самые важные.
    
4. **Связи в обе стороны.** Если A ссылается на B, то B должна ссылаться на A.
    
5. **Типы связей:**
    
    - "Используется вместе": Retry ↔ Idempotency
    - "Альтернатива/выбор": 2PC ↔ Saga
    - "Часть целого": Chunking → Google Drive дизайн
    - "Углубляет": WAL → Репликация
    - "Следующий шаг": Требования → Расчёт нагрузки

## Особенности для курсов по Go

1. **Больше кода.** Примеры, output, бенчмарки — в части деталей (после ---).
2. **Подводные камни в TL;DR.** Неочевидное поведение — обязательно в шпаргалку наверх.
3. **Устройство изнутри.** Структуры из runtime, диаграммы памяти.
4. **Сопоставление с существующими.** ~200 карточек по Go. Не дублировать — углублять.

## Чего НЕ делать

1. **Не разжёвывать очевидное.** Я разработчик.
2. **Не добавлять отсебятину.** Карточки основаны на материале курса.
3. **Не делать карточки-монстры.** Больше 2 экранов → разбивай.
4. **Не дублировать.** Тема покрыта → дополнить, не создавать новую.
5. **Не пропускать связи.** Минимум 1-2 ссылки.
6. **Не пихать код в TL;DR.** Код только после `---` (инлайн — ок).
