## Что проверяем

Кандидат понимает как построить распределенную масштабируемую систему и как ее мониторить.

## Условие

Мы делаем классифайд. Соискатель выступает в роли технического директора компании-подрядчика, которая будет делать backend. Frontend часть не рассматриваем.

## Функциональные требования

- Можно сделать поисковый запрос и получить страницу поисковой выдачи — SERP (Search Engine Results Page)
- Можно посмотреть карточку отдельного объявления
- Можно посмотреть список своих объявлений
- Можно добавить новое объявление которое появится в поисковой выдаче

## Дополнительные вводные от бизнеса

> Сразу не выкладывать, дать возможность соискателю самому спросить про это.

- Система должна быть масштабируемой. Хотим начать со 100 RPS и иметь возможность дойти до 20k RPS
- Соотношение пишущей и читающей нагрузки 1/100
- Объявления содержат несколько фотографий
- Поиск должен быть полнотекстовым
- Допустима задержка между подачей объявлений и появлением в поисковой выдаче

## Приемлемый вариант решения

Кандидат должен обратить внимание, что система read-heavy, и использовать это в свою пользу. Можно делать несколько реплик для чтения и кешировать данные на разных слоях.

Система должна быть масштабируемой, выдерживать одновременное добавление большого количества новых объявлений.

### БД
- Обоснованный выбор СУБД
- Посчитана нагрузка на БД и объем хранимых данных
- Шардированная и реплицированная БД
- Есть понимание, как делать решардинг
- Поиск не ведет к тяжелым запросам
- В геораспределенной системе данные разложены близко к потребителям

### Архитектура
- Несколько ДЦ, пользователь направляется к ближайшему ДЦ, например через Global Server Load Balancing
- На входе в ДЦ стоит Linux Virtual Server для отказоустойчивости, затем L7 балансировщик для терминации SSL
- Обоснован выбор монолит/микросервисы, система декомпозирована на сервисы
- Сервисы развернуты в облаке, межсервисная балансировка запросов

### Метрики
- Выбрано 5 метрик, позволяющих понимать состояние системы (ok/prefail/fail)
- Есть понимание, что такое перцентили
- Есть понимание, как находить провалы в посещениях (сравнение с историческими данными)
